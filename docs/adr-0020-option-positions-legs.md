# ADR-0020: オプションの組み合わせは今の取引の文書に「原資産の計画 + レッグ」で持ち、ポジション ID は取引の ID にする

- 状態: 採用
- 日付: 2026-11-19
- 関連: Issue #32（オプションの組み合わせのポジション）、設計書 0.3（K13〜K15）・4.2・4.7・5.7・6.4・7.6・11.1・C28・C36・C46〜C54、ADR-0004（記録の API と保存）、ADR-0006（チャート画像）、ADR-0007（削除の [元に戻す]）、ADR-0009（本番の配信と切り戻し）、ADR-0012（口座）、ADR-0016（取引の一覧のページ分け）、ADR-0017（明細の特徴の鍵）、ADR-0018（サービスワーカーを置かない）

## 背景

- オーナーはオプションの組み合わせのポジションを、先物の取引と同じように振り返りたい（#32「組み合わせポジになるからポジアイディがいるきがする」）。オーナーのオプションの記録のシートは 1 行 = 1 レッグで、GRP の列がポジションをまとめている。ポジション 4 つのうち 3 つがレッグ 3 本、1 つがレッグ 1 本（売りのプットだけ）で、SL（LC）は原資産の価格で書いている
- 目指す形は「原資産の取引とシームレス」: レッグ 1 本なら今の画面と手間を変えず、LC は原資産の価格、1R は原資産が LC に達したときのポジション全体の損失
- 今の取引の文書は 1 文書 = 1 取引（`record.instrumentId`・`side`・`entries[]`・`exit`・`lc`、snapshot、チャートは `users/{uid}/charts/{tradeId}-{slot}`。文書に `schemaVersion: 1`）。判定・R は保存せず、画面が `toTradeInput` → `evaluateTrade` で出す。一覧のページ分け（ADR-0016）・期間の集計（C44）・削除と元に戻す（ADR-0007）・チャート（ADR-0006）・口座の付け替え（C36）はどれも 1 文書を単位にしている
- 今の取引は限月・P / C・行使価格を任意の欄に持つが、1 取引 = 1 銘柄の 1 回の建てなので、組み合わせを 1 つの計画・1 つの判定として記録できない
- 保存の形は一度データが入ると戻しにくい。切り戻し（`rollback.yml`）で前の版に戻ったとき、前の版の直す画面が新しい形の文書を上書きすると、知らない欄（レッグ）が消える（前の版の API は本文の知らない欄を 400 にするが、前の版の画面はレッグを送らないので、レッグの無い本文で上書きが通る）
- 記録からは決めようのない売買の考え方 3 つ（ロール・中立の形・LC での損失の見込み）は、オーナーが推奨の案で決めた（設計書 0.3 の K13〜K15）

## 決定

1. **ポジション = 今の取引の文書**。ポジション ID は取引の ID。別のコレクションは作らない
2. **レッグは `record.legs`**（1〜10 本。`id`・`optionType`・`contractMonth`・`strike`・`side`（`buy` / `sell`）・`quantity`・`entry {price, time?}`・`exit {price, time?, kind: closed | expired}`）。レッグの損益・ポジションの判定・R は保存しない。画面と文書の言葉は「レッグ」（「足」は時間足の意味で使っているため）
3. **ポジションの計画と判定の値は原資産の価格で今の欄に置く**: `side` = ポジションの向き（自動）、`lc`・`tp` = 原資産、`entries` = 1 つ（`price` = 建てたときの原資産、`quantity` = 1）、`exit.price` = 決済したときの原資産。`statementPnlYen`・`fees` はポジションの合計。新しい欄は `legs`・`riskPlan`（`maxLoss` =「最大損失まで」）・`lcLossPlanYen`（LC での損失の見込み。任意。K15）の 3 つだけ
4. **判定は 5.3・5.4 の規則を原資産の上でそのまま当てる**。違うのは勝ち負けの境（ポジションの手数料を除いた損益の符号）と「持ち続けた」（決済したときの原資産が LC を不利な側に越えた）だけで、ほかに「最大損失まで」の例外がある（C50）。1R は 見込み → 実際の動きから → 満期の損益から の順（C48・C49）。「実際の動きから」は原資産が LC までの幅の半分以上逆へ動いた負けだけ（わずかな逆の動きで割って 1R が膨らみ、作られた過剰リスクにならないよう。C32 と同じ守り）。満期の損益・最大損失は為替を掛けて口座の通貨で出し、為替が出なければ額を出さない（最大損失が定まるかは価格の通貨のまま見るので、為替が空でも「最大損失まで」は C にならず、1R が出ないだけ）。レッグを持つ取引には 5.1 の 1R の補いの式と明細から逆算した為替を当てない
5. **ポジションの損益には満期で消えたレッグの損益を必ず入れる**。`statementPnlYen` は決済したレッグの明細の損益で、満期で消えたレッグ（明細に出ない）の損益は建値から導出して足す。明細の損益が無ければすべてのレッグの導出の損益の合計（設計書 4.7）。ポジションの決済の時刻と決済したときの原資産は、リスクが残っていたレッグを最後に閉じた時点で決める（C54）: 自分で決済したレッグはその時点、満期で消えた売りのレッグは SQ の日と SQ の原資産、満期で消えた買いのレッグは数えない（損益にだけ入れる）。売りを SQ まで残すのはリスクを持ち続けることで、オーナーの記録で多い売りのプットの裸を「持ち続けた」から外すと、いちばん大事な規律を見逃すため。買いは損失が払ったプレミアムで止まっているので、放置して消えても規律どおりの決済を SQ の原資産で「持ち続けた」にしない。時刻の検査は SQ の日を決済の時刻として受け付ける。決済の時点が満期で消えた売りで決まるときは、ポジションの決済の注文の種類を「満期（SQ）」（`expiry`。レッグを持つ取引だけが持てる値）にし、逆指値とみなさない（先に決済したレッグの「逆指値」が残って「持ち続けた」から外れないように）
6. **先物・現物・CFD の取引は書き換えない**（レッグを持たない文書 = レッグ 1 本の今の形）。オプションの銘柄で新しく記録する取引は、レッグ 1 本でもレッグの形にする。前からある「プレミアムで記録した 1 本のオプションの取引」はそのまま読み、レッグを足す PUT は受けない
7. **`schemaVersion` は `legs` を持つ文書だけ 2**（PUT は本文の形で版を決める。レッグの無い先物の取引は直しても 1 のまま）。レッグを知らない画面・API がレッグを落とさないよう、守りを 2 つ置く:
   - (a) **知らない版の守り**: 保存済みの版がこの版の知る値より大きい取引の PUT（口座の付け替え・`?snapshot=current` を含む同じ入口）・チャートの差し替え（PUT）・外す（DELETE）を 409 にする。レッグの形より 1 つ前のデプロイで単独に出す
   - (b) **レッグの無い本文の守り**: レッグを受け付ける最初の版から、保存済みにレッグがある取引へ `legs` の無い本文で PUT すると 409 にする（レッグを知らない画面の `mergeEdit` は知っている欄だけを残すので、`legs` を落とした本文を送るため）。`legs` を送る画面は `riskPlan`・`lcLossPlanYen` も知っているので、それらが無いのは本人が消したと読む。版の確かめは書き込みと同じトランザクションの中で行う。チャートの入口は `legs` を書き換えない
   - 穴の無さ（デプロイの順 a → b を持つ保存 → 画面）: 画面より前へ `rollback.yml` で戻すと、残る API は (b) を持つので、戻した画面の直す画面は 409 で止まる。保存より前（a だけの版）へ戻すと、v2 の文書は (a) で 409。古いタブ（サービスワーカーが無く、ホーム画面に追加したタブは前の JS のまま開いていられる。ADR-0018）が今の API に送る PUT は (b) で 409。今の画面は `legs` を送る。残る穴は (a) より前の版へ 2 つ以上手で戻すときだけで、`infra/README.md` の切り戻しの注意に書く。(a) の版を 1 つ前のリビジョンにするため、保存の版のデプロイは「本番の動いているリビジョンが (a) のコミットを含む」ことを確かめてから承認する（`deploy.yml` の concurrency は承認待ちの run を新しい run が取り消すので、(a) の承認待ちのうちに保存をマージすると (a) だけのリビジョンができない）
8. **ロール・一部の決済・レッグの追加は同じポジションの中のレッグで表す**（ロール = 前のレッグの決済 + 新しいレッグの建て。前後を結ぶ欄は持たず、判定は今の 3 つのタップに任せる。K13）
9. すべてのレッグが同じ銘柄（原資産 + オプション）・同じ snapshot（乗数・価格の通貨）・同じ口座・同じ為替。LC は 1 つで、初めは向きのある組み合わせだけを扱う（K14）。先物のレッグ（デルタヘッジ）・上下 2 つの LC（中立の形）・レッグごとの建てたときの原資産（後から足したレッグのナンピン）は後で欄を足す（どれも足すだけで済み、今の形を壊さない）

## 選択肢

- **A. 今の文書に原資産の計画 + `legs`**（採る）: 判定・LC の物差し・一覧・期間の集計・直近の流れ・削除・チャート・口座の付け替えが今のまま 1 文書で動く。「原資産とシームレス」に合う。前の版でも原資産の取引として読める。ページ分け・索引（ADR-0016・C44）を変えない。代わりに、`entries[0].quantity` = 1 のように、レッグを持つ文書では意味の無い値を置く欄があり、`entries`・`exit.price` の意味が銘柄の商品の形とレッグの有無で変わる（`toTradeInput` の 1 か所で分ける）
- **B. ポジションの文書とレッグの文書を分ける**（シートの GRP と同じ形）: 1 行 = 1 レッグでシートや明細の形に近いが、一覧・集計・削除・チャートが 2 つのコレクションの結合とトランザクションになる。ページ分けのカーソル（ADR-0016）がポジションの単位で組めない。取り込み・記録で片方だけ書かれる窓ができる。採らない
- **C. すべての取引をレッグの配列に書き換える**（移し替え）: 形は 1 つになるが、保存済みのすべての取引を書き換え、切り戻しで前の版が読めなくなる。#47 で避けた「鍵を変える移し替え」と同じ危うさ。採らない
- **D. 今の文書に `legs` と、原資産の値の新しい欄（`underlying.entry` など）を足す**: 欄の意味ははっきりするが、今の必須の欄（`entries`・`exit.price`）に何を入れるかの問題が残り、判定のコードが原資産の欄とで二手に分かれる。前の版では読めない。採らない
- **E. 1 レッグ = 1 取引で、取引に `positionId` を足す**: 今の形の変更は最小だが、判定・R・計画どおり率がレッグごとになり、「ポジションで 1R」が成り立たない。売りのレッグだけ見ると利益でも、ポジションでは負けている、が起きる。採らない

## 結果

- オプションに特有なのはレッグの検査・満期の損益・1R の出し方だけになり、5.3・5.4 の規則と 5.6 の表は原資産の上でそのまま使える。先物の取引と同じ一覧・同じ集計に 1 件として並ぶ（C53）
- レッグを持つ文書では `entries[0].quantity` は使わない（1 で固定）。数量の比（C42）は比だけを出し、提案の数量は出さない
- 守り（決定 7 の (a)）より前の版へ切り戻すと、前の版の直す画面でオプションのポジションを保存したときにレッグが消える。(a) をレッグの形の 1 つ前のデプロイで出し、(b) をレッグを受け付ける最初の版に入れることで、`rollback.yml`（1 つ前のリビジョン）の範囲・古いタブ・今の画面のどれでも起きない。2 つ以上前へ手で戻すときは、オプションのポジションを直さない（`infra/README.md` の切り戻しの注意に、レッグの形を出す Issue で足す）
- 前の版（(a) の版を含む）は `schemaVersion: 2` の文書を一覧・詳細に出すが、R・リスク（%）・判定は違って見える（1R を先物 1 枚の式か損益の逆算で出し、`riskPlan: maxLoss` の取引は LC が無いので C と出る）。保存は (a) の 409 で守られる。切り戻しの注意にこのことも書く
- (b) は `legs` の有無だけを鍵にしている。次に欄を足すとき（上下 2 つの LC など）は、画面が知っている版を本文か header で送り、`保存済みの版 > 送った版` を 409 にする一般の形にする（古い画面が知らない欄を落とす問題を、欄ごとの規則でなく版で止める）
- 明細の特徴の鍵（ADR-0017）は行の向きの書き方の集合を含むので、同じ会社でも先物の明細とオプションの明細で鍵が分かれ、口座の自動の選択が別々に覚えられる。受け入れる（それぞれ 1 回選べば覚える）
- ポジションの単位は「一緒に記録したもの」で、明細の行をどうまとめるかは利用者が決める（API の純関数が建てた日でまとめた下書きを出し、1 タップで分け直せる。C51）
- 為替が要る（価格の通貨 ≠ 口座の通貨）ポジションは、為替を入れないと満期で消えたレッグの損益・満期の損益・最大損失が出ない（明細から為替を逆算しない）
- 勝ったポジションの多くは 1R が満期の損益からの見積もりになる。見込みを入れた取引だけ本人の見積もりになり（K15）、期間の半分を超えるときは振り返りに 1 行添える（6.4）
- 範囲外（後の Issue）: 上下 2 つの LC（中立の形）、先物のレッグ、レッグごとの建てたときの原資産と後から足したレッグのナンピン、ロールの前後を結んだ表示、入る前の計画（縦切り 3）でのレッグの入力、約定明細からのレッグの読み取り
