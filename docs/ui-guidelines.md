## 1. はじめに

**目的**: 画面を足す・直すときに「このアプリではこうする」を 1 か所で引けるようにする。

**読む人**: 画面を触る開発者、実装・レビューをする AI のエージェント、PR をレビューする人。初めて読む人向けに書く。

**ほかの文書との関係**:

| 文書 | 役割 |
|---|---|
| このガイドライン | **原則と規則**（なぜ・こうする / こうしない・何で確かめるか）。画面の中身が変わっても変わりにくいもの |
| `docs/design.md` | **設計書**（考え方・記録の形・判定・画面の一覧）。規則の出どころとして節番号で参照する（9.1 からこの文書へリンクしている） |
| `CLAUDE.md` | リポジトリの作りと確認の手順 |

食い違ったら、このガイドラインを直すか設計書を直すかを PR で決める（黙ってどちらかに合わせない）。

**このアプリの前提**: 裁量トレードの損失ノート。トレーダーが決済の後に 1 回、スマホで素早く記録し（設計書 7.5）、PC で広く振り返る（設計書 9.1）。物差しは「勝ったか」ではなく「計画どおりだったか」（設計書 1.1）。動機は「入力が面倒で記録が続かない」（設計書 K10）なので、**記録の手間を減らすことと、開きたくなる見た目は、機能と同じ重さ** で扱う（設計書 K2）。

### この文書の読み方

規則は 3 つの層でつながっています。**原則**（2 章。なぜそうするか）→ **規則**（3 章・9 章・10 章。こうする / こうしない）→ **検査**（6 章。機械か目で確かめる）。規則には、どの原則から来たか（P1〜P13・A1〜A8）と、何で確かめるかを添えます。

| 知りたいこと | 読む所 |
|---|---|
| このアプリの画面の考え方を 5 分でつかむ | 2 章（原則の表）と 9.1（構成の原則の表） |
| 色・数字・取り消し・戻る・幅・当たり・言葉などの規則 | 3 章（原則ごと） |
| タブ・次の画面・シートのどれで出すか、縦 / 横 / 広いの形 | 9.2〜9.5・9.7 |
| ホームと記録する画面の形（1 画面・2 つの段） | 9.4 |
| 入力の欄・キーボード・下の帯 | 10.1（安全域は 9.6） |
| 終わった・失敗した・保存できたをどう知らせるか | 10.2（動きは 9.8） |
| 文字が入らないとき（切らない・折り返す・省略） | 10.3 |
| 使えない欄・押せないボタン | 10.4 |
| 読み込み中・空・失敗の画面 | 10.5 |
| 1 画面に入らないときに何を削るか | 10.6 |
| ボタンの重さ・押せる行・チップ | 9.12 |
| 文字の大きさ・余白・角丸・面 | 9.9（値は `ui/src/styles/tokens.css`） |
| 画面に出す言葉 | 8 章 |
| PR の前に確かめること・検査の名前 | 6 章 |
| ガイドラインと今の画面の違い（これから直す所） | 5 章 |

規則の書き方と番号の約束:

- 規則は「する / しない / 検査」で書く。**検査** は機械で確かめているもの（`npm test` の vitest、`npm run ui:check`）。検査の無い規則は目で確かめる（6 章）
- ガイドラインは **目指す形** を書く。今の画面が違っていても、ガイドラインを今の画面に合わせて書き換えない。違いは 5 章の表に載せ、Issue で直す
- 原則の番号（P1〜・A1〜）と章・節の番号（3 章の「P4」、「9.7」、「10.1」など）は、コードのコメント・テスト・ADR・設計書から引かれている。**番号は付け替えない**。足すときは末尾に足し、無くす規則は節を残して行き先を書く
- 8 章の表（8.1〜8.4）はテスト（`tests/ui/wording.test.ts`）が見出しの文字と表の形で読む。見出しと列の並びを変えない
- 規則を足す・変えるときは、原則（どの P か）・検査（何で確かめるか。無ければ「目で」）・5 章（今の画面との違い）を同じ PR でそろえる

## 3. 原則ごとの規則

各行は「こうする / こうしない」とアプリの中の実例。画面の構成（どこに出すか）に関わる規則は 9 章、操作の作法（入力・知らせ・文字の切り方など）は 10 章に詳しく書き、ここからは節の番号で引く。

### P1 記録の手間の予算

- する: 記録する画面は全画面のシートの中の 2 つの段（1 段目「スクショを入れる」→ 2 段目「振り返る」= LC と一言 → 2 つのタップ）で、主の動作（[記録する]）は 1 つ。明細の読み取りを待たせない（9.4・設計書 C23）
- する: 入力の既定値を置き、手で打つ欄を増やさない（設計書 C17・C19）。2〜3 択は `Segment`（タップ 1 回）で、プルダウンにしない。4 択以上（決済の理由など）は 1 行の `select`（`.select`。当たり 44px・文字 16px）
- する: 任意の欄は主の流れに置かず、取引の欄のシートの次の段に送る（9.3）。入力を増やす機能は、30 秒の予算と引き換えにする（何を減らすかを同じ PR で決める。10.6）
- する: 下の帯は 1 つ（判定の 1 行 + [記録する]）で、幅 360px で 112px 以下。状態の文は 1 行で、360px で切れない短さにする（長い知らせは判定のシートに全文で）。保存の失敗の知らせ（[もう一度ログイン] を含む）が出ている間だけ伸びてよい。記録中は下のタブを隠す（帯を 2 段重ねない。9.2）。キーボードが出ている間は帯を貼り付けず本文の最後に置く（10.1）
- する: 押せない理由は、帯には数（「あと 6 欄」「誤り 1 欄」）か一言（「明細を読み取っています」）だけ、欄の名前は判定のシートに文で出し、[記録する] の読み上げの説明（`aria-describedby`）に結ぶ（色だけに頼らない。10.4）。そろったら帯に判定の要約を出す
- する: 判定は下の帯に常に 1 行で出し、押すと判定のシート（9.3）。タップのたびに画面を動かさない
- する: 開いた直後の 1 画面に、その段でやることが全部入る（9.4・10.6）。画面の説明文を付けない。送る前の注意（設計書 C38）は畳まずに各枠の下に 3 行以下、補足は「i」の説明のシートに置く。PC だけの貼り付けの案内は指で触る端末では出さない
- する: 行き先（ホーム・取引・振り返り・設定）と真ん中の ［＋ 記録］ は、どの画面からも 1 タップ（9.2）
- しない: 記録の途中に確認・説明のダイアログを挟む。任意の欄を必須にする。閉じる操作の要る知らせを足す（10.2）
- 検査: `ui:check` の V6（下のタブ 4 つ + ［＋ 記録］・全画面のシートの間はタブを隠す）、記録する画面の R1〜R10（R10 = 明細を貼って打つ 2・選ぶ 2 で判定まで）・LD1（記録する画面に「LC を入る前に決めていたか」が無く、編集の画面は前からの「価格あり・決めていなかった」の取引だけ問いを出す。#202）、下の帯の高さ（112px まで）と状態の文の行数・切れ（幅 360 の全状態）、R11（最後のタップの直後に帯の判定の 1 行が窓の中）・R12（1 画面に収まる。9.10）、ACC1・ACC2（口座の Segment の 1 タップ・その場で足す）。`record-view.test.tsx`「帯には数、名前は判定の枠」。30 秒の人の実測は [`record-timing-check.md`](record-timing-check.md)

### P2 色は規律を表す

- する: 判定の段のトークンは `--tier-{plan,break,worst,neutral}-{ink,tint,line,solid}` の 4 つの役割（9.9 の表。#229・C61）。文字・記号・線は `ink`、バッジ・印の地と 1 件の取引の判定のカードの面は `tint`、縁は `line`、帯・面の塗りは `solid`。文字用の `ink` で面や帯を塗らない。段と判定の対応は `ui/src/lib/badge.ts` の 1 か所（A・計画どおりの勝ち = 計画どおり、B・危ない勝ち = 崩れ、C = 極悪、判定なし = 中立）
- する: 強調の色（`--accent`）は操作にだけ使い、判定の段の色と混ぜない。使う所は 6 つ（主のボタン・開いているタブ・2 番目の重さのボタンの文字と枠・トーストの操作のボタン・文の中のリンク・フォーカス。9.9）
- しない: 損益・R の正負で文字や面の色を変える。判定の段の色を判定以外（入力の誤りなど）に使う（入力の誤りは `--danger`）
- する: 判定の枠の LC の物差し（#34。`components/Ruler.tsx`）は色を足さない。線・点・文字は文字と線のトークン（`--ink*`・`--line*`）だけで、点の種類（イン・決めた LC・広げた後の LC・決済・TP）は形で見分ける（判定の段の色も使わない。窓・滑りの A で越えた区間が「計画どおり」の色にならないように）

### P3 数字は符号と単位で読ませる

- する: 同じ画面の見方の選択（振り返りのタブの期間と取り込みの切り替え。#88・#128）は URL の検索部分（`/review?period=7d&imports=1`）に入れ、履歴を積まずに置き換える（`navigator.replace`）。同じ画面の検索部分だけの置き換えでは見出しへフォーカスを移さず、スクロールもしない（押した選択肢にフォーカスが残る）。再読み込み・URL を開くで同じ見方に着く。知らない値は既定（7 日）
- する: 履歴はいつも「ホーム + 今のタブの積み重ね」。タブはそれぞれ次の画面の積み重ねを記憶に持ち、切り替えると前の積み重ねが戻る。同じタブをもう一度押すと根へ。戻るは今のタブの積み重ねを 1 つ戻り、ホーム以外のタブの根ではホームへ。直接開いたときは起動で履歴をこの形に組み直す（規則と例は 9.7）
- する: キャンセル（✕）の「前の画面」は、アプリの中で進んで来た画面があればそこへ戻り（履歴を増やさない。`history.state` の `appDepth`）、URL を直接開いた画面では記録する画面はホーム・編集の画面は詳細へ置き換える（戻るでアプリの外へ出ない。`router.tsx` の `back`。#75）
- しない: ハッシュ（`#/trades`）の URL。画面の状態を端末に保存して URL と食い違わせる
- 検査: `routes.test.ts`（V1〜V6・`safeNext`・行き来の種類 push / pop）、`ui:check` の V1〜V7・S1（長い画面でスクロール → 進む → 先頭、戻る → 元の位置）。層は `back-layers.test.ts`（戻るで閉じる・UI で閉じた後の履歴の数・画面が移らない）と `ui:check` の IT1〜IT3

### P7 どの幅でも崩れない

- する: 画面の形は 3 つ（縦・横・広い。境目は幅 600・1024・1280 と高さ 500。キーボードを除いた大きさで決める。9.5）。中身の最大の幅は形ごと。View の中の並びの段は、窓ではなく列の幅のコンテナクエリで決める
- する: 数字・ボタン・バッジ・セグメントの項目は `white-space: nowrap`。3 択のセグメントの文言は幅 360px で入る短さ（4〜5 字）にする（入らなければ `ui:check` の「部品のはみ出し」が拾う）。文は折り返す。何を切らず・何を折り返し・何を省略してよいかは 10.3
- する: 枠（四辺の線か、親と違う面の色を持つ箱。入力欄・ボタン・セグメントの項目・画像・canvas を含む）の入れ子は 2 段まで（面の上の枠 → その中の入力の部品）。カードの中では内枠を作らず、区切りは 1 辺の線か余白で示す（#33）
- しない: 幅ごとに別の画面を作る。スマホだけ機能を落とす。カード → 内枠 → 部品の 3 段の入れ子
- 検査: `ui:check`（枠の入れ子 3 段以上 0 件（擬似要素・影・輪郭は数えない。`--inject-clip` の入れ子の見本で見逃さないことを確かめられる）、横スクロール 0px、折り返さない部品（ボタン・セグメント・バッジ・行き先など）のはみ出し 0 件 = 部品の中で文字が横・縦に箱を超える・部品ごと親の左右を超える・overflow の祖先で切られる。`--inject-wide 400` と `--inject-clip` で検査が崩れを見逃さないことを確かめられる）

### P8 指でもキーでも読み上げでも使える

- する: 押せるもの（リンク・ボタン・選択肢・入力欄・タブ）の当たりは 44×44px 以上（`--tap`）。セグメントの radio は項目の全面に透明で重ね、当たり = 項目
- する: フォーカスの輪は `:focus-visible` で `--focus`。入力欄は文字 16px 以上（iOS の自動拡大を避ける。欄の種類とキーボードは 10.1）
- する: 外側の枠がフォーカスを示す欄（数・文字・日時の欄の `.numfield`・選択の `.select`）は、枠の色と角丸に沿う光（box-shadow）だけで示し、内側の要素に共通の輪（outline）を重ねない（角丸の枠の外に四角い枠がずれて出る。#52。`ui:check` の FOC1）
- する: 入力の部品（入力欄・セグメント）の枠（`--field-line`）とフォーカスの輪（`--focus`）は、面に対して両テーマで 3:1 以上（WCAG 1.4.11）
- する: 選んだ選択肢は面の濃さ・強調の枠・文字の前のチェックの記号の 3 つで示す（遠目・屋外でも分かる。色だけに頼らない。記号は項目の中に収め、文字に重ねない）
- する: 文字のトークン（`--ink`・`--ink-2`・`--ink-3`）× 面（`--bg`・`--s1`〜`--s3`）、`--on-accent` × `--accent`、バッジの文字 × 地、`--danger` × 面は両テーマで 4.5:1 以上
- する: 「i」は `button`（`type="button"`）で、名前は「「〈言葉〉」の説明」。見た目は 20px の丸（小さいラベルの「R」・物差し・札は 16px）、当たりは 44×44px（負の余白でラベルの段の高さを変えない）。押すと説明のシートが開き（縦 = 下から、横 = 右のパネル、広い = 押した所の吹き出し。9.3）、Esc・戻る・✕ で閉じたらフォーカスを「i」へ戻す。説明は同時に 1 つ。文の中の用語集のリンクは当たりの 44px の例外（WCAG 2.5.8 の inline）（`lib/info-tip.ts`。#57・#129）
- しない: `div` に `onClick` だけ付けてボタンにする。記号だけのボタンに名前を付けない
- する: 文字の大きさは `--fs-*` のトークン、行の高さは倍率か文字の大きさからの `calc` で決める（px の決め打ちにしない）。端末で文字を大きくしたとき（Android の Chrome の文字の拡大は px の文字も大きくする）に、文字だけ大きくならない・行が重なることを避ける（WCAG 1.4.4。#79）
- する: フォーカスした欄を、貼り付いた帯やキーボードで隠さない（WCAG 2.4.11。寄せ方と帯の扱いは 10.1）。使えない欄・押せないボタンの形は 10.4
- 検査: `ui:check`（幅 360 の当たり < 44 の件数・文字の拡大 200% の状態）、`cssTokens.test.ts` (d)・「入力の部品の枠とフォーカスの輪は 3:1」

### P9 速く、動きは因果の分だけ

- する: 動きは因果の分だけ（押した手応え・次の画面・タブ・シート・セグメントの選択・判定が出た・読み取りが終わった・保存の後。場面ごとの時間と作りは 9.8、知らせとしての使い方は 10.2）。時間と曲線はトークン（`--dur-fast` / `--dur-base` / `--dur-sheet` と `--ease` / `--ease-sheet`）だけで書く。`prefers-reduced-motion: reduce` ではトークンを 0s にする
- しない: 飾りのアニメーション（浮き沈み・跳ねる）。繰り返す動き。振動。ms の直書き
- 検査: 目で（6 章）

### P10 利用者の言葉

- する: 相場の言葉（LC・TP・イン・エントリー・決済・ロング / ショート・足・窓・滑り）はそのまま。判定はオーナーの言葉（A いい損失 / B 悪い損失 / C 極悪な損失 / 計画どおりの勝ち / 危ない勝ち）
- する: 操作の言葉・相場の用語は 8 章の用語集にそろえる（キャンセル・追加・削除・保存・再読み込み など一般的なアプリの言葉。1 つのものに 1 つの言葉）。誤りの文の中の [〜] は押すボタンの名前と一字一句同じにする
- しない: 開発中の合言葉・内部の識別子（tier・grade・route など）を画面に出す。設計書の内部の呼び名（崩れの条件・3 つのタップ など）は 8.3 の対応表で画面の言い方に直す
- 検査: `tests/ui/wording.test.ts`（8 章の表を読み、使わない言葉が画面の文字列に 0 件・対応表と画面の名前が一致・[〜] がボタンの名前）と目で（6 章）

### P11 安全な作り

- する: スタイルはクラスと `data-*` / ARIA 属性だけで切り替える。テーマは `<html data-theme>`（`applyTheme`）。ビルドの `index.html` はインラインの script / style・style 属性・外部 URL を持たない
- する: 画面から API へは `/api/...`（同一オリジン）だけで、`ui/src/auth/session.ts` の `api` を通す（ログイン中の ID トークンを付け、ログインしていなければ送らない）。Firestore・Storage の SDK を画面で読み込まない（firebase は `firebase/app`・`firebase/auth` だけ）
- する: ログインできないときは決まった文言だけを出し（「ログインのサービスと通信できませんでした」など）、コード・例外の本文を出さない。白い画面にしない（ADR-0003）
- する: 画像のプレビューは canvas に描く（決済明細の読み取り。#15）。object URL・data URL を作らない（CSP の img-src に `blob:`・`data:` を足さない）
- 例外: 書き出したファイルの保存（#167・ADR-0025）は `ui/src/lib/download.ts` だけが文字の Blob の object URL を作り、`a[download]` で保存してすぐ取り消す（img・canvas・iframe に使わない。CSP は変えない）
- しない: `innerHTML` などの HTML の文字列を DOM に入れる API、JSX の `style`、`.style` の書き換え。外部のフォント・CDN・画像を読む（書体は同梱の数字の書体だけ。CSS の url() は `base.css` の `@font-face` の 1 か所。#237）。`createObjectURL`・`toDataURL`・`FileReader`
- 検査: `csp-check.sh`（assets の CSS の url() に data: と外部が無い。#237）、`source-rules.test.ts`（自己テスト付き。object URL・data URL の規則は #15 の AC-13）、`cssTokens.test.ts`「url() は数字の書体の @font-face の 1 か所だけ・@import は書かない」

### P12 見た目はトークンで

- する: `tokens.css` は「テーマに依らない `:root`（文字・余白・角丸・動き・大きさ）」と「原色の層（`:root` の `--c-*` だけの規則）」と「テーマの 2 つの定義（`:root, :root[data-theme="dark"]` = 既定のダーク、`:root[data-theme="light"]`）」だけ。色の値（影・暗い面の色の部分も）は原色の層にだけ書き、2 つの定義は原色の参照（`var(--c-…)`）だけで役割を決めて名前の組をそろえる。原色の名前は `--c-<色相>-<段>`（段は OKLCH の明るさから。`-aNN` は不透明度）。部品・枠・画面の CSS は原色を直接使わない（役割だけ。#229・C61）
- する: 部品の CSS（`components.css`）・枠の CSS（`layout.css`）は `var(--…)` と、トークン同士の `color-mix()` だけで色を書く。TSX はクラス名だけを持ち、見た目の値を持たない
- する: 角丸は `--radius-sm` 10px・`--radius-md` 14px・`--radius-lg` 18px・シートの上の角の `--radius-sheet` 28px と、丸い形の `--radius-pill` だけ。部品の CSS に px の角丸を直書きしない（#33・9.9）
- する: テーマは OS の設定で選ばない（既定はダーク。選んだテーマは端末に記憶）
- する: 開発の時だけの部品の見本の CSS は `ui/src/pages/dev/parts.css` に置き、見本の画面からだけ読み込む（本番の CSS に入れない）
- 検査: `cssTokens.test.ts` (a)(b)(c)「prefers-color-scheme を使わない」「TSX に色の直書きが無い」「角丸のトークンと直書き 0 件」

### P13 起きたことは、その場で知らせる

- する: 押した・進んでいる・終わった・失敗した・何も無い、のどれにも見える形を決める。使い分け（その場の文 / 札 / トースト / シート / 動き）は 10.2 の表、読み込み中・空・失敗の画面は 10.5
- する: 知らせは起きた場所に 1 回だけ出す。同じことを帯・カード・トーストで重ねない。閉じる操作を要らせない
- する: 読み上げの領域（状態 = `role="status"`、失敗・誤り = `role="alert"`）は先に描いておき、中身だけを替える（WCAG 4.1.3）
- しない: 振動（`navigator.vibrate`）・音。完了を知らせるだけのトースト・ダイアログ。白い画面・黙った失敗
- 検査: 10.2・10.5 の検査の行

### 4.3 標準と違う判断をしている所（理由つき）

| 標準 | このアプリ | 理由 |

| キーボードの上に操作の帯（次へ・完了・送信）を付ける作り（チャットやフォームのアプリに多い） | キーボードが出ている間は、下に貼り付いた帯を貼り付けず、スクロールする本文の最後に置く（10.1） | 縦の窓の 4 割前後をキーボードが取る。その上に帯を残すと、入れている欄と前後の欄を見る場所が残らない（オーナーの指摘。#172・#173）。主の操作は下へスクロールすれば押せ（#183）、キーボードを閉じると下の端に戻る |
| 完了・保存をトースト（Snackbar）で知らせる | トーストは取り消し（[元に戻す]）と戻る道（[記録に戻る]）だけ。完了・失敗はその場の文と画面の移り（10.2） | トーストは消えるので、見逃すと手がかりが残らない。読み取りの結果は確かめてほしい中身で、要約の行のその場に残す（#166） |
| 手応えに振動（haptics）を使う | 使わない | オーナーが決めた（「振動は要らないよ。」#166）。iPhone の Safari では `navigator.vibrate` が動かず、端末で体験が割れる |
| 引き下げて読み直す（pull to refresh）・行のスワイプ | 使わない（9.3） | 書きかけが消える再読み込みを誘う。iPhone の端からの戻るとぶつかる |
| 使えない欄は `disabled` で止める | 自分の選択で止まった欄は、薄い形のまま押せて、押すと選択が外れる（10.4） | `disabled` はタップを受けず、どこを押せば戻るかを探させる（オーナーの指摘。#171） |

## 8. 用語集（画面の言葉）

画面の文字と読み上げの名前で使う言葉の決まり（#74。オーナーの「一般的な文言になっていないところが多い」「相場用語を統一したい」から）。

- 基準: ① 一般的なアプリ（iOS・Android・Google・Notion など）の標準の操作の言葉 ② 同じものは画面をまたいで同じ言葉 ③ 相場の言葉は言い換えない ④ 開発中にできた造語を出さない ⑤ 短く、360px で折れない ⑥ 誤り・注意の文は何が起きたかと次に何をするかを言い切る
- 表のバッククォートで囲んだ言葉はテスト（`tests/ui/wording.test.ts`）が読む。「使わない言葉」は画面の文字列（`ui/src` の文字列・JSX の文字・テンプレートの文字。開発用の部品の見本とコメントを除く）に 1 つも出ない。言葉を足す・変えるときは、表と画面を同じ PR で直す
- 利用者が引くアプリの中の用語集（「i」の吹き出しと用語集の画面。`ui/src/lib/glossary.ts`）の見出しも、この章の言葉にそろえる（8.3）

| `入力`・`入力してください`・`手入力` | `入れてください`・`手で入れ`・`手で` | 誤りの文は「〜を入力してください」。数は「数値」 |
| `貼り付け`・`貼り付ける` | `貼る`・`貼れ`・`貼っ`・`貼ると` | 画像の貼り付け。行き先は `この欄` |

| `タイムゾーン` | `時間帯` | 明細の時刻のタイムゾーン |

| `指定なし` | `選ばない`・`選んでいない` | 時間足の選択肢と表示 |

テストで分けられないもの: 「直す」（編集の意味か誤りを正す意味か）と「変える」（「変更」にする操作か、「名前を変えると」のような文か）は意味で分かれるので、レビューで見る。JSX の式をはさんで割れた文（`「{PROVISIONAL_MARK}」は…`）は、割れた片ごとに検査する。

### 9.2 ナビ

### 9.3 3 つの重ね方

| 形 | 動き | 使う所 | 閉じ方 |
|---|---|---|---|
| **次の画面**（push） | 右から重なる。上の帯に「‹ 前の画面の名前」と題。タブは残る | 取引 → 詳細、詳細 → すべての欄・総評、設定 → 口座 / 銘柄 / AI の利用状況 / 用語集、振り返り → 数で見る・崩れの取引 | 戻る・「‹」 |

下のシートにするもの: 「i」の説明（説明のシート。用語集のリンクをたどる規則は P6 のまま）・取引の欄（記録する画面の要約の ［編集］。口座の追加の 2 欄もこの中に開く）・ほかの欄（任意。取引の欄のシートの次の段）・チャート（記録する画面の 2 段目のチャートの行・1 段目のチャートのある小さな枠。時間足・差し替え・削除・決済時・追加のチャート）・判定（下の帯の 1 行を押す）・記録したときの値と今の値の比較・詳細の操作（「…」= 今の値と比べる・削除）・期間の指定・明細のタイムゾーン・口座の追加・保存の後の good / more（#123）。チャートの拡大は画像を全画面で見る層（黒い面・✕）。

- する: 開く・閉じるは `lib/back-stack.ts` の層に載せる（履歴に 1 段積み、戻るで上から 1 つ閉じる。今の「i」の規則のまま）。Android の Chrome は、`showModal()` の間の戻る・Esc を dialog の `cancel` → `close` に回し `popstate` を出さない（close watcher）。dialog の `close` は UI で閉じたのと同じに扱い、糊が積んだ段を `history.back()` で戻して数を合わせる（P6 の規則。`back-layers.test.ts` に例を足す）。取り消せる `cancel` は Esc と同じ（たどった説明なら 1 つ前へ）、取り消せない `cancel`（操作をはさまずに続けた 2 回目の戻る）はシートごと閉じる（「戻るで 1 つずつ」の例外。#129）。キーの Esc は dialog の `keydown` を取り消して自分で扱い、close watcher を通さない（続けて押しても 1 つずつ戻る）

- する: シートを開いている間は、トーストの取り消しの時間（[元に戻す] の 8 秒）を止め、閉じたら続ける（モーダルの間は外が inert になり、トーストを押せないため）
- する: シートの見せ方は形で替える（同じ部品）。見せ方は同じ `<dialog>` 要素のクラスと `data-form` の CSS だけで替え、作り直さない（口座の追加・期間・取引の欄のシートの入力の欄の値とフォーカスを、形が替わっても保つ。9.5 の「DOM の形を替えるのは入力の欄を持たない側だけ」と同じ）。縦 = 下から、横 = 右から出るパネル（幅 400px・高さいっぱい）、広い = 説明と小さな操作は押した所の吹き出し / メニュー（幅 360px まで。最上層の dialog なので、置き方は CSS の anchor positioning（`position-area` と `position-try-fallbacks`。下 → 上・左端そろえ → 右端そろえ、3 つの質問・物差しは上を先に）。使えないブラウザでは中央。後ろは暗くせず、面の端は線で示す。#129）・入力のあるものは中央のダイアログ（幅 480px・最大の高さ 80%）。右から出るパネルは広い形では使わない（分割の右の列とまぎらわしい）
- しない: 中央の確認のダイアログ（P4 のまま。確認は誘惑ガードだけ）。その場で開く折りたたみ（`<details>`）と、欄に重なる吹き出し（縦と横の形）。例外は用語集の画面の中のページの中のリンク
- しない（最初は）: 下へ引いてシートを閉じる操作（指の動きを追う処理が要る）。行のスワイプ（iPhone の左端からの戻るとぶつかる）。引き下げて読み直す（`overscroll-behavior-y: contain` でブラウザの引っ張って再読み込みも止める。書きかけが消えるため）
- トーストは今のまま（縦は下のタブの上・全画面のシートの間は下の帯の上、横と広いは右下）

### 9.4 スクロールしないホームと 2 つの段の記録する

- する: pointer と hover は、ホバーの見た目（`@media (hover: hover)`）と押したときの縮み（`@media (hover: none)`）にだけ使う（指で触る PC・マウスをつないだタブレットで、同じ窓の大きさが違う画面にならないように）
- する: 高さを見る。スマホの横向き（844×390・932×430）は幅だけなら PC の側になるが、縦 400px 前後に上下の帯は置けないので「横」にする。横と広いは高さ 500 で排他（ノートの低い窓 1366×600・拡大 150% の 1280×620 も「広い」）
- 端末ごと: タブレットの縦（768×1024・Android の 800×1280）は「縦」（下のタブ + 640px の 1 列。2 列にすると 1 列がスマホより狭い）。タブレットの横（1024×768・1280×800）は「広い」。折りたたみの開いた縦（690×830 前後）は「縦」、開いた横は幅と高さしだいで「縦」か「広い」、閉じた外の画面（340px 前後）は「縦」。開閉は幅が変わるので、入力中でもすぐ決め直す（欄の値とフォーカスは保つ）
- する: View の中の並びの段（一覧の口座の位置・詳細の「エントリー … →」・レッグの表など、今の窓の幅 480 / 720 の段）は、窓ではなく列の幅のコンテナクエリにする（分割の左の列 440px で 720 以上の並びにならないように）
- する: 向きは固定しない（manifest に `orientation` を書かない。Web では iPhone の向きを固定できず、横で使う人もいる）。主の形は縦で、横は「崩れない・記録ができる」を守る
- しない: 形の境目を足す（境目は幅 600・1024・1280 と高さ 500 だけ）。形ごとに機能を落とす（P7）。幅の下限は 360px（P7。320px でも横スクロールを出さないのは目標で、検査はしない = P8 の組み替え）

同じ部品の 3 つの形:

| 部品 | 縦 | 横 | 広い |
|---|---|---|---|
| ナビ | 下のタブ + 真ん中の ［＋ 記録］ | 左のレール | 左のサイドバー（1024〜1279 はレール） |
| 画面の題 | 根は大きな題、次の画面は上の帯 | 列の先頭の小さな題（上の帯は置かない） | 中身の先頭の大きな題（上の帯は置かない） |
| 記録する | 全画面のシート・1 列・下の帯に判定。左上に ✕ | 全画面のシート（レールを隠す）・2 列（左 = 欄がスクロール / 右 = 判定と ［記録する］）。左上に ✕ | サイドバーを残した中身の面いっぱいのパネル・2 列・右 420px に判定と ［記録する］ を貼り付け。取引の欄は畳まない（#38）。パネルの左上に ✕。開いている間、サイドバーの ［＋ 記録する］ は選択中の表示で押しても同じ画面（主のボタンは右の列の 1 つ） |

### 9.6 安全域とキーボード

- する: `index.html` の viewport に `viewport-fit=cover` と `interactive-widget=resizes-content` を足し、`apple-mobile-web-app-status-bar-style` を `black-translucent` にして、上の安全域まで面を敷く（ライトのテーマでは状態のバーの文字が白のままなので、上の安全域の面だけ暗くする）。`resizes-content` で Android の Chrome は窓がキーボードの分だけ縮む（iPhone の Safari はこの指定を見ず、窓は縮まない。どちらでも同じ振る舞いにする規則は 10.1）。窓が縮んでも形は替えない（9.5。形はキーボードを除いた大きさで決める）
- する: 安全域は `env(safe-area-inset-*)` を受けるトークン `--safe-top / right / bottom / left` を通して使う（検査から値を差し替えられるように）。上の帯・タブ・レール・シート・トーストは `--safe-*` の分だけ内側に寄せ、面は端まで敷く。横の形ではノッチが左右どちらにも来るので、左右の両方に入れる
- する: 実機（ホーム画面に追加した iPhone）で安全域を確かめる（Chromium では `env()` が 0 で、`ui:check` は差し替えた値でしか見られない）
- する: キーボードが出ているかは `visualViewport` の `resize` を聞く薄い層（純関数 + 糊）で決め、出ている間は `<html>` に印を付ける。印の間の振る舞い（フォーカスした欄を見える範囲へ寄せる・下に貼り付いた帯を本文の最後へ移す・決定キー）は 10.1 が正
- する: 横の形でキーボードが出たら、左の列はフォーカスした欄だけが見えるように送り、右の列（判定と ［記録する］）はそのまま残す（列が左右なので、欄と縦を取り合わない。本文の最後へ移すのは下に貼り付いた帯だけ。10.1）
- する: 欄の種類（`inputmode`）と決定キー（`enterkeyhint`）は 10.1。シートは `dvh` で高さを決め、キーボードで縮む
- しない: 下に固定した帯を、キーボードの裏に置いたままにする・キーボードの上に残す（本文の最後へ移す。10.1）。`.style` で位置を書き換えて帯をキーボードに追わせる（P11）

### 9.7 行き来と戻る

iOS のタブの作法に寄せる。**タブはそれぞれ次の画面の積み重ねを持ち、戻るは今のタブの積み重ねを 1 つ戻る**。

規則:

1. **履歴の形は「ホーム + 今のタブの積み重ね」**（直接開いたときも 5 でこの形に揃える）: ブラウザの履歴は、いちばん下にホーム（`/`）、その上に今のタブの根（ホーム以外のとき）、その上に今のタブで開いた次の画面、の順に積む。シート（下のシート・全画面のシート）の段は、その上に `back-stack` の層として積む（URL は変えない。全画面のシートは今の URL `/record`・`/trades/{id}/edit` の 1 段）
2. **タブを切り替える**（A → B）: 先に開いている層を閉じ（`back-stack` の段を戻し終える。今の P6 の「置き換えの前に積んだ段を戻し終える」と同じ）、全画面のシート（記録する・編集）が開いていれば閉じて書きかけを残し「記録の入力は残っています」+ ［記録に戻る］ を出す（ADR-0019。全画面のシートはどのタブの積み重ねにも残さず、戻ったタブで黙って開き直さない）。A の積み重ねと各画面のスクロールの位置を記憶に残してから、履歴をホームの段まで `history.go(-k)` で戻し、B の根（B がホームなら根は戻った段そのもの）と B の記憶の積み重ねを 1 つずつ push し直す（B で前に開いていた次の画面が出る。#127 で決めた: 根の段を置き換えると前のタブの「進む」側の段が残り、進むで別のタブの画面へ入れてしまうため、置き換えずに積み直す。履歴の形は同じ）。戻す段の数は、今の項目の印の深さ（`appDepth`）で決める。画面が自分で積む段（用語集の中で言葉をたどった `#…` の段）も深さに数える（数えないと戻る段が足りず、タブの根の下に用語集が残る。#127 のレビュー B1）。戻すあいだの `popstate` は router が画面に出さない。push し直した項目はブラウザがスクロールの位置を正しく覚えていないので、記憶した位置を殻が戻す（いちばん上の画面は着いたとき、その下の段は後で戻って着いたとき。`back-stack` が積んでいる間の `scrollRestoration = manual` は今のまま、タブを替える前に層の段を戻し終えて auto に戻す。#127）。用語集の中でたどった段は、タブの記憶では用語集の 1 段にまとめる
3. **同じタブをもう一度押す**: 次の画面を開いていれば `history.go(-k)` で根へ戻り、記憶の積み重ねを捨てる。根にいれば先頭へ送って裏で読み直す
4. **戻る**（Android のキー・端からのスワイプ・ブラウザの戻る）: いちばん上の層があれば 1 つ閉じる → 全画面のシートなら閉じて書きかけを残す（「記録の入力は残っています」。ADR-0019）→ 次の画面なら 1 つ前へ → ホーム以外のタブの根ならホームへ（アプリの外へ出さない）→ **ホームの根ではアプリを出られる**（ブラウザ・OS に任せる。ホーム画面から開いたアプリなら閉じる。ホームの下に項目を足さない・`popstate` で押し戻さない。戻るを罠にしない）
5. **履歴を組み直すのは、アプリの印が無いときだけ**: 起動のとき、今の項目の `history.state` にアプリの印（`appDepth`・タブ・積み重ねの位置）が無いとき（新しく開いた・外のリンクから来た・ホーム画面のアイコン・共有）だけ、今の項目をホーム `/` に置き換え、URL から決まるタブの根と次の画面を push する（例: `/trades/a` → `[/, /trades, /trades/a]`、`/trades/a/edit` → `[/, /trades, /trades/a, /trades/a/edit]`、`/record` → `[/, /record]`、`/settings/accounts` → `[/, /settings, /settings/accounts]`）。ホーム画面のアイコンは `start_url` の `/` で開くので、組み直しは要らない（`[/]`）。**印があるとき（再読み込み・bfcache・前へ / 次へで戻ってきた）は組み直さない**。ブラウザが保っている履歴の並びのまま、今の項目の印からタブと積み重ねの記憶を戻す（二重に積まない）。今の項目が層の段（`back-stack` の印。シートを開いたまま再読み込み）なら、シートは開き直さず、画面に出さずに、層の印が持つ深さ n（たどった説明・重ねたシートで 2 段以上もある）だけ `history.go(-n)` で画面の段へ戻る（層の段に `replaceState` で印を外すだけだと、同じ URL の段が 2 つ並び、戻るが 1 回効かなく見えるため。前へ側に残った層の段は、次に積むときに消える）。それより前に「進む」で層の印を持つ段に入ったとき（URL は同じで、シートは開いていない）は、糊が開いていない層の段と見て、画面に出さずに同じ規則で画面の段へ戻す。**組み直しを履歴に書くのは、利用者の最初の操作（押す・キーを打つ = ユーザーのアクティベーション）のとき**（#127 で決めた）。起動の直後に操作なしで `pushState` すると、Chrome の「操作の無い項目を戻るで飛ばす」仕組みが戻るのボタンだけでなく `history.go` にも効き、直接開いた詳細でホームのタブを押すと、組み直した段を飛ばして前のページまで戻ってしまう（ui:check の V6 で再現した）。書くまでの間も、今の画面の印（タブ・深さ）は組み直した後の形として扱う。**既知の挙動: 直接開いて一度も触らずに戻ると、根やホームを通らずにアプリを出る**（Android の戻る・ブラウザの戻る・iPhone の端からのスワイプのどれでも。罠にはならない側の外れ）。一度でも触った後は組み直した並びで戻る。ログインの門が触る前に置き換えたとき（ログインしていないまま開いた）は組み直しを捨てて 1 段のまま残し、ログインした後の行き先への置き換え（ログインの押下が操作）で組み直す。ログアウト（ログインの画面への置き換え）はホームの段まで戻ってから置き換え、タブの記憶を捨てる（次にログインした利用者にタブ・積み重ねを持ち越さない）。タブは URL で決める（`/trades*` = 取引、`/review*` = 振り返り、`/settings*`・`/glossary` = 設定、ほか = ホーム）。ホームの行から開いた詳細はホームのタブの積み重ねで、その印も state に持つ
6. **全画面のシートの「前の画面」**: ✕（キャンセル）で入力が無いとき・保存の後に戻る先は、今の積み重ねの 1 つ下（`history.back()`）。5 の組み直しで直接開いても下にホーム（編集は詳細）があるので、`appDepth` が 0 になる場合は無くなる。再読み込みでは印の `appDepth` をそのまま使う（ADR-0019 の決定 5・11 への追記）
- `back-stack` との関係: 層の段は今の画面の項目の上に積む（URL は同じ・印は層）。タブの切り替え・画面の移り・組み直しの前に層の段を戻し終え、再読み込みで残った層の段は 5 のとおり画面の段に戻す。層の規則（戻るで 1 つ閉じる・UI で閉じたら糊が数を合わせる・close watcher）は P6・9.3 のまま
7. **広い形と横の形の分割で行を選ぶ**: `/trades/{id}` は置き換え（戻るで 1 件ずつたどらない）

| 例（縦の形） | 履歴 | 戻ると |
|---|---|---|
| ホーム → 取引 → 行 a | `[/, /trades, /trades/a]` | `/trades` |
| 続けて設定のタブ | `[/, /settings]`（取引の記憶 = `/trades/a`） | ホーム |
| 続けて取引のタブ | `[/, /trades, /trades/a]`（a が出る） | `/trades` |
| 続けて取引のタブをもう一度 | `[/, /trades]` | ホーム |
| `/trades/a` を直接開く（印なし） | `[/, /trades, /trades/a]` | `/trades` |
| `[/, /trades, /trades/a]` で詳細を再読み込み（印あり） | 組み直さず `[/, /trades, /trades/a]` のまま | `/trades` |
| 詳細で説明のシートを開いたまま再読み込み（層 1 段。説明の中で言葉をたどった 2 段なら 2 つ） | 層の段から黙って深さの分だけ戻り、今の位置は `[/, /trades, /trades/a]` の 3 つ目（シートは開かない） | `/trades`（1 回で画面が替わる） |
| ホームの根で戻る | `[/]` | アプリを出る（ブラウザ・OS） |

| ホームで説明のシートを開く | `[/, /（層）]` | シートを閉じる |

- する: どの画面にも URL がある（P6）は変えない。記録するは `/record`、編集は `/trades/{id}/edit`（詳細の比較のシートの ［編集で今の値にする］ は `?values=current` を付けて開き、読み込んだ後に「今の値」を選ぶ。#131）、詳細の次の画面は `/trades/{id}/fields`（すべての欄）・`/trades/{id}/comment`（総評。#131）、振り返りは `/review`、設定の下は `/settings/accounts`（口座）・`/settings/instruments`（銘柄）・`/settings/ai-usage`（AI の利用状況）と `/glossary`（用語集。#133 で決めた。どれも設定のタブの次の画面で、直接開くと下に `/settings` を敷く）
- する: 層の再読み込み（1 段・2 段）と「進む」で層の段に入った例は `back-layers.test.ts` に足す
- する: 上の表の例を `routes.test.ts`（純関数の行き来の規則）に足す。積み重ねの記憶はタブの記憶の中だけ（端末の保存先に書かない）

### 9.8 動き

| 場面 | 動き | 作り |
|---|---|---|
| 次の画面へ・戻る | 右から重なる（240ms）。戻るは逆 | `document.startViewTransition()` + `::view-transition-old / new`。向きは `<html>` のクラス |
| タブの切り替え | 重ねて薄く替える（120ms）。横には動かさない | 同上（クロスフェード） |
| 全画面のシート・下のシート | 下から出る（320ms・`--ease-sheet`）。後ろは暗くなる | `<dialog>` + `@starting-style` と `transition`（`display`・`overlay` を `allow-discrete`） |
| 押したとき | 行・ボタン・タブは 80ms で面を 1 段明るく、ボタンは 0.97 倍 | `:active`。`@media (hover: none)` だけ |
| セグメントの選択 | 選ばれた面が横に滑る（160ms） | 選択の面を 1 つの要素にして `transform`（クラスで） |
| 判定が出た | 下の帯のバッジと R が 1 回だけ 4px 上がって現れる（200ms） | クラスの付け替え |
| 読み取りが終わった（読めた・失敗した。#166） | 2 段目の明細の行の面が 1 回だけアクセントの色に明るくなって戻る（200ms。大きさ・位置は変えない）。キャンセル（利用者が押した）は動かない。シート・段を行き来しても繰り返さない | hook の層が移りを 1 回だけ見てクラスを付け、`animationend`（と時間）で外す |
| 保存の後 | シートが下へ閉じ、ホームの直近の流れに新しい点が入る（300ms） | 点に `view-transition-name`（クラスで付ける） |

- する: 時間と曲線はトークン（`--dur-*`・`--ease`・`--dur-sheet`・`--ease-sheet`）で書き、動きを減らす設定では全部 0（P9）
- する: `startViewTransition` の callback は、Preact が描き終えた（commit した）ときに解ける Promise を返す（Preact には `flushSync` が無い）
- する: iPhone の端からの戻るのスワイプはブラウザが自前で動かすので、`popstate` の `hasUAVisualTransition` が true のときはこちらの動きを飛ばす（二重にしない）。9.7 の 2・3 の `history.go(-k)` の間の `popstate` も動かさない
- する: View Transitions・`@starting-style`（Safari 17.5 以降）が無いブラウザでは、動きなしで同じ結果にする（`startViewTransition` があるときだけ包む。`ui:check` の 1 状態で、無い場合を確かめる）
- しない: 飾りの動き（P9）。振動（`navigator.vibrate`。iPhone で動かない）
- 時間のトークンは `--dur-fast` 120ms・`--dur-base` 200ms・`--dur-sheet` 320ms の 3 つ（9.9）。上の表の 80・160・240・300ms はまだトークンに無い。動きを作るとき（#136）に、トークンを足すか 3 つに寄せるかを決め、ms を直書きしない（P9。5 章の 11）

### 9.9 文字の階層・余白・角丸・面

色は判定の 4 段・藍のアクセント・ダークが既定（P2）。値の正は `ui/src/styles/tokens.css` で、ここは段の役割を書く（値を変えるときはトークンとこの表を同じ PR で直す）。

| 2 | 主役の文・シートの題 | `--fs-lg` | 20px・750 |
| 3 | 帯の題 | `--fs-nav` | 17px・650 |
| 4 | 本文・欄 | `--fs-md` | 16px |

## 10. 操作の作法

9 章が「どこに・どの形で出すか」を決めるのに対して、この章は **触っている最中の振る舞い** を決めます（2026-11-21。#173）。入力とキーボード・知らせ・文字の切り方・使えない欄・読み込み / 空 / 失敗・密度の 6 つ。どれも 2 章の原則から来ていて、節の先頭に出どころを書きます。

きっかけになったオーナーの言葉（2026-11-21）:

> lcの値を入れていたらソフトキーが上がってきて入力欄が隠れてみえない。あと、ソフトキーの上にスティッキーなuiを置くのもその他のuiをはいちする画面が狭くなってきつくない。

> 後、読み取り完了と結果のユーザーフィードバックが弱くない？

> 読み取り結果のところ、文字列技途中で切れていて意味がわからない。

> なしを選んだら、数値ランが薄くなるのは良いねんけど、そこをタップしたらなしのチェックを解除して、数値入力にしてほしい。

この章の規則のうち、今の画面がまだ沿っていないものは 5 章にあります。

### 10.1 入力とキーボード

出どころ: P1（手間の予算）・P8（フォーカスした欄を隠さない）・A5（安全域とキーボードで隠さない）。安全域と viewport の指定は 9.6。

**欄の種類**（端末に合うキーボードを出させる）:

| 欄 | 指定 | 理由 |
|---|---|---|
| 価格・数量・為替・資金（正の数） | `type="text"` + `inputmode="decimal"` | 数字と小数点のキーボード。`type="number"` は使わない（区切りつき・全角の貼り付けを受けられず、端末ごとに値の扱いが割れる。P3 の `parseNum` で受ける） |
| 符号つきの数（損益） | `inputmode="text"` | iPhone の数字のキーボードにはマイナスが無い |
| 整数だけ（限月など） | `inputmode="numeric"` | 小数点の要らない数字のキーボード |
| 文（一言・総評・名前） | 既定（日本語の入力） | — |
| 日時・日付 | `type="datetime-local"`・`type="date"` | 端末の選ぶ UI に任せる（自前のカレンダーを作らない） |

- する: 入力の欄の文字は 16px 以上（iPhone の自動の拡大を避ける。P8）。値の欄は `autocomplete="off"`・`spellcheck="false"`（端末の候補の帯と波線を出さない）
- する: 入力中の値を書き換えない（区切りを入れない・丸めない・全角を半角に直さない。直すのは保存の本文を作るとき。P3）
- する: 既定値と読み取りで埋まる欄は、キーボードを出させない（要約で見せ、直すときだけ取引の欄のシートで開く。P1）

**決定キー**（`enterkeyhint`。キーボードの右下のキーの表示と動き）:

- する: 続けて入れる欄の並びでは、途中の欄は「次へ」（`enterkeyhint="next"`）で次の欄へフォーカスを移し、最後の欄は「完了」（`done`）でフォーカスを外してキーボードを閉じる。記録する画面の 2 段目は LC →（次へ）→ 根拠が崩れる条件 →（完了）→ 閉じる。閉じると下の帯が戻り、タップと [記録する] が押せる
- する: シートの中の続けて入れる欄の並びも同じ（#174）。並びに入れるのは文字・数のキーボードを出す欄だけで、**選ぶ欄（Segment・select・押す形のトグル）と日時の欄は飛ばす**（フォーカスを移すとキーボードが閉じ、「次へ」の意味が崩れる。選ぶ欄は既定値と読み取りで埋まることが多い）。表示していない欄（通貨が同じときの為替など）も並びに入らない。日時の欄の Enter はフォーカスを外すだけ（フォームを送らない）。最後の欄の「完了」もフォーカスを外すだけで保存しない（設定のシートも。保存は ［保存］）

  | シート | 並び（→ は「次へ」、最後が「完了」） |
  |---|---|
  | 取引の欄（記録する・編集） | 銘柄 → 数量 → イン → 決済 →（為替）。オプションは 銘柄 →（足す銘柄の乗数）→ イン → 決済 →（為替） |
  | ほかの欄（任意） | 損益 → 手数料 →（オプションの損失の見込み） |
  | レッグ | 限月 → 行使価格 → 枚数 → イン → 決済 |
  | 2 段目の LC・広げた後の LC | LC →（オプションの損失の見込み）→ 根拠が崩れる条件。広げた後の LC は 1 つだけ（完了） |
  | 設定の口座 | 名前 →（通貨。取引のある口座は文字なので飛ばす）→ 資金 → 許容リスク |
  | 設定の銘柄 | 名前 → 原資産 → 価格の通貨 → 乗数 → 数量の刻み |

  並びは部品が欄の ID の配列で宣言し、純関数 `lib/enter-chain.ts` の `enterChain`（偽 = 表示しない欄を落とす）が途中 / 最後を決め、`enterPropsOf` が `NumberField`・`TextField` の `enterKeyHint`・`onEnter` を返す（次の欄が消えていたら外す）。欄を足すときは並びの配列に足す
- する: 主の流れの決定キーでは保存を送らない（記録する・編集の画面。判定の 1 行を見てから [記録する] を押す）。欄が 1〜2 個の小さな入力（記録する画面の取引の欄の中のその場の口座の追加・設定の銘柄の追加）は、最後の欄の決定キーを主のボタンと同じにしてよい（表示は「完了」）。欄が 3 つ以上のシート（設定の口座の追加・編集、銘柄の編集）は並びにして、最後の欄でも保存を送らない（#174）
- する: 決定キーだけに頼らない。iPhone の数字のキーボードには決定キーが無いので、欄の外を押せば閉じ、次の欄は見える範囲にあって押せること（下の「寄せ」）
- しない: キーボードの上に自前の帯（次へ / 完了のボタン）を足す
- 決定キーとショートカットは別のもの: 決定キーは画面のキーボードの右下のキー（`enterkeyhint`）で、主の流れでは保存を送らない。`⌘ / Ctrl + Enter`（記録する・保存）は外付けのキーボードのショートカットで、広い形だけの決まり（9.5）。ショートカットはまだ無い（5 章の 10・#135）

**日本語の入力**（IME）:

- する: 変換中のキー（`isComposing` が true、または `keyCode` が 229）は操作にしない。変換を確定する Enter で次の欄へ進めない・追加や保存を送らない。Esc も同じ。判定は 1 つの純関数にそろえる（#172 の `isEnterCommit`。今の下のシートの Esc は `isComposing` だけを見ている = 5 章の 5）
- する: 変換中の文字で誤りを出さない（確定してから検査する）

**入力中の欄を見える範囲に入れる**（以下、この動きを「寄せる」と書きます）:

- する: キーボードが出たら、フォーカスした欄が **見える範囲**（キーボードを除いた窓から、貼り付いた上の帯と、残っている下の帯を除いた範囲）に入るように、入るだけ動かす。すでに見えていれば動かさない。中央へ飛ばさない（前後の欄との位置の関係を保つ）
- する: 1 画面に収まっていてスクロールの余地の無い画面（記録する画面の 2 段目）と下のシートの本文は、キーボードが出ている間だけ下に余白を足して動かせるようにし、閉じたら余白を消して元の位置（スクロール 0）に戻す。iPhone の Safari はキーボードで窓が縮まないため
- する: キーボードが出ているかは 1 か所（`visualViewport` を聞く薄い層）で決め、`<html>` の属性の印にして、CSS はその印だけを見る。Android の Chrome（窓が縮む）と iPhone の Safari（窓は縮まず、見える範囲だけが縮む）のどちらでも、利用者から見た振る舞いを同じにする
- する: 利用者が自分でスクロールした後は、位置を取り合わない。動きを減らす設定では、滑らせずに移す
- しない: `.style` で位置を書き換える（P11）。フォーカスした欄を、帯かキーボードの裏に置いたままにする

**貼り付いた帯**（キーボードが出ている間）:

- する: キーボードが出ている間は、**下に貼り付いた帯を貼り付けず、スクロールする本文の最後に置く**（#183）。記録する・編集の下の帯（「あと N 欄」・判定の 1 行・[記録する] / [保存]）と、下のシートの下の帯（[保存]・[追加]・[完了]）。下へスクロールすれば、判定の 1 行と並んだ [記録する] をキーボードを閉じずに押せる。キーボードを閉じたら下の端に貼り付いた帯に戻す
  - 理由: 390×844 の窓でキーボードは 4 割前後を取る。その上に帯（最大 112px）を残すと、上の帯を除いて入力に使える高さは 300px 前後になり、入れている欄の前後が見えない。入力中に見たいのは今の欄とその前後で、保存のボタンではない。一方で帯を隠すだけ（#172）では、キーボードを閉じないと [記録する] に届かなかった（オーナー「ソフトキーを閉じないと「記録する」ボタンが押せなくてめんどくさいやん。スクロールしてもかくていぼたんでてこないし」）
  - する: 本文の最後に置くのは帯と同じ要素で、位置だけを CSS で替える（同じボタンを 2 つ描かない・読み上げにも 1 つ。押せる条件・押せない理由・保存中の文・保存の失敗の知らせは帯のまま）。押したら、フォーカス中の欄を外して入力（変換中の文字）を確定させてから送る（iPhone の Safari はボタンを押してもフォーカスが欄に残るため）
  - 手間は増えない: 最後の欄の「完了」でキーボードが閉じると、下の端の帯に戻る（上の「決定キー」）
- する: 書きかけの案内（「前の入力の続きです」の行。`.draft__resumed`）も、キーボードが出ている間はたたむ。たたんだ後に寄せる量を決める（たたんだ分だけ欄が動くため）。たたむ対象はこの 1 つで、足すときはここに書き足す（送る前の注意・誤りの文・完了の文はたたまない）
- する: 保存の失敗の知らせは帯の中にあるので、キーボードが出ている間は帯と一緒に本文の最後へ移る（消えずに残る。10.2 の「消えない」のまま）
- する: 上の帯（✕・題・進み具合）は残す。やめる道と、今どこにいるかは隠さない
- する: 帯の位置を替えるのは CSS で印を見て行い（`position: static`）、帯の DOM と中の状態（判定・押せない理由）は保つ。キーボードを閉じたときに、その時点の判定が下の端に出ている
- する: 外付けのキーボード・PC（画面にキーボードが出ない）では印が付かないので、帯は出たまま
- しない: 帯をキーボードの上に追わせる。帯の一部（判定の 1 行）だけをキーボードの上に残す（2026-11-21 に方針を替えた。前は「判定の 1 行に畳む」。4.3）。キーボードの間に帯を隠して、送るボタンに届かなくする（2026-11-22。#183）

**作り**（#172）:

- 印は純関数 `lib/keyboard.ts` の `keyboardMode` が決める。文字を入れる欄にフォーカスがあり、拡大していない（`visualViewport.scale` が 1）ときだけ。iPhone の Safari = 窓（layout viewport）の高さと `visualViewport` の高さの差が 120px 以上 → `overlay`。Android の Chrome（resizes-content）= 窓そのものが、キーボードの無いときの高さから 120px 以上縮んだ → `resize`。どちらも、指で触る端末（`pointer: coarse` が主の入力）のときだけ付ける（PC で窓の高さだけを縮めた・下に開発の道具を出したときに帯を消さない）。キーボードの無いときの高さは、同じ幅で欄を編集していない間に測り直す（編集の外で縮んだ窓 = 画面の分割などを基準にする）。120px は、iPhone の入力の補助の帯・アドレスバーの出入り（60px 前後）を数えない下限
- 糊は `lib/keyboard-reveal.ts`（main.tsx が 1 回入れる）。`visualViewport` の resize・scroll・窓の resize・focusin / focusout を rAF で 1 フレーム 1 回にまとめて決め、`<html data-keyboard="overlay|resize">` を付け外しして、同じフレームで（帯を本文の最後へ移した後の形で）寄せる。キーボードが上がる・下がる間（落ち着く間: フォーカスした欄・印が替わってから 1 秒。その間に続けて来る resize で 0.3 秒ずつ延ばす。`visualViewport` の scroll は本人のスクロールでも来るので、見直すだけで延ばさない）は毎フレーム寄せ直し、上がりきった最後の見える高さで欄の下に余白が残るようにする（Android の Chrome はキーボードの動きの後に窓が縮むことがあり、iPhone は `visualViewport` の resize が何回か来る。オーナー「ソフトキーがズルっと上がってきたら、それにあわせて…みえるいちまですくろーる」）。寄せる量は見えていれば 0 なので、見えている欄は動かさない。落ち着いた後は、フォーカスした欄・印・見える高さ（120px 以上）が替わったときだけ寄せる（Android のブラウザのタブでアドレスバーの出入りの resize のたびに本人のスクロールを引き戻さない）。落ち着く間は滑らせずに移す（毎フレーム追うので、キーボードの動きに合わせて動く）
- 寄せる量は `planReveal`（見える範囲 = `visualViewport` の範囲 ∩ スクロールの容器の枠 − 貼り付いた帯。上下 16px の余白）。内側の容器（下のシートの本文）から順に動かし、`<dialog>` の中では文書を動かさない。貼り付いた帯の一覧は `keyboard-reveal.ts` の `COVERS` の 1 か所で、貼り付く帯を足すときはここに書き足す（position が sticky / fixed で高さのあるものだけ数える）
- iPhone の余白は `--kbd-room`（60lvh。`overlay` の間だけ。窓の高さを変数で渡さない = `.style` を使わないので決まった大きさ）
- 帯を本文の最後へ移す CSS は record.css（記録する・編集の下の帯。書きかけの案内はたたむ）と components.css（下のシートの ［保存］ / ［追加］ の帯）。今は形を見ずに下の帯を移す。横の形（`data-form`。#134）を入れるときは、右の列の判定と ［記録する］ を動かさないよう、この規則を縦の形に限る
- 印がある間は、フォームの暗黙の送信（決定キーを渡していない欄の Enter）で保存を送らない。送るのは、本文の最後の送るボタンを指で押し始めて（フォームの pointerdown。スクロールに替わった pointercancel・ボタンの外の pointerup・キーの keydown では忘れる）2 秒以内の送信だけ（`keyboard-reveal.ts` の `notePress`・`takeSubmit` と純関数 `keyboard.ts` の `submitAllowed`。#183）。送る前に、印の間だけフォーカス中の文字の欄を外す（`commitFocusedEntry`。印の無い PC の送信では外さず、誤りで止まったときにフォーカスを欄に残す）。設定の口座・銘柄の編集のシートも同じ門（`notePress`・`takeSubmit`。#174）。銘柄の追加（欄が 1 つ）は門を付けず、欄の Enter で ［追加］ を送る小さな入力のまま（送る前に欄を外すのは同じ）。押すとフォーカスが欄から外れるので、寄せは働かず、キーボードが閉じて帯が下の端に戻る。LC の決定キーは並びの次の欄（オプションの損失の見込みがあればその欄）へ移る

**フォーカスを動かしてよいとき**:

| きっかけ | 行き先 |
|---|---|
| 画面が変わった | 見出し（`h1`。P6） |
| シートを開いた / 閉じた | シートの見出し / 開いたボタン（9.3） |
| 明細を選んで 2 段目へ移った | LC の欄（9.4） |
| 読み取りが終わり、どの欄にもフォーカスが無い | LC の欄（9.4） |

| 消した・破棄した | トーストの [元に戻す]（P4） |

- しない: 入力中の欄からフォーカスを奪う。知らせのためにフォーカスを動かす（10.2）。利用者の操作の外でシートを開く（タイムゾーンの選択は印とボタンで待つ。9.4）
- 覚えておくこと: iPhone では、利用者の操作の外の `focus()` でキーボードは出ない（欄の強調だけになる）。これを前提にしてよい（勝手にキーボードが上がらない）

### 10.2 知らせとフィードバック

出どころ: P13（起きたことは、その場で知らせる）・P4（取り消し）・P9（動きは因果の分だけ）・P1（閉じる手間を足さない）。

**使い分け**（起きたことごとに、出し方は 1 つ）:

| 起きたこと | 出し方 | 場所 | いつ消えるか | 読み上げ |
|---|---|---|---|---|
| 押した | 面の色が 1 段明るくなる・ボタンは少し縮む（9.8） | 押したもの | 指を離したら | — |
| 裏で進んでいる（読み取り中・読み込み中・保存中） | その場の短い文（「読み取り中…」）と骨組み。押したボタンは文字を「保存しています…」に替えて押せなくする | 結果が出る場所・押したボタン | 終わったら結果に替わる | `role="status"`（`aria-busy`） |
| 裏の処理が終わった（読み取りの完了） | その場の **完了の文**（結果を一言で: 「2 行を読み取りました · 入力が必要な欄 1」）と、1 回だけの短い動き | 進行中の文があった同じ場所 | 消えない（次の読み取りを始めるまで） | 同じ `role="status"` の中身を替える |
| 保存できた（画面が替わる） | 画面の移りそのもの（シートが閉じる・保存の後のシート「記録しました」が開く・一覧に行が入る） | — | — | 着いた先の見出し |
| 保存できた（画面が替わらない。設定のシートなど） | その場の 1 行（「〈名前〉 を保存しました。これから記録する取引に反映されます。」） | 保存した行のそば | 次の操作まで | `role="status"` |
| 失敗した（読み取り・読み込み・保存） | その場の文（何が起きたか + 次にすること）と、やり直すボタン（10.5） | 結果が出るはずだった場所・押した帯 | 消えない（やり直すか直るまで） | `role="alert"` |
| 入力の誤り | 欄のすぐ下の文と枠の色（P5）。帯には数だけ（「誤り 1 欄」） | 誤りの欄 | 直したら | `aria-invalid`・`aria-describedby` |
| 判定が出た・変わった | 下の帯の判定の 1 行が 1 回だけ現れ直す（9.8） | 下の帯 | — | 帯の状態の文 |
| 取り消せる操作をした（削除・破棄） | **トースト** + [元に戻す]（8 秒。P4） | 下のタブの上（9.3） | 8 秒。フォーカス・ポインタ・シートが開いている間は止める | `role="status"` |
| 全画面のシートの中で取り除いた（レッグの削除・読み取った明細の削除。#184） | **その場の 1 行** + [元に戻す]（トーストにしない。シートの中ではトーストの時間が止まり、場所も無くならない） | 取り除いた所のすぐそば | 次の操作まで（明細は次の明細を選ぶ・記録する・✕・画面を離れる。その後は画像も捨てる） | `role="status"`（領域は先に描く） |
| 離れた所に残したもの（書きかけ） | トースト + [記録に戻る]、タブの ［＋ 記録］ の印の点、ホームの 1 行（P4） | — | トーストは 8 秒、印と行は書きかけがある間 | `role="status"`・印の「入力の途中あり」 |
| 利用者の判断が要る（明細の時刻のタイムゾーン） | 印（「時刻が未確定」）と 2 番目の重さのボタン。シートは自動で開かない（9.4） | 関わる行 | 選んだら | 印の文字 |
| 言葉の意味を知りたい | 「i」→ 説明のシート（P5・9.3） | 言葉の横 | 閉じるまで | シートの見出し |
| 戻せない操作の前（アカウントの削除） | 確認（P4。ここだけ） | — | — | — |

規則:

- する: **知らせは起きた場所に出す**。結果が流れ込む行・押したボタン・誤りの欄。画面の隅に出して目を動かさせない
- する: **トーストは「場所が無くなった」ことにだけ使う**（消した行・閉じたシートの書きかけ）。中身は取り消しか戻る道の操作 1 つ。完了・失敗・誤りには使わない（消えると手がかりが残らない）
- する: 1 つの出来事に知らせは 1 つ。次の知らせが来たら前のものと入れ替える（完了の文と「次の行（2 / 2）です」を並べない。#166）。次の行の知らせが出ている行で読み直しが失敗して前の明細に戻したら、知らせは消して失敗の `role="alert"` だけにする（キャンセルで戻したら同じ 1 行を「読み取りをキャンセルしました」に替える。#180）
- する: 知らせで配置を動かさない。進行中の 1 行と完了の文は同じ場所・同じ高さに出し、場所は先に取っておく（読み取りの結果が流れ込んでも LC の位置が動かない。9.4）
- する: 結果の知らせは **結果の中身を一言で言う**（「終わりました」ではなく、何行読めたか・手で入れる欄がいくつ残ったか）。確かめてほしい中身（読み取った値）は、知らせではなく要約としてその場に残す
- する: 自動で消える知らせは 8 秒にそろえ、フォーカスかポインタが乗っている間・シートが開いている間は時間を止める（WCAG 2.2.1）
- する: 読み上げは、状態と完了 = `role="status"`、失敗と誤り = `role="alert"`。領域は先に描いて中身だけを替える（描いた瞬間に中身があると読まれない端末がある）。見える文と読み上げの文を二重に流さない
- する: 完了・失敗の知らせに動きを付けるなら、1 回だけ・`--dur-base`（200ms）以下・位置と大きさを変えない。行き来しても繰り返さない。動きを減らす設定では動かさず、文は同じに出す（P9）。この規則は知らせの動きだけのもので、押した手応え・画面の移り・判定が出たときの動きは 9.8 の表に従う
- する: 待ち時間の目安は 3 段（4 章の「応答の時間」）。0.1 秒以内に押した手応え、1 秒を超えるなら進行中の印、10 秒を超えうるもの（明細の読み取り）は待たせずに先へ進めて、キャンセルできるようにする（設計書 C23）
- する: 文は「何が起きたか + 次に何をするか」を言い切る（8 章の基準 ⑥）。進行中の文だけ末尾に「…」を付ける
- しない: 閉じる操作の要る知らせ（操作つきのダイアログ・押すまで消えない帯）を足す。知らせのためにフォーカスを奪う（例外は削除の後の [元に戻す]）
- しない: 知らせに判定の段の色を使う（P2）。失敗は `--danger` と形の印と文で示す
- しない: 振動（`navigator.vibrate`）・音。オーナーが決めた（「振動は要らないよ。」#166）。知らせは画面の表示と読み上げだけ

検査:

- ある: `ui:check` の T-X1・T-X2（確認が出ない・[元に戻す]）、DR1・DR2（書きかけの知らせ）、SH2（シートの間はトーストの時間が止まる）、R5・R9（保存と読み取りの失敗の文言）。`deletions.test.ts`・`drafts.test.ts`。`wording.test.ts`（文の中の [〜] がボタンの名前）
- ある: `ui:check` の RD1（完了の文・キャンセルの文と同じ読み上げの領域・欄を埋めても読み上げ直さない・1 回だけの動き・動きを減らす設定で 0・シートを閉じた後・次の行の知らせ・幅 360 で切れない。#166。次の行の知らせが名前の上の 1 行に 1 つ・同じ領域・スキップ・3 行の 2 行目の後。#180）。`record-screen.test.ts` の `statementStatus`・`readFinished`、`record-view.test.tsx` の読み上げの領域の例
- 目で（6 章の 18）: 新しい処理に、進行中・完了・失敗の 3 つの見え方があるか。同じ知らせが 2 か所に出ていないか

### 10.3 文字の切り方

出どころ: P7（どの幅でも崩れない）・P5（値は見える）・P8（文字を大きくしても読める）。きっかけは、記録する画面の要約が 1 行の高さに固定されて省略され、「100.5 → 99.2 · 11/14 00:10」のように見出しの無い値が並び、途中で切れて意味が分からなかったこと（#164。値は架空）。

入らない文字の収め方は 3 つあり、**何の文字かで決まります**。

| 収め方 | 使う文字 | 作り |
|---|---|---|
| **切らない**（1 行のまま全部出す） | 数字（価格・数量・R・金額・%）と符号・単位、日時、判定の名前、L / S、ボタン・タブ・チップ・セグメントの文字、欄のラベル、印（「読み取り」「時刻が未確定」） | `white-space: nowrap`。入る短さの言葉にする（8 章の基準 ⑤）。入らなければ下の「入らないとき」 |
| **折り返す** | 文（説明・理由・注記・誤りの文・完了の文・失敗の文）、値を並べた要約の行（塊の間で折る）、利用者が書いた文（一言・総評） | 高さを固定しない。塊（「数量 1」「イン 100 → 決済 99.2」）の中では折らず、塊の間で折る。区切りの「·」は後ろの塊の頭に付け、行末に残さない（P3 の数量の行と同じ）。利用者の文は長い英数字でも折れるようにする |
| **省略する**（末尾を「…」） | 下の表の「省略してよい所」だけ | `text-overflow: ellipsis`。全文が 1 タップ先にあること |

省略してよい所（これ以外は省略しない）:

| 文字 | 場所 | 全文のある所 |
|---|---|---|
| 利用者が付けた名前（銘柄・口座） | 一覧の行・ホームの行（2 行目の末尾の口座）・口座の Segment の選択肢（長い名前があるとき。#47 U4）と見出しの右の「選択中: 〈名前〉」 | 詳細・「選択中」の 1 行・設定の口座と銘柄 |
| 利用者が書いた文の写し（一言） | 一覧の行（行の数を決めて切る） | 詳細・総評の画面 |
| 上の帯の題と「‹ 前の画面の名前」 | 上の帯 | 画面の中の題・前の画面 |

- する: 省略する要素の隣の値（L / S・数量・時刻・R）は別の要素にして、縮まないようにする（名前が省略されても、値は全部見える）。縮む順は「名前 → それでも入らなければ並びを組み替える」で、値を先に縮めない
- する: **値には意味の手がかりを付ける**。1 行に見出しの無い値を並べない。見出し（「数量 1」）か形（「イン → 決済」の矢印、R・円・% の単位）で、切り取って見ても何の値かが分かるようにする
- する: 1 行に詰める値は、意味のまとまりで行を分ける（記録する画面の要約は 3 行: 銘柄の名前 / L / S · 数量 · イン → 決済 / 決済の時刻 · 明細の損益。9.4）
- する: **いちばん長い実際の桁で確かめる**。価格は 6 桁 + 小数、名前は限月つきの長い銘柄、口座は長い名前、金額は 7 桁、で幅 360px を見る（値は架空で作る）。検査の見本にもその状態を入れる
- する: 文字を大きくしたとき（200%）は、省略で逃げずに折り返して縦に伸ばす（P8・9.4）
- する: 切らない文字に、はみ出して重なるのを防ぐ保険として省略の指定を置いてよいのは、下の帯の状態の文（`.record__status`）と Google でログインするボタンの文字（`.gsi__text`。ブランドの決まった形）の 2 つだけ。どちらも検査の幅（360px 以上・等倍の文字）で実際に省略が起きたら外れとして直す（帯の状態の文の切れは `ui:check` が測る）
- しない: 高さを固定して `overflow: hidden` で切る（1 画面の約束を、切って守らない。10.6）。省略した全文を `title` 属性だけに置く（指では出ない）。数字・単位・判定・日時を「…」で切る。数と単位・符号の間で折る（`AmountText` の塊にする。P3）

入らないとき（切らない文字が幅に入らない）は、この順に直す:

1. 言葉を短くする（8 章の表を直す。意味が変わらない範囲で）
2. 塊の間で折り返せる並びにする（1 行 → 2 行）
3. 列の幅のコンテナクエリで並びを組み替える（横並び → 縦積み。9.5）
4. 補助の情報を次の画面かシートへ送る（10.6）

検査:

- ある: `ui:check` の「部品のはみ出し」（折り返さない部品の中の文字が箱を超える・N 行に折れる）、文字の拡大の「切れ」（文字が切る祖先の外に出る。「…」で省く作りは除く）、SZ1（数量の行が塊の中で折れない）、下の帯の状態の文の切れ
- ある（#176）: 上の表に無い要素の省略（`text-overflow: ellipsis`・`line-clamp`）が 0 件であることの CSS のテスト（`tests/ui/truncation-rules.test.ts`。表は `ALLOWED`、別の Issue に分けて残す外れは `KNOWN`（#212 で記録する・編集の 5 つを直して今は空）で、直して省略が無くなると落ちて消すことを知らせる）。いちばん長い値の状態の `ui:check` の LV1（360×780 のダークの一覧・ホーム・詳細で、省略してよい所の外の要素に実際に「…」が出た件数 0・判定の名前・日時・時間足の要素が切れない）と LV2（#212。360×780・390×844 のダークの記録する画面の 2 段目・1 段目と編集の画面（オプションの欄の名前も）で、同じ「…」0・値の切れ 0・時間足と「追加 N 枚」の塊が 1 行・横スクロール 0px・2 段目と 1 段目の縦は R12 と同じ上限。文字の拡大 2 倍でも「…」0・値の切れ 0・横スクロール 0px）

### 10.4 使えない欄・押せないボタン

出どころ: P1（探させない）・P5（理由は見える）・P8（読み上げでも分かる）。きっかけは、LC の ［なし］ で薄くなった価格の欄を押しても何も起きず、［なし］ をもう一度押す必要があったこと（#171）。

使えない理由で、形が決まります。

| 理由 | 形 | 戻し方 |
|---|---|---|
| 1. **自分の選択で要らなくなった欄**（LC の ［なし］・［最大損失まで］ など、隣の選択が値を不要にした） | `disabled` にしない。薄い形（面を薄く・枠を点線に・placeholder に理由「なし」）のまま、押せる・フォーカスできる | 欄を押す・Enter / Space・数字を打ち始める、で選択が外れてそのまま入力できる（1 タップ）。選択のボタンをもう一度押しても外れる |
| 2. **条件がそろっていない主のボタン**（[記録する]・[保存]） | 押せない形にしてよい。ただし **理由を必ずその場に出す**（帯に数か一言、欄の名前は判定のシート。`aria-describedby` で結ぶ。P1） | 理由の欄を埋める。理由の表示から、その欄へ行ける（要約のチップを押すとその欄でシートが開く。9.4） |
| 3. **処理中**（保存中・追加中・読み込み中） | 押したボタンの文字を「保存しています…」に替えて押せなくする（二度押しを防ぐ）。欄は処理の間だけ止めてよい | 終われば戻る。押したボタンは消さず、フォーカスを落とさない |
| 4. **上限に達した**（チャートの枚数・レッグの本数） | 押せない形 + 隣に理由の文（`aria-describedby`） | 1 つ減らす |
| 5. **この取引・この口座では変えられない**（直せない取引・通貨を変えられない口座） | 欄を並べずに、値を文で見せて理由を 1 行添える | — |
| 6. **その人には関係が無い**（口座が 1 つの人の口座の欄） | 出さない（P1） | — |

- する: 1 の形で選択が外れるのは、利用者の操作（押す・キーを打つ）のときだけ。フォーカスが通っただけ（Tab・プログラムの `focus()`・読み上げの移動）では外さない
- する: 1 の形でも文字は読める濃さにする（placeholder・値は `--ink-3` 以上。押せる部品なので、コントラストの対象。4.2）。薄さは面と枠で示し、色だけに頼らない
- する: 条件しだいで使えるようになるものは、場所を保って薄くする（出したり消したりして配置を跳ねさせない）。絶対に使えないものだけ出さない
- する: 押せない形には、見える理由を 1 つ付ける。理由の文が長いときは短い一言 + シート（P1 の帯の規則）
- しない: 理由の無い `disabled`。`disabled` の欄を並べて「見せるだけ」に使う（文で見せる）。押せない理由を色の薄さだけで示す

検査:

- #171 で入る: LC の欄の例（押す・打つで外れる・フォーカスだけでは外れない）
- ある: `record-view.test.tsx`（帯には数、名前は判定の枠）、`ui:check` の R3（二度押し）
- まだ（5 章の 7・#213）: 画面のソースの `disabled` のうち、理由（`aria-describedby` か処理中の文字）と結ばれていないものが 0 件であることのテスト
- 目で（6 章の 22）: 押せない形に見える理由があるか

### 10.5 読み込み・空・失敗

出どころ: P13（黙って済ませない）・P11（失敗の中身を出さない）・A1（タブの根は 1 画面）。

データを読む画面と部品は、**4 つの状態**（読み込み中・空・失敗・中身）を必ず持ちます。新しい画面を作るときは、4 つの見え方を先に決めます。

読み込み中:

- する: 中身の高さを先に取った骨組みと、文を 1 つ（「読み込んでいます…」。`aria-busy` と `role="status"`）。読み終えたときに配置が跳ねない
- する: 前の中身があるなら、消さずに薄く残して裏で読む（振り返りの期間の切り替え・戻ってきた一覧。白紙に戻さない）
- する: 続きの読み込みは、押したボタンを同じ場所に残して文字だけ替える（フォーカスを保つ。10.4 の 3）
- する: 状態の文は「〜しています…」の形にそろえる（読み込んでいます…・保存しています…・追加しています…）。幅の無い所（ボタンの中・骨組みの 1 行）だけ短い形（読み取り中…）
- しない: 回る印だけで文が無い。全画面を覆う読み込み（部分が読めるなら部分から見せる）

空:

- する: 何が無いかと、次にすることを 1〜2 文で言う。初めての空（取引 0 件）と、絞った結果の空（この期間に取引が無い）を分け、後者は条件を変える道を示す
- する: 記録を促すときは、いつも同じ場所にある ［＋ 記録］ を指す一言にする（空の画面に別の [記録する] を置かない。A2・9.4）
- する: 空でも画面の骨格（題・期間の選択）は同じ場所に出す
- しない: 空を誤りのように見せる（`--danger`・警告の印）

失敗:

- する: 起きた場所に、決まった文（何が起きたか + 次にすること）と、やり直す道を 1 つ（読み込みは [再読み込み]。2 番目の重さ。8.1。書き込みは押した同じボタン）。`role="alert"`
- する: 失敗の種類で道を分ける

| 種類 | 今の文と道（文言の正はコードの定数。変えるときは 8 章の表と一緒に） |
|---|---|
| 読み込めなかった（通信・サーバーの誤り） | 「〈何〉を読み込めませんでした。通信状況を確認して、再読み込みしてください。」（取引・振り返り・設定）+ [再読み込み] |
| 続きを読み込めなかった | 「続きを読み込めませんでした。通信状況を確認してください。」。一覧は残し、末尾の同じボタンが [再読み込み] になる |
| 保存・追加を送れなかった | 「通信できませんでした。入力内容は残っています。もう一度 [記録する] を押してください（二重には保存されません）。」（[保存]・[追加] も同じ形）。やり直しは同じボタン |
| ログインが切れた | [もう一度ログイン]（8.1）。書きかけは残す |
| 使えないアカウント（403） | 専用の画面（`pages/Forbidden.tsx`）。「別のアカウントでもう一度ログインしてください。」と ［別のアカウントでログイン］ |
| 見つからない（消した取引の URL） | 「この取引は見つかりません」と、上の帯の「‹ 取引」（P6） |
| AI の上限・読み取りの失敗 | 決まった文言（「読み取れませんでした。もう一度貼り付けるか、手入力してください。」など）と、手入力で続ける道（9.4。読み取りが無くても記録できる） |

- する: 失敗は部分にとどめる。一部が読めなくても、読めた部分は使える（AI の利用状況が読めなくても口座は保存できる・続きの読み込みが失敗しても一覧は残る）
- する: 書き込みの失敗では入力を消さない。同じボタンでもう一度送れる。二重には送らない
- する: 通信が無いときも同じ形（通信の失敗）で出す。オフラインの専用の画面は作らない（サービスワーカーを置かない。ADR-0018）
- しない: 白い画面。コード・例外の本文・内部の識別子を出す（P11）。失敗をトーストだけで知らせる（10.2）

検査:

- ある: `ui:check` の状態（読み取り中・読み取りの失敗・保存の失敗 R5・続きの読み込みの失敗 TL-P3・資金が未設定・取引 0 件のホーム・使えないアカウント F1 / F2・ログインの門 L1〜L7）、`wording.test.ts`（使わない言葉）
- ある: 読み込み中の文は「読み込んでいます…」1 つ（`wording.test.ts`。#177）
- 目で（6 章の 20）: 新しい画面・部品に 4 つの状態があり、`ui:check` の状態に入っているか

### 10.6 密度と 1 画面の約束

出どころ: A1（タブの根は 1 画面）・P1（開いた直後にやることが全部入る）と、P7・P8（読める・押せる）の折り合い。

1 画面に収める約束と、読みやすさ・押しやすさがぶつかったときは、**上のものを先に守ります**。

1. **読める・押せる**: 文字の大きさのトークン（いちばん小さい段は 12px。それより小さい文字を作らない）、当たり 44px、コントラスト、意味を運ぶ文字を切らない（10.3）
2. **入力の流れが途切れない**: 手で打つ欄・タップ・主のボタンが、等倍の文字の 390×844 でスクロールなしに届く（9.4）
3. **1 画面に収まる**: 等倍の文字の目標（9.4・9.10）
4. **余白のゆとり**

約束が及ぶ範囲:

| 画面 | 約束 |
|---|---|
| ホーム・記録する画面の 1 段目と 2 段目 | 等倍の文字の 390×844（安全域 上 47・下 34 を入れても）で縦のスクロール 0px。360×780 は、ホームは行を隠して 0px、記録する画面は 120px 以下（9.4・9.10） |
| ほかのタブの根（取引・振り返り・設定） | 開いた 1 画面で要点が読める。続きはスクロールしてよい（一覧は月の見出しが上に残る） |
| 次の画面・下のシートの中 | スクロールしてよい（シートは最大 86dvh で中がスクロール。9.3） |
| 文字を大きくしたとき | 縦に伸びてよい。横スクロールは 0px のまま（9.4） |
| キーボードが出ている間 | 約束の外（見える範囲が半分になる。10.1 の寄せで動かす） |

1 画面に入らなくなったら、この順に試します:

1. **送る**: 補足・任意の欄・説明・内訳を、次の画面かシートへ（9.3）。その場に残すのは、その画面で決めること・押すことだけ
2. **隠す順を決める**: 入らない高さでは、下の行から隠す（ホームの直近の取引は 3 件目から。9.4）。隠した中身には 1 タップで届くこと
3. **重ねて言わない**: 同じことを 2 か所で言っている行を 1 つにする（帯が「明細を読み取っています」と言うなら、枠の中は短く。P5）
4. **余白を詰める**: 段の間の余白を、余白のトークンの 1 つ下の段まで。当たり・文字の行の高さ・カードの内側の余白は詰めない
5. それでも入らなければ、**スクロールを許す**（上の優先の 1・2 を崩すより、伸ばす）

- する: 1 画面の画面に行を足す PR は、何を送る・隠す・詰めるかを同じ PR で決める（手間の予算と同じ「引き換え」。P1）
- する: 余白・文字・角丸はトークンの段だけを使う（P12）。画面ごとの半端な値で詰めない
- する: 1 枚のカードの主役は 1 つ（数字か文）。同じ重さの行を 5 つ以上並べるなら、まとめた一覧（9.9）にする
- する: 送る前の注意（設計書 C38）は畳まない。密度のために同意の代わりの文を隠さない（9.4）
- しない: 入れるために文字を小さくする・当たりを 44px 未満にする・文字を省略で切る・高さを固定して切る。カードの中に説明の文を常に出す（補足は「i」へ。9.9）

検査:

- ある: `ui:check` の R12 と「1 画面に収まる」（390×844 のホームと記録する画面の 1 段目・2 段目の 4 つの状態で縦のスクロール 0px。安全域の差し替えも）、下の帯の高さ（112px まで）、枠の入れ子 3 段以上 0 件、当たり < 44 が 0 件、文字の大きさのトークンの段（`cssTokens.test.ts`）
- 目で（6 章の 21）: 行を足したとき、何と引き換えたかが PR に書いてあるか
