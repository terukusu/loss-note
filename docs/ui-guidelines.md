# 画面の原則（UI / UX ガイドライン）

loss-note の画面が沿う原則と規則、そのよりどころにした世の中のベストプラクティス、画面を触る PR のチェックリスト。

> Issue #3（画面のデザインの土台）で作成（2026-11-17）。option-simulator の `docs/ui-guidelines.md` の構成を移植し、原則を loss-note 向けに作り直した。価格・損益の例はすべて架空。

---

## 1. はじめに

**目的**: 画面を足す・直すときに「このアプリではこうする」を 1 か所で引けるようにする。

**読む人**: 画面を触る開発者、実装・レビューをする AI のエージェント、PR をレビューする人。初めて読む人向けに書く。

**ほかの文書との関係**:

| 文書 | 役割 |
|---|---|
| このガイドライン | **原則と規則**（なぜ・こうする / こうしない・何で確かめるか）。画面の中身が変わっても変わりにくいもの |
| `docs/design.md` | **設計書**（考え方・記録の形・判定・画面の一覧）。規則の出どころとして節番号で参照する（9.1 からこの文書へリンクしている） |
| `CLAUDE.md` | リポジトリの作りと確認の手順 |

食い違ったら、このガイドラインを直すか設計書を直すかを PR で決める（黙ってどちらかに合わせない）。

**このアプリの前提**: 裁量トレードの損失ノート。トレーダーが決済の後に 1 回、スマホで素早く記録し（設計書 7.5）、PC で広く振り返る（設計書 9.1）。物差しは「勝ったか」ではなく「計画どおりだったか」（設計書 1.1）。動機は「入力が面倒で記録が続かない」（設計書 K10）なので、**記録の手間を減らすことと、開きたくなる見た目は、機能と同じ重さ** で扱う（設計書 K2）。

## 3. 原則ごとの規則

各行は「こうする / こうしない」とアプリの中の実例。**検査** は機械で確かめているもの（`npm test` の vitest、`npm run ui:check`）。検査の無い規則は目で確かめる（6 章）。

### P1 記録の手間の予算

- する: 記録の画面は「スクショを貼る → LC と一言 → 3 つのタップ」の順に縦に並べ、主の動作（[記録する]）は 1 つ。スマホでは画面の下半分（親指の届く所）に押すものを寄せる
- する: 入力の既定値を置き、手で打つ欄を増やさない（設計書 C17・C19）。2〜3 択は `Segment`（タップ 1 回）で、プルダウンにしない
- する: 4 択以上（決済の理由など）は 1 行の `select`（`.select`。当たり 44px・文字 16px）。任意の欄は `<details>`（「ほかの欄（任意）」）に畳み、主の流れを短くする
- する: 主の動作（[記録する]）は幅 720px 未満で下部の行き先の上に貼り付け（sticky）、帯は 1 段（1 行の状態の文 + [記録する]）で幅 360px で 64px 以下にする（入力中の欄を隠さない。#33）。幅 720px 未満は幅いっぱい・不透明で下部の行き先に付け、下の文字を透かさない。状態の文は 360px で切れない短さにする（長い知らせは判定の枠の案内に全文で）。保存の失敗の知らせ（[ログインし直す] を含む）が出ている間だけ伸びてよい。保存の後のボタン 1 つは帯に包まない
- する: 押せない理由は、帯には数（「あと 7 欄」「誤り 1 欄」）か一言（「明細を読み取っています」）だけ、欄の名前は判定の枠の案内に文で出し、[記録する] の読み上げの説明（`aria-describedby`）に結ぶ（色だけに頼らない）。そろったら帯に判定の要約を文字だけで出す（バッジ・色を使わない）
- する: 判定の枠は 3 つのタップ（見出し「決済までの振る舞い」）の枠のすぐ後に置き、タップの後に判定が出ていれば判定のバッジと R の行を見える範囲へ寄せる（`scrollIntoView` の `nearest`。見えていれば動かさない。押したタップを上へ隠さない。動きを減らす設定では動きを付けない。フォーカスは動かさない）
- する: 開いた直後の 1 画面に [スクショを選ぶ] と銘柄の欄が入るようにする（画面の説明文を付けない。送る前の注意は 3 つの中身を畳まずに 3 行以下、補足は「i」の吹き出しに置く（#57）。PC だけの貼り付けの案内は指で触る端末では出さない）
- する: 行き先（ホーム・記録する・一覧・設定）は幅 720px 未満で画面の下に固定し、どの画面からも 1 タップ
- しない: 記録の途中に確認・説明のダイアログを挟む。任意の欄を必須にする
- 検査: `ui:check` の V6（幅 360 の全画面から 4 つの行き先へ 1 タップ）、記録する画面の R1〜R10（R10 = 明細を貼って打つ 2・選ぶ 3 で判定まで）、帯の高さと状態の文の行数・切れ（幅 360 の全状態。`--inject-clip` の帯の見本で見逃さないことを確かめられる）、R11（判定が見える範囲の外で最後のタップを座標で押す → アプリが寄せ、判定のバッジと R が見える）・R12（開いた直後の 1 画面・注意 3 行以下・全長 2,550px 以下。口座が 2 つ以上の形は口座の欄の分だけ 2,646px 以下。#47）、ACC1・ACC2（口座の Segment の 1 タップ・その場で足す）。`record-view.test.tsx`「帯には数、名前は判定の枠」。30 秒の人の実測は [`record-timing-check.md`](record-timing-check.md)

### P2 色は規律を表す

- する: 判定の段のトークンは `--tier-{plan,break,worst,neutral}-{ink,bg,line}`。段と判定の対応は `ui/src/lib/badge.ts` の 1 か所（A・計画どおりの勝ち = 計画どおり、B・危ない勝ち = 崩れ、C = 極悪、判定なし = 中立）
- する: 強調の色（`--accent`）は操作（主のボタン・今いる画面・フォーカス）にだけ使い、判定の段の色と混ぜない
- しない: 損益・R の正負で文字や面の色を変える。判定の段の色を判定以外（入力の誤りなど）に使う（入力の誤りは `--danger`）
- する: 判定の枠の LC の物差し（#34。`components/Ruler.tsx`）は色を足さない。線・点・文字は文字と線のトークン（`--ink*`・`--line*`）だけで、点の種類（イン・決めた LC・広げた後の LC・決済・TP）は形で見分ける（判定の段の色も使わない。窓・滑りの A で越えた区間が「計画どおり」の色にならないように）
- する: ホームの規律の振り返り（#88。`components/ReviewSummary.tsx`・`DisciplineCurve.tsx`、CSS は `styles/review.css`）は判定の段の色と文字・線のトークンだけ。判定の内訳の帯は段の色（`--tier-*-ink`）の区切り、規律コストの曲線は 実際 = 文字の色（`--ink`）の実線・計画どおりだったら = 計画どおりの段（`--tier-plan-ink`）の破線・差の面 = 崩れの段（`--tier-break-ink` を薄く）+ `--tier-break-ink` の 45 度の斜線（色だけに頼らない）・崩れた取引（計画どおりの R に置き換えた取引）の点 = 判定のバッジと同じ形（△・×）の段の色の線。右端の「計画」「実際」の札と差の括弧・目盛りは文字と線の色。R・% の数字は無色。面の色・内枠を足さない
- 検査: `badge.test.ts`、`cssTokens.test.ts`「段の色が互いに違う」「バッジの段のクラスは段のトークンだけ」「物差しの CSS は文字・線・段のトークンだけ」「振り返りの段の CSS は判定の段・文字・線のトークンだけ」

### P3 数字は符号と単位で読ませる

- する: R は小数 1 桁 + `R`、円は 1 円単位で 3 桁区切り + `円`。丸めは 0 から遠い側（四捨五入）。負の符号は `−`（U+2212）、ちょうど 0 は `±`、丸めて 0 になっても元の符号を残す（`−0.0R`。設計書 C29）
- する: 表示は `ui/src/lib/format.ts` の `formatR` / `formatYen` だけを通す（`RNum` / `YenNum` の部品）。本文の書体の桁の揃う数字（`tabular-nums`。等幅の書体にしない）で、大きさは `num--lg`（22px）/ `num--xl`（36px）。数値の入力欄も同じ。等幅（`--mono`）は ID・コードだけ（`.mono`）
- する: 資金のような符号の無い金額（損益ではないもの）は `formatAmountYen`（`1,000,000円`。+ を付けない）で出す（Issue #5）
- する: 価格・数量・乗数・数量の刻み・レートの表示は `formatPrice` / `formatQuantity` / `formatNumber` で、整数部だけ 3 桁区切り（`38,250`・`10,000`）。保存した数のまま丸めない（FX の `1.08345` はそのまま。小数部は区切らない）。負の符号は `−`（U+2212）。入力の欄の値には区切りを入れない（入力中もフォーカスが外れても書き換えない。既定値・流し込みは `formatPlain`）。区切りつき・全角の貼り付けは `parseNum` が受ける（正しい 3 桁区切りだけ）（#40）
- する: 金額は取引・口座の通貨で出す（`formatMoney`・`formatAmount`。#47 PR-2）。円は今のまま（`−8,000円`・`1,000,000円`）、ほかの通貨は「数 + 半角の空き + 3 文字」で小数 2 桁（`−50.00 USD`・`10,000.00 USD`）。記号（$・€）は使わない。判定の枠の大きな数字では、数は `.num`、単位（円・通貨の 3 文字）は `.num` の外で小さく（`.num-unit`）。レートの式も金額と同じ書き方（`1 USD = 150円`・`1 EUR = 1.1 USD`）。文の中の金額は数と単位を 1 つの塊（`AmountText`）にして行の境目で離さない。通貨の違う金額を足さない・円に直した値を並べない。価格（イン・LC・決済）には単位を付けない
- する: 判定の枠の R・リスク・損益はラベルの上端を揃える。値が出ないときは場所に「—」を出し、理由は数の段の下の注記に 1 回だけ（一覧と同じ形「リスクの「—」: 損益を入力すると表示されます」。価格の通貨が口座の通貨と違う取引は「為替か損益を入力すると表示されます」で、損益の場所も「—」。#47 PR-2）。LC が無い取引は R・リスクの段を出さず「LC が無いので R・リスクは表示されません」の 1 行にする。ホーム・一覧の「—」の理由は一覧の下の脚注に 1 回だけ
- する: 判定の枠の数量と提案の数量（#67）は数の段のすぐ下（口座の 1 行の前）に注記と同じ無色の 1 行（`verdict__aside`）で出す。色・「大きすぎ」の言葉・新しい色のトークンを足さない（判定の定義を増やさない）。文は「数量 10,000 · 提案の数量 4,000（2.5 倍）」の形で、実際の数量と提案の数量を並べ、比は括弧に下げる（リスク（%）と同じ数を主役に重ねない）。区切り（「数量 10,000」「· 提案の数量 4,000（2.5 倍）」。「·」は後ろの区切りの頭に付け、行末に残さない。#58）の中では折らず、幅 360px で足りなければ区切りの間で折る（`ui:check` の SZ1 が確かめる）。画面の言葉は「数量」「提案の数量」「許容リスク」（「サイジング」「提案」だけ・「許容」だけ・「刻み」を文に書かない）
- 言葉: **提案の数量** = 記録したときの資金・許容リスクと LC から出した、その LC で入れた最大の数量（数量の刻みに切り捨て。刻み 1 つでも許容リスクを超えるときは「最小の数量でも許容リスクを超えます」）
- しない: 数字の部品（`.num`）に色を付ける。ハイフン（-）を負の符号に使う。R・円以外の番号に `.num` を使う（ID・コードは `.mono`）
- しない: `.num` を色のある親の中に置く（`.num` は色を宣言せず親の文字の色を継ぐので、判定のバッジ（`.badge`）・誤りの文（`.field__error`）の中に置くと段の色・誤りの色が付いてしまう）。バッジ・誤りの文と並べるときは、数字をその外に出す
- 検査: `format.test.ts`、`cssTokens.test.ts`「数字の部品は色を持たない」「本文の書体の桁揃え」、`ui:check` の R13（大きな R の計算後の大きさ 36px・等幅でない・ラベルの上端の差 1px 以内）

### P4 取り消せるなら確認しない

- する: 消すは即実行 + トーストの [元に戻す]（部品 `components/Toast.tsx`・`lib/deletions.ts`。#9。アプリの殻に 1 つで、画面を移っても取り消せる。取り消しの時間は 8 秒、トーストにフォーカス・ポインタがある間は止める。[消す] の後は [元に戻す] にフォーカス。トーストにはどの取引かを出す。ADR-0007）。直すは保存の前に判定の変化を見せる明示の保存で受ける（直した後の [元に戻す] は別 Issue）。戻せない操作（アカウントの削除）だけ確認する
- する: 誘惑ガード（保有中に LC を広げる・時間足を長くする。設計書 7.1）は、意図して 1 手を足す唯一の場所

### P5 値と警告は見える、色だけに頼らない

- する: 図（振り返りの判定の内訳の帯・規律コストの曲線。#88）は `aria-hidden` にし、同じ中身を文字（凡例の `ul`・数字の段の文・既定で畳んだ「数で見る」の表 `table`）で読ませる。線は形（実線 / 破線 / 斜線の面）で見分け、凡例を添える（差が無い期間は凡例の「差」を外し「崩れなし」の 1 行）。並びは 期間 → 一言の見出し（1 行目 = 主役の「崩れで −0.6R」を `num--xl` + 状態の記号 ○ △ ×、2 行目 =「守っていれば +0.9R · 実際 +0.3R」）→ 曲線 → 計画どおり率と内訳 →「数で見る」で、曲線は 360px で 180px・720px 以上で 250px の高さ。目盛りはきりのよい刻み（0.5・1・2・5 × 10^k の R、3〜5 本）、右端に今の値の札、横軸は「取引の順」（両端だけ日付）。日付は 1 つの規則（今年は「11/13」、ほかの年は「2025/11/13」。`format.ts` の `formatDay`）。率は `num--lg`（見出しより小さく）で、100% をそろったときだけ・0% を 0 件のときだけ出す。率が出ないときは数の場所に「件数が少ない」と、あと何件で出るか。期間の切り替えの途中は前の図を薄く残し（aria-busy）、最初の読み込みは中身の高さを取る。件数が多い（1 件あたり 8px 未満）ときは計画の線を細い実線に、崩れの印を横軸の上の帯に。図は依存を足さず SVG を手で組む（座標は純関数 `lib/review-chart.ts`。面は viewBox を幅に伸ばし、線は `non-scaling-stroke`、目盛りの文字は伸ばさない別の SVG に百分率の y で置く = style 属性を使わない）。計画どおり率・規律コストの横に「i」（用語集の言葉）

## 8. 用語集（画面の言葉）

画面の文字と読み上げの名前で使う言葉の決まり（#74。オーナーの「一般的な文言になっていないところが多い」「相場用語を統一したい」から）。

- 基準: ① 一般的なアプリ（iOS・Android・Google・Notion など）の標準の操作の言葉 ② 同じものは画面をまたいで同じ言葉 ③ 相場の言葉は言い換えない ④ 開発中にできた造語を出さない ⑤ 短く、360px で折れない ⑥ 誤り・注意の文は何が起きたかと次に何をするかを言い切る
- 表のバッククォートで囲んだ言葉はテスト（`tests/ui/wording.test.ts`）が読む。「使わない言葉」は画面の文字列（`ui/src` の文字列・JSX の文字・テンプレートの文字。開発用の部品の見本とコメントを除く）に 1 つも出ない。言葉を足す・変えるときは、表と画面を同じ PR で直す
- 利用者が引くアプリの中の用語集（「i」の吹き出しと用語集の画面。`ui/src/lib/glossary.ts`）の見出しも、この章の言葉にそろえる（8.3）

### 8.1 操作の言葉

| 使う言葉 | 使わない言葉 | 使い分け |
|---|---|---|
| `キャンセル` | `やめる` | 入力・読み取りを取りやめるボタン。読み上げの名前は何を取りやめるかを足す（`明細の読み取りをキャンセル`） |
| `破棄しました`・`残っています` | `捨てました`・`捨て` | 記録する・編集の書きかけを [キャンセル] で取りやめた知らせ（`記録の入力を破棄しました` + [元に戻す]）と、画面を移っても残している知らせ（`記録の入力は残っています` + [記録に戻る] / [編集に戻る]。#75） |
| `追加`・`追加しています…`・`追加しました`・`追加できませんでした` | `足す`・`足し`・`足せ`・`足さ` | ボタンは名詞の「追加」、見出し・リンクは「口座を追加」「銘柄を追加」 |
| `削除`・`削除しました`・`削除できませんでした` | `消す`・`消し`・`消せ`・`消さ`・`外す`・`外し` | 取引・チャートを取り除く操作。取引の削除は即実行 + [元に戻す]（P4） |
| `保存` | `[保存する]` | 編集・設定の保存のボタン（[〜] の形の言葉は、ボタンの文字と文の中の [〜] を指す。「保存すると」のような文は使ってよい）。新しく記録する主ボタンは `記録する`（8.4） |
| `変更` | `選び直` | 選んだもの（口座・時間足・チャート）を替える |
| `再読み込み` | `もう一度読み込`・`読み込み直` | 読み込みに失敗したときのボタンと案内（「再読み込みしてください」） |
| `もう一度ログイン` | `ログインし直` | ログインが切れたときのボタンと案内 |
| `再計算` | `計算し直`・`し直` | 「し直す」の形は使わない（`もう一度記録してください` のように言う） |
| `スキップ` | `飛ばす`・`飛ばし` | 明細の行を記録せずに次へ |
| `入力`・`入力してください`・`手入力` | `入れてください`・`手で入れ`・`手で` | 誤りの文は「〜を入力してください」。数は「数値」 |
| `貼り付け`・`貼り付ける` | `貼る`・`貼れ`・`貼っ`・`貼ると` | 画像の貼り付け。行き先は `この欄` |
| `確認` | `確かめ` | 「通信状況を確認して」「確認してから」 |
| `通信できませんでした` | `つながりません`・`つながら` | 通信の失敗。結果を言い切る |
| `反映されます` | `効きます`・`に効く` | 設定の保存の結果。言葉の説明は「判定に関わる言葉」 |
| `表示されます`・`表示されません`・`表示なし` | `出ます`・`出ません`・`出なく` | 判定・R・リスクが表示されるかどうか |
| `通知` | `知らせ` | トーストを閉じるボタンの読み上げの名前（`通知を閉じる`） |
| `修正済み` | `直した` | 読み取った値を利用者が書き換えた欄の印 |
| `タイムゾーン` | `時間帯` | 明細の時刻のタイムゾーン |
| `初期値`・`初期値のまま` | `既定`・`仮の値` | 銘柄・許容リスクの初期の値。名前だけで自動で追加した銘柄の印は `初期値のまま` |
| `未入力の欄` | `足りない欄`・`そろえ` | 判定に要る欄が空のとき |
| `指定なし` | `選ばない`・`選んでいない` | 時間足の選択肢と表示 |
| `この欄` | `枠` | チャートの貼り付けの行き先 |
| `保存されます`・`保存します` | `記憶します`・`写して`・`写す` | 端末の設定・取引に記録した時点の値 |
| `取引の形態` | `商品の形` | 銘柄の現物・CFD / 先物 / オプション |
| `入力元` | `出どころ` | 記録の入力元（手入力・明細） |
| `超えて` | `越えて` | 決めた LC を超えて決済した幅（数量・線を超える意味の標準の字） |
| `判定していません` | `見ていない` | 判定の枠の注記。です・ます調にそろえる（「〜のため、過剰リスクは判定していません」） |

「直す」は誤りを正す意味（「誤りのある欄を直す」「直してから、もう一度押してください」「違うときは時刻の欄を直してください」）でだけ使い、編集の意味では使わない（PR #73）。

テストで分けられないもの: 「直す」（編集の意味か誤りを正す意味か）と「変える」（「変更」にする操作か、「名前を変えると」のような文か）は意味で分かれるので、レビューで見る。JSX の式をはさんで割れた文（`「{PROVISIONAL_MARK}」は…`）は、割れた片ごとに検査する。

### 8.2 相場の用語

1 つのものに 1 つの言葉。相場の言葉そのものは言い換えない。

| 指すもの | 画面の言葉 | 使わない言葉 | 使い分けの規則 |
|---|---|---|---|
| ポジションを持ったときの価格 | `イン` | `建値`・`エントリー価格` | 欄の名前・表示・誤りの文は「イン」 |
| ポジションを持った時点・場面 | `エントリー`・`エントリーの時刻`・`エントリー時`・`入る` | `建てた`・`建てが`・`建てご`・`建ての`・`入った後` | 名詞は「エントリー」、問いの動詞は「入る」（`LC を入る前に決めていたか`）。「〜建て」（USD 建て）は通貨建ての意味の別の言葉なので使ってよい |
| ポジションを閉じた価格・時点 | `決済`・`決済の時刻`・`決済日時`・`決済時` | `決済の価格`・`エグジット`・`手仕舞い` | 価格の欄は「決済」。一覧の列の見出しは中身が日時なので「決済日時」 |

### 8.3 内部の呼び名と画面の言い方

設計書・コードは内部の呼び名のまま使う。画面に出すときは、識別子が引く画面の言い方にする（テストが識別子で画面の名前を引き、一字一句の一致を確かめる）。

| 内部の呼び名（設計書・コード） | 識別子 | 画面の言い方 | 出る所 |

### 8.4 変えない言葉

すでに標準の言葉、またはこのアプリの中心の言葉なので、そのまま使う。

| 言葉 | 理由 |
|---|---|
| `記録する` | アプリの主な動詞。新しく記録する操作と、編集の `保存` を見分けられる |
| `元に戻す`・`閉じる`・`編集`・`ログアウト`・`Google でログイン`・`続きを読み込む`・`次の取引を記録` | 標準の言葉 |
| `日本時間で合っている` | 明細の時刻のタイムゾーンの確認のボタン。押す内容をそのまま言う |
| `A いい損失`・`B 悪い損失`・`C 極悪な損失`・`計画どおりの勝ち`・`危ない勝ち` | オーナーの損失種別の定義から来た、アプリの中心の言葉 |
| `欄`・`誤り`・`スクショ` | 「入力欄」として通じる・「エラー」より柔らかい・一般に通じて 360px のボタンに収まる |
| `LC の物差し` | 判定の枠の図の見出しで、用語集で引ける（#57）。物差しは一般の言葉 |
| `LC を入る前に決めていたか`・`LC を動かしたか`・`時間足を変えたか` | 3 つの質問の名前。詳細の答えの札の名前も同じ問いの名前にする（計画から外れた答えは「外れ」の字を出さず、記号と枠で示す。読み上げは「計画から外れた」） |
