# ADR-0022: 心理のタグを取引の文書の最上位に ID の集合で持ち、専用の入口で置き換える

- 状態: 採用
- 日付: 2026-11-21
- 関連: 設計書 C55・4.2・9.4・6.1、ADR-0004（記録の API と保存）、ADR-0020 の決定 7（保存の形の版と、知らない欄を落とさない守り）、ADR-0021（下のシート）、Issue #156・#162（心理ごとの集計）・#163（選択肢に出すタグを設定で選ぶ）・#123（good / more）

## 背景

取引に心理のタグ（悔しい・取り戻したい・調子に乗った など 21 個。C55）を 0 個以上付けたい。付けるのは記録の保存の後のシートと取引の詳細で、チップを押した時点で保存する（シート・アプリを閉じても残る）。複数行の明細では、最後の行の後に 1 度だけ出るシートで付けたタグを、その明細から保存した行すべてに付ける。

保存の形には 3 つの条件がある。

1. 後で心理ごとの計画どおり率を数える（#162）ので、名前ではなく固定の ID で持つ。#163 で選択肢に出すタグを設定で選べるようにしても、過去の記録の意味が変わらない
2. 判定・R・集計の入力（`record`・`snapshot`。`core/record.ts` の `toTradeInput`）は変えない
3. 前の版へ戻したとき（`rollback.yml`）・古いタブの直す画面が保存したときに、タグを落とさない。前の版の直す画面（`mergeEdit`）は、知っている欄だけを `record` に組んで PUT を送る

## 決定

1. **取引の文書の最上位に `emotionTags`**（`record` の外。`snapshot`・`charts` と並ぶ）。値はタグの ID の配列で、一覧の順に並べ、重複なし・平常心はほかと同時に無い。0 個のときは鍵ごと消す（タグの無い取引は前と同じ形）。取引の応答はタグのある取引だけに鍵を足す
2. **書く入口は `PUT /api/trade-emotions`** 本文 `{"tradeIds": [1〜20 件], "tags": [0〜21 個]}`。指した取引すべてのタグを 1 トランザクションで **置き換える**（足す / 外すの差分ではなく集合を送るので、同じ本文を送り直しても同じ結果）。1 件でも無い（ほかの利用者の取引を含む）なら 404 で何も書かない。取引の ID の形が崩れていれば、経路の ID と同じく保存先に触れずに 404。`record`・`snapshot`・`charts`・`schemaVersion` は変えず、`updatedAt` だけ進める。20 は明細の行の上限と同じ
3. **`schemaVersion` は上げない**。取引の PUT とチャートの PUT / DELETE は、どれも読んだ文書を `{**doc, ...}` で組み直すので、`record` の外の鍵を保つ。前の版の API も同じ作りなので、戻してもタグは文書に残り、応答に出ないだけ（出し直せば見える）。古いタブの直す画面の PUT も `record` だけを送るのでタグを落とさない。ADR-0020 の決定 7 の (b) のような守りは要らない。ただし新しい入口も、知らない版（この版の知る値より大きい `schemaVersion`）の文書には書かない（409 `unknownSchemaVersion`。決定 7 の (a) と同じ規則を書き込みの入口すべてにそろえる）
4. **ID の一覧は 2 か所で、fixture で突き合わせる**: 画面は `core/emotion-tags.ts`（ID・まとまり・並び・選び方の純関数。文言は `ui/src/lib/emotion-tags.ts`）、API は `api/src/loss_note_api/emotion_tags.py`。`tests/core/emotion-tags-fixture.test.ts` が `tests/fixtures/records/emotion-tags.json` を作り、`api/tests/test_emotion_tags_fixture.py` が突き合わせる。ID は保存の形なので、足すだけにする（変える・消すと過去の記録の意味が変わる）
5. **画面は押すたびに集合を送り、要求は 1 本ずつ**（`ui/src/lib/emotion-controller.ts`）。送っている間に押されたら、終わった後に最新の集合を 1 本だけ送る（後に届いた古い集合で上書きしない）。失敗したら待っている送りを捨てて、最後に保存できた集合へ戻す

## 選択肢

- **`record.emotionTags` に持ち、取引の PUT で送る**（直す画面の `KEPT_KEYS` で保つ）: 前の版の直す画面・API はこの欄を知らないので、戻した後に直すとタグが落ちる。防ぐには版を上げて ADR-0020 の決定 7 の (a)(b) と同じ段取り（守りの版を 1 つ前に出す）が要り、タグの無い先物の取引まで前の版で直せなくなる。また、チップを押すたびに取引の本文全体を送ることになり、直す画面と同時に開いていると互いの変更を上書きする。採らない
- **取引ごとの入口 `PUT /api/trades/{id}/emotions`**: 複数行の明細では押すたびに N 本の要求になり、一部だけ失敗すると行ごとにタグが食い違う。採らない（1 件の詳細も集合の入口で 1 件を指せば足りる）
- **取引の部分の更新（PATCH）**: 今の取引の検査（`validate_trade`）と欄同士の検査を部分の本文向けに作り直すことになる。タグだけのために広げない。採らない
- **名前（日本語）で保存する**: 名前を直すと過去の記録と食い違い、#163 の選択と集計（#162）が名前の揺れに弱くなる。採らない

## 結果

- タグの無い取引の文書・応答の形は変わらない（既存の fixture のテストは変更なしで通る）。判定・R・期間の集計はタグで変わらない
- 前の版へ `rollback.yml` で戻しても、付けたタグは文書に残る（画面に出ないだけ）。`infra/README.md` の切り戻しの注意に足すことは無い
- 同じ取引を 2 つのタブで同時に付け外しすると、後に届いた集合が勝つ（1 人で使う前提では起きにくいので守りは足さない）
- 心理ごとの集計（#162）は `emotionTags` を ID で数える。選択肢に出すタグを選ぶ（#163）のは画面の側の絞り込みで、保存の形は変えない
