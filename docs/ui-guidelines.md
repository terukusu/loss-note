# 画面の原則（UI / UX ガイドライン）

loss-note の画面が沿う原則と規則、そのよりどころにした世の中のベストプラクティス、画面を触る PR のチェックリスト、アプリとしての画面の構成（ナビ・重ね方・画面の形。9 章）。

> Issue #3（画面のデザインの土台）で作成（2026-11-17）。option-simulator の `docs/ui-guidelines.md` の構成を移植し、原則を loss-note 向けに作り直した。価格・損益の例はすべて架空。

---

## 1. はじめに

**目的**: 画面を足す・直すときに「このアプリではこうする」を 1 か所で引けるようにする。

**読む人**: 画面を触る開発者、実装・レビューをする AI のエージェント、PR をレビューする人。初めて読む人向けに書く。

**ほかの文書との関係**:

| 文書 | 役割 |
|---|---|
| このガイドライン | **原則と規則**（なぜ・こうする / こうしない・何で確かめるか）。画面の中身が変わっても変わりにくいもの |
| `docs/design.md` | **設計書**（考え方・記録の形・判定・画面の一覧）。規則の出どころとして節番号で参照する（9.1 からこの文書へリンクしている） |
| `CLAUDE.md` | リポジトリの作りと確認の手順 |

食い違ったら、このガイドラインを直すか設計書を直すかを PR で決める（黙ってどちらかに合わせない）。

**このアプリの前提**: 裁量トレードの損失ノート。トレーダーが決済の後に 1 回、スマホで素早く記録し（設計書 7.5）、PC で広く振り返る（設計書 9.1）。物差しは「勝ったか」ではなく「計画どおりだったか」（設計書 1.1）。動機は「入力が面倒で記録が続かない」（設計書 K10）なので、**記録の手間を減らすことと、開きたくなる見た目は、機能と同じ重さ** で扱う（設計書 K2）。

## 3. 原則ごとの規則

各行は「こうする / こうしない」とアプリの中の実例。**検査** は機械で確かめているもの（`npm test` の vitest、`npm run ui:check`）。検査の無い規則は目で確かめる（6 章）。

### P1 記録の手間の予算

- する: 記録の画面は「スクショを貼る → LC と一言 → 3 つのタップ」の順に縦に並べ、主の動作（[記録する]）は 1 つ。スマホでは画面の下半分（親指の届く所）に押すものを寄せる
- する: 入力の既定値を置き、手で打つ欄を増やさない（設計書 C17・C19）。2〜3 択は `Segment`（タップ 1 回）で、プルダウンにしない
- する: 4 択以上（決済の理由など）は 1 行の `select`（`.select`。当たり 44px・文字 16px）。任意の欄は `<details>`（「ほかの欄（任意）」）に畳み、主の流れを短くする（→ 9.3 で置き換え: 取引の欄のシートの中の次の段）
- する: 主の動作（[記録する]）は幅 720px 未満で下部の行き先の上に貼り付け（sticky）、帯は 1 段（1 行の状態の文 + [記録する]）で幅 360px で 64px 以下にする（入力中の欄を隠さない。#33）。幅 720px 未満は幅いっぱい・不透明で下部の行き先に付け、下の文字を透かさない。状態の文は 360px で切れない短さにする（長い知らせは判定の枠の案内に全文で）。保存の失敗の知らせ（[ログインし直す] を含む）が出ている間だけ伸びてよい。保存の後のボタン 1 つは帯に包まない（→ 9.3・9.6 で置き換え: 記録するは全画面のシートでタブを隠し、下の帯は判定の 1 行 + [記録する] の 1 段。キーボードが出たら判定の 1 行に畳む）
- する: 押せない理由は、帯には数（「あと 7 欄」「誤り 1 欄」）か一言（「明細を読み取っています」）だけ、欄の名前は判定の枠の案内に文で出し、[記録する] の読み上げの説明（`aria-describedby`）に結ぶ（色だけに頼らない）。そろったら帯に判定の要約を文字だけで出す（バッジ・色を使わない）
- する: 判定の枠は 3 つのタップ（見出し「決済までの振る舞い」）の枠のすぐ後に置き、タップの後に判定が出ていれば判定のバッジと R の行を見える範囲へ寄せる（`scrollIntoView` の `nearest`。見えていれば動かさない。押したタップを上へ隠さない。動きを減らす設定では動きを付けない。フォーカスは動かさない）（→ 9.3 で置き換え: 判定は下の帯に常に 1 行で出し、押すと判定のシート）
- する: 開いた直後の 1 画面に [スクショを選ぶ] と銘柄の欄が入るようにする（画面の説明文を付けない。送る前の注意は 3 つの中身を畳まずに 3 行以下、補足は「i」の吹き出しに置く（#57）。PC だけの貼り付けの案内は指で触る端末では出さない）（→ 9.4 で置き換え: 明細の場所（選ぶ前・読み取り中・読み取りの後）と LC・一言・3 つの質問・判定が、開いた直後から 390×844 で 1 画面。読み取りを待たない）
- する: 行き先（ホーム・記録する・一覧・設定）は幅 720px 未満で画面の下に固定し、どの画面からも 1 タップ（→ 9.2・9.5 で置き換え: 下のタブ 4（ホーム・取引・振り返り・設定）+ 真ん中の [＋ 記録]。横はレール、広いはサイドバー）
- しない: 記録の途中に確認・説明のダイアログを挟む。任意の欄を必須にする
- 検査: `ui:check` の V6（幅 360 の全画面から 4 つの行き先へ 1 タップ）、記録する画面の R1〜R10（R10 = 明細を貼って打つ 2・選ぶ 3 で判定まで）、帯の高さと状態の文の行数・切れ（幅 360 の全状態。`--inject-clip` の帯の見本で見逃さないことを確かめられる）、R11（判定が見える範囲の外で最後のタップを座標で押す → アプリが寄せ、判定のバッジと R が見える）・R12（開いた直後の 1 画面・注意 3 行以下・全長 2,550px 以下。口座が 2 つ以上の形は口座の欄の分だけ 2,646px 以下。#47）、ACC1・ACC2（口座の Segment の 1 タップ・その場で足す。→ 9.4・9.11: 口座が 2〜3 なら要約の下の Segment で 1 タップのまま、足すのはシート。R11・R12 は 9.10 の「1 画面に収まる」に置き換え）。`record-view.test.tsx`「帯には数、名前は判定の枠」。30 秒の人の実測は [`record-timing-check.md`](record-timing-check.md)

### P2 色は規律を表す

- する: 判定の段のトークンは `--tier-{plan,break,worst,neutral}-{ink,bg,line}`。段と判定の対応は `ui/src/lib/badge.ts` の 1 か所（A・計画どおりの勝ち = 計画どおり、B・危ない勝ち = 崩れ、C = 極悪、判定なし = 中立）
- する: 強調の色（`--accent`）は操作（主のボタン・今いる画面・フォーカス）にだけ使い、判定の段の色と混ぜない（→ 9.9 で置き換え: 使う所を 6 つに決める）
- しない: 損益・R の正負で文字や面の色を変える。判定の段の色を判定以外（入力の誤りなど）に使う（入力の誤りは `--danger`）
- する: 判定の枠の LC の物差し（#34。`components/Ruler.tsx`）は色を足さない。線・点・文字は文字と線のトークン（`--ink*`・`--line*`）だけで、点の種類（イン・決めた LC・広げた後の LC・決済・TP）は形で見分ける（判定の段の色も使わない。窓・滑りの A で越えた区間が「計画どおり」の色にならないように）
- する: ホームの規律の振り返り（#88。`components/ReviewSummary.tsx`・`DisciplineCurve.tsx`、CSS は `styles/review.css`）は判定の段の色と文字・線のトークンだけ。判定の内訳の帯は段の色（`--tier-*-ink`）の区切り、規律コストの曲線は 実際 = 文字の色（`--ink`）の実線・計画どおりだったら = 計画どおりの段（`--tier-plan-ink`）の破線・差の面 = 崩れの段（`--tier-break-ink` を薄く）+ `--tier-break-ink` の 45 度の斜線（色だけに頼らない）・崩れた取引（計画どおりの R に置き換えた取引）の点 = 判定のバッジと同じ形（△・×）の段の色の線。右端の「計画」「実際」の札と差の括弧・目盛りは文字と線の色。R・% の数字は無色。面の色・内枠を足さない
- する: ホームの直近の流れ（#35。#128 で一覧の上から外した。`components/StreakStrip.tsx`、CSS は `styles/streak.css`）は判定の段の色と文字・線のトークンだけ。点は段の地・線・文字の色の丸に段の記号（○ △ × −）を重ね、連続している点の下の線は文字の色（`--ink-2`）。損益・R を出さない
- 検査: `badge.test.ts`、`cssTokens.test.ts`「段の色が互いに違う」「バッジの段のクラスは段のトークンだけ」「物差しの CSS は文字・線・段のトークンだけ」「振り返りの段の CSS は判定の段・文字・線のトークンだけ」

### P3 数字は符号と単位で読ませる

- する: R は小数 1 桁 + `R`、円は 1 円単位で 3 桁区切り + `円`。丸めは 0 から遠い側（四捨五入）。負の符号は `−`（U+2212）、ちょうど 0 は `±`、丸めて 0 になっても元の符号を残す（`−0.0R`。設計書 C29）
- する: 表示は `ui/src/lib/format.ts` の `formatR` / `formatYen` だけを通す（`RNum` / `YenNum` の部品）。本文の書体の桁の揃う数字（`tabular-nums`。等幅の書体にしない）で、大きさは `num--lg`（22px）/ `num--xl`（36px）。数値の入力欄も同じ。等幅（`--mono`）は ID・コードだけ（`.mono`）
- する: 資金のような符号の無い金額（損益ではないもの）は `formatAmountYen`（`1,000,000円`。+ を付けない）で出す（Issue #5）
- する: 価格・数量・乗数・数量の刻み・レートの表示は `formatPrice` / `formatQuantity` / `formatNumber` で、整数部だけ 3 桁区切り（`38,250`・`10,000`）。保存した数のまま丸めない（FX の `1.08345` はそのまま。小数部は区切らない）。負の符号は `−`（U+2212）。入力の欄の値には区切りを入れない（入力中もフォーカスが外れても書き換えない。既定値・流し込みは `formatPlain`）。区切りつき・全角の貼り付けは `parseNum` が受ける（正しい 3 桁区切りだけ）（#40）
- する: 金額は取引・口座の通貨で出す（`formatMoney`・`formatAmount`。#47 PR-2）。円は今のまま（`−8,000円`・`1,000,000円`）、ほかの通貨は「数 + 半角の空き + 3 文字」で小数 2 桁（`−50.00 USD`・`10,000.00 USD`）。記号（$・€）は使わない。判定の枠の大きな数字では、数は `.num`、単位（円・通貨の 3 文字）は `.num` の外で小さく（`.num-unit`）。レートの式も金額と同じ書き方（`1 USD = 150円`・`1 EUR = 1.1 USD`）。文の中の金額は数と単位を 1 つの塊（`AmountText`）にして行の境目で離さない。通貨の違う金額を足さない・円に直した値を並べない。価格（イン・LC・決済）には単位を付けない
- する: 判定の枠の R・リスク・損益はラベルの上端を揃える。値が出ないときは場所に「—」を出し、理由は数の段の下の注記に 1 回だけ（一覧と同じ形「リスクの「—」: 損益を入力すると表示されます」。価格の通貨が口座の通貨と違う取引は「為替か損益を入力すると表示されます」で、損益の場所も「—」。#47 PR-2）。LC が無い取引は R・リスクの段を出さず「LC が無いので R・リスクは表示されません」の 1 行にする。一覧の「—」の理由は題の行の「i」（説明のシート）に 1 回だけ。ホームでは出さない（設計書 9.2・9.3。#132）
- する: 判定の枠の数量と提案の数量（#67）は数の段のすぐ下（口座の 1 行の前）に注記と同じ無色の 1 行（`verdict__aside`）で出す。色・「大きすぎ」の言葉・新しい色のトークンを足さない（判定の定義を増やさない）。文は「数量 10,000 · 提案の数量 4,000（2.5 倍）」の形で、実際の数量と提案の数量を並べ、比は括弧に下げる（リスク（%）と同じ数を主役に重ねない）。区切り（「数量 10,000」「· 提案の数量 4,000（2.5 倍）」。「·」は後ろの区切りの頭に付け、行末に残さない。#58）の中では折らず、幅 360px で足りなければ区切りの間で折る（`ui:check` の SZ1 が確かめる）。画面の言葉は「数量」「提案の数量」「許容リスク」（「サイジング」「提案」だけ・「許容」だけ・「刻み」を文に書かない）

- する: 「i」は `button`（`type="button"`）で、名前は「「〈言葉〉」の説明」、開閉は `aria-expanded`・`aria-controls`。見た目は 20px の丸（小さいラベルの「R」・物差し・札は 16px）、当たりは 44×44px（負の余白でラベルの段の高さを変えない）。開いてもフォーカスを動かさず、Esc・戻るで閉じたらフォーカスを「i」へ戻す。吹き出しは同時に 1 つ、窓（上の帯・下部の行き先・貼り付きの帯を除く）と切る祖先の端で切れないように揃え（左 / 右 / ボタンを含むカードの左右 8px の内側）、下に入らなければ上に開く（3 つのタップは上を先に）。左 / 右の揃えでは矢印で「i」を指し、開いている「i」は強調の色。文の中の用語集のリンクは当たりの 44px の例外（WCAG 2.5.8 の inline）（`lib/info-tip.ts` の `infoPlace`。#57）（→ 9.3 で置き換え: 縦と横の形では吹き出しをやめて説明のシート、広い形だけ押した所の吹き出し。「i」のボタンの名前・開閉・当たり・フォーカスを「i」へ戻す規則はこのまま）
- しない: `div` に `onClick` だけ付けてボタンにする。記号だけのボタンに名前を付けない
- する: 文字の大きさは `--fs-*` のトークン、行の高さは倍率か文字の大きさからの `calc` で決める（px の決め打ちにしない）。端末で文字を大きくしたとき（Android の Chrome の文字の拡大は px の文字も大きくする）に、文字だけ大きくならない・行が重なることを避ける（WCAG 1.4.4。#79）

### P9 速く、動きは因果の分だけ

- する: 動き（押した手応え・面の色の切り替え）は `--dur-fast` / `--dur-base` と `--ease` だけで書く。`prefers-reduced-motion: reduce` ではトークンを 0s にする（→ 9.8 で置き換え: 次の画面・タブ・シート・保存の後の動きを因果の分だけ足す。時間はトークン、動きを減らす設定で 0 は同じ）
- しない: 飾りのアニメーション（浮き沈み・跳ねる）。ms の直書き
- 検査: 目で（6 章）

### P10 利用者の言葉

- する: 相場の言葉（LC・TP・イン・エントリー・決済・ロング / ショート・足・窓・滑り）はそのまま。判定はオーナーの言葉（A いい損失 / B 悪い損失 / C 極悪な損失 / 計画どおりの勝ち / 危ない勝ち）
- する: 操作の言葉・相場の用語は 8 章の用語集にそろえる（キャンセル・追加・削除・保存・再読み込み など一般的なアプリの言葉。1 つのものに 1 つの言葉）。誤りの文の中の [〜] は押すボタンの名前と一字一句同じにする
- しない: 開発中の合言葉・内部の識別子（tier・grade・route など）を画面に出す。設計書の内部の呼び名（崩れの条件・3 つのタップ など）は 8.3 の対応表で画面の言い方に直す
- 検査: `tests/ui/wording.test.ts`（8 章の表を読み、使わない言葉が画面の文字列に 0 件・対応表と画面の名前が一致・[〜] がボタンの名前）と目で（6 章）

### P11 安全な作り

- する: スタイルはクラスと `data-*` / ARIA 属性だけで切り替える。テーマは `<html data-theme>`（`applyTheme`）。ビルドの `index.html` はインラインの script / style・style 属性・外部 URL を持たない
- する: 画面から API へは `/api/...`（同一オリジン）だけで、`ui/src/auth/session.ts` の `api` を通す（ログイン中の ID トークンを付け、ログインしていなければ送らない）。Firestore・Storage の SDK を画面で読み込まない（firebase は `firebase/app`・`firebase/auth` だけ）
- する: ログインできないときは決まった文言だけを出し（「ログインのサービスと通信できませんでした」など）、コード・例外の本文を出さない。白い画面にしない（ADR-0003）
- する: 画像のプレビューは canvas に描く（決済明細の読み取り。#15）。object URL・data URL を作らない（CSP の img-src に `blob:`・`data:` を足さない）
- しない: `innerHTML` などの HTML の文字列を DOM に入れる API、JSX の `style`、`.style` の書き換え。外部のフォント・CDN・画像を読む。`createObjectURL`・`toDataURL`・`FileReader`
- 検査: `csp-check.sh`、`source-rules.test.ts`（自己テスト付き。object URL・data URL の規則は #15 の AC-13）、`cssTokens.test.ts`「url() も @import も書かない」

### P12 見た目はトークンで

- する: `tokens.css` は「テーマに依らない `:root`（文字・余白・角丸・動き・大きさ）」と「テーマの 2 つの定義（`:root, :root[data-theme="dark"]` = 既定のダーク、`:root[data-theme="light"]`）」だけ。色・影の値は 2 つの定義の中にだけ書き、名前の組をそろえる
- する: 部品の CSS（`components.css`）・枠の CSS（`layout.css`）は `var(--…)` と、トークン同士の `color-mix()` だけで色を書く。TSX はクラス名だけを持ち、見た目の値を持たない
- する: 角丸は `--radius-lg` 12px・`--radius-md` 8px・`--radius-sm` 6px と丸い形の `--radius-pill` だけ。部品の CSS に px の角丸を直書きしない（#33）（→ 9.9 で置き換え: 値を 18 / 14 / 10 にし、シートの上の角の `--radius-sheet` 28 を足す。直書きしない規則は同じ）
- する: テーマは OS の設定で選ばない（既定はダーク。選んだテーマは端末に記憶）
- する: 開発の時だけの部品の見本の CSS は `ui/src/pages/dev/parts.css` に置き、見本の画面からだけ読み込む（本番の CSS に入れない）
- 検査: `cssTokens.test.ts` (a)(b)(c)「prefers-color-scheme を使わない」「TSX に色の直書きが無い」「角丸のトークンと直書き 0 件」

## 8. 用語集（画面の言葉）

画面の文字と読み上げの名前で使う言葉の決まり（#74。オーナーの「一般的な文言になっていないところが多い」「相場用語を統一したい」から）。

- 基準: ① 一般的なアプリ（iOS・Android・Google・Notion など）の標準の操作の言葉 ② 同じものは画面をまたいで同じ言葉 ③ 相場の言葉は言い換えない ④ 開発中にできた造語を出さない ⑤ 短く、360px で折れない ⑥ 誤り・注意の文は何が起きたかと次に何をするかを言い切る
- 表のバッククォートで囲んだ言葉はテスト（`tests/ui/wording.test.ts`）が読む。「使わない言葉」は画面の文字列（`ui/src` の文字列・JSX の文字・テンプレートの文字。開発用の部品の見本とコメントを除く）に 1 つも出ない。言葉を足す・変えるときは、表と画面を同じ PR で直す
- 利用者が引くアプリの中の用語集（「i」の吹き出しと用語集の画面。`ui/src/lib/glossary.ts`）の見出しも、この章の言葉にそろえる（8.3）

### 8.1 操作の言葉

|---|---|---|

「直す」は誤りを正す意味（「誤りのある欄を直す」「直してから、もう一度押してください」「違うときは時刻の欄を直してください」）でだけ使い、編集の意味では使わない（PR #73）。

テストで分けられないもの: 「直す」（編集の意味か誤りを正す意味か）と「変える」（「変更」にする操作か、「名前を変えると」のような文か）は意味で分かれるので、レビューで見る。JSX の式をはさんで割れた文（`「{PROVISIONAL_MARK}」は…`）は、割れた片ごとに検査する。

### 8.4 変えない言葉

すでに標準の言葉、またはこのアプリの中心の言葉なので、そのまま使う。

| 言葉 | 理由 |
|---|---|

### 9.3 3 つの重ね方

| 形 | 動き | 使う所 | 閉じ方 |

下のシートにするもの: 「i」の説明（説明のシート。用語集のリンクをたどる規則は P6 のまま）・取引の欄（記録する画面の要約の ［編集］。口座の追加の 2 欄もこの中に開く）・ほかの欄（任意。取引の欄のシートの次の段）・チャート（記録する画面の 2 段目のチャートの行・1 段目のチャートのある小さな枠。時間足・差し替え・削除・決済時・追加のチャート）・判定（下の帯の 1 行を押す）・記録したときの値と今の値の比較・詳細の操作（「…」= 今の値と比べる・削除）・期間の指定・明細のタイムゾーン・口座の追加・保存の後の good / more（#123）。チャートの拡大は画像を全画面で見る層（黒い面・✕）。

- する: 部品は 1 つ（`Sheet`）。`<dialog>` の `showModal()`（最上層・フォーカスを閉じ込める・Esc・後ろを操作できない）、後ろの暗い面は `::backdrop`。CSP に触れない（style 属性を使わない）
- する: 開く・閉じるは `lib/back-stack.ts` の層に載せる（履歴に 1 段積み、戻るで上から 1 つ閉じる。今の「i」の規則のまま）。Android の Chrome は、`showModal()` の間の戻る・Esc を dialog の `cancel` → `close` に回し `popstate` を出さない（close watcher）。dialog の `close` は UI で閉じたのと同じに扱い、糊が積んだ段を `history.back()` で戻して数を合わせる（P6 の規則。`back-layers.test.ts` に例を足す）。取り消せる `cancel` は Esc と同じ（たどった説明なら 1 つ前へ）、取り消せない `cancel`（操作をはさまずに続けた 2 回目の戻る）はシートごと閉じる（「戻るで 1 つずつ」の例外。#129）。キーの Esc は dialog の `keydown` を取り消して自分で扱い、close watcher を通さない（続けて押しても 1 つずつ戻る）
- する: 高さは中身で決め、最大は `86dvh`。中がスクロールする（文字の拡大 200% でも窓の中に収まる。#110）
- する: シートを開いている間は、トーストの取り消しの時間（[元に戻す] の 8 秒）を止め、閉じたら続ける（モーダルの間は外が inert になり、トーストを押せないため）
- する: シートの見せ方は形で替える（同じ部品）。見せ方は同じ `<dialog>` 要素のクラスと `data-form` の CSS だけで替え、作り直さない（口座の追加・期間・取引の欄のシートの入力の欄の値とフォーカスを、形が替わっても保つ。9.5 の「DOM の形を替えるのは入力の欄を持たない側だけ」と同じ）。縦 = 下から、横 = 右から出るパネル（幅 400px・高さいっぱい）、広い = 説明と小さな操作は押した所の吹き出し / メニュー（幅 360px まで。最上層の dialog なので、置き方は CSS の anchor positioning（`position-area` と `position-try-fallbacks`。下 → 上・左端そろえ → 右端そろえ、3 つの質問・物差しは上を先に）。使えないブラウザでは中央。後ろは暗くせず、面の端は線で示す。#129）・入力のあるものは中央のダイアログ（幅 480px・最大の高さ 80%）。右から出るパネルは広い形では使わない（分割の右の列とまぎらわしい）
- しない: 中央の確認のダイアログ（P4 のまま。確認は誘惑ガードだけ）。その場で開く折りたたみ（`<details>`）と、欄に重なる吹き出し（縦と横の形）。例外は用語集の画面の中のページの中のリンク
- しない（最初は）: 下へ引いてシートを閉じる操作（指の動きを追う処理が要る）。行のスワイプ（iPhone の左端からの戻るとぶつかる）。引き下げて読み直す（`overscroll-behavior-y: contain` でブラウザの引っ張って再読み込みも止める。書きかけが消えるため）
- トーストは今のまま（縦は下のタブの上・全画面のシートの間は下の帯の上、横と広いは右下）

- 2 段目「振り返る」: 上から **入れたもののカード**（1 枚の面に、明細の行・（口座 2〜3 なら）口座の Segment・チャートの行）・入る前に決めた LC・崩れの条件の一言・3 つのタップ・下の帯（判定の 1 行 + ［記録する］）。LC・一言・3 つのタップは、明細を選んだ直後・読み取り中・読み取りの後のいつでも入れられる（C23・7.5 の流れ 2）
- チャートの行: 空 = 小さなローソク足の絵と ＋・題「エントリーした足のチャート」・チャートの注意（2 行）。行全体が押せて **1 タップでチャートを選ぶ**。入った = 小さな写し・「エントリー時 · 1時間足」・決済時の 1 行・›。押すとチャートのシート（時間足・差し替え・削除・決済時・追加のチャート）
- 2 段目の明細の行の 3 つの状態（同じ場所・同じくらいの高さで入れ替わる）:
  1. 読み取り中: 要約の骨組み（「読み取り中…」）と 2 番目の重さの ［キャンセル］（読み上げ「明細の読み取りをキャンセル」。8.1。下の帯が「明細を読み取っています」と言うので枠の中は短く）
  2. 読み取りの後・手入力の後: 要約 3 行（銘柄の名前 / L / S · 数量 · イン → 決済 / 決済の時刻 · 明細の損益。何も切らず、狭ければ折り返す。#164）+ 印「読み取り」+ ［編集］（取引の欄のシート）。読めなかった・未入力・誤りの欄は要約がチップで名指しし（誤りの値は要約に出さず「—」）、押すとその欄でシートが開く。読み取りの結果は要約に後から流れ込むだけで、ほかの欄の場所を動かさない。取引の欄（L / S・イン・決済）に値があれば、2 枚目の読み取りの失敗・キャンセルの後も要約のまま（#130）
  3. やり直し: 読み取りの失敗・キャンセルで取引の欄に値が無い。理由と ［スクショを選ぶ］（1 段目へ）・［手入力で続ける］（選ぶ枠は 1 段目だけ。［記録する］ は 2 段目にしか無く、要約を通らずに記録できる経路は無い = 7.5）
  - 明細の時刻にタイムゾーンが書かれていないとき（#58）: シートを **自動では開かない**（入力中の欄を奪わない）。要約の行に印「時刻が未確定」と 2 番目の重さの ［タイムゾーンを選ぶ］ を出し、押すとタイムゾーンのシート（選択肢ごとに欄に入る日本時間。端末に覚えたタイムゾーンがあれば最初からそれで入り、印は出ない = #58 のまま）。保存の門（7.5。選ぶか時刻の欄を直すまで保存しない）は今のまま保ち、下の帯の判定の 1 行は「タイムゾーンが未選択」と押せない理由を出す
- する: 読み取りが終わったとき、どの欄にもフォーカスが無ければ LC の欄へフォーカスを移す（入力中の欄からフォーカスを奪わない。iPhone ではユーザーの操作の外の `focus()` でキーボードは出ないので、欄の強調だけになる）
- する: 口座が 2〜3 の人は、明細の行とチャートの行の間に口座の Segment を 1 行で残す（1 タップ。今の ACC1 と「この明細の口座を選んでください」の 1 行の置き場。要約の出ている読み取りの後・手入力の後だけ）。4 つ以上は要約の先頭の口座の札 → 取引の欄のシートの口座の欄。口座の追加は取引の欄のシートの中に開く（シートを重ねない）
- する: もう 1 枚の明細は上の帯の ［スクショ］ で 1 段目へ戻り、明細の枠の ［スクショを変更］ で選ぶ（注意は同じ枠の下。取引の欄のシートは欄だけ）。複数行の進み具合「1 / 2 行目」は上の帯の題の下（右は ［スクショ］ が使う）。オプションのレッグの欄（#117）は取引の欄のシートに置く（2 段目の行を増やさない）。レッグ 1 本の欄は幅 360 でも 2 列（P / C | 買い / 売り、限月 | 行使価格、枚数 | ［満期で消滅］、イン | 決済）で 1 画面に収め、［このレッグを削除］ は区切りの下に離す。消したら一覧に「レッグ N を削除しました ［元に戻す］」（シートの中はトーストが押せないため。P4）
- する: 縦の 390×844（等倍の文字）に、ホーム画面に追加した iPhone の安全域（上 47・下 34）を入れて測り、2 段目の 4 つの状態（読み取り中・読み取りの後・手入力・2 行の明細 + 口座 3 つ）は縦のスクロール 0px（チャートの注意を含む）、1 段目も 0px（注意は C38 の同意の代わりなので畳まない）。安全域 0 でも同じ。「狭めた = …」の手がかりは 3 つ目の問いの「i」の説明の先頭に置き、画面の行にしない（#130。オーナーが決めた）
- 30 秒の測り方（`docs/record-timing-check.md`）はこの形と同じ（段の移りのタップは 0）: 明細を選ぶと 2 段目に移るので、読み取りを待たずに LC と一言を打ち、3 つのタップを選び、要約が埋まったら確かめる。読み取りの秒数は人の入力と重なり、30 秒に足し算で乗らない

### 9.5 画面の形と切り替えの境目

| 形 | 条件（キーボードを除いた窓の大きさ） | ナビ | 列 | 中身の最大の幅 |
|---|---|---|---|---|
| **縦**（compact） | 下のどちらでもない | 下のタブ 4 + 真ん中の ［＋ 記録］ | 1 列 | 640px（中央に寄せる） |
| **横**（landscape） | 高さ 500px 未満 かつ 幅 600px 以上 | 左の縦のレール（アイコン・60px + 左の安全域）。［＋］ はレールの真ん中 | 2 列 | 窓いっぱい（左右の安全域の内側） |
| **広い**（wide） | 幅 1024px 以上 かつ 高さ 500px 以上 | 左のサイドバー（1280px 以上はラベルつき 232px、1024〜1279px はアイコンだけの 72px のレール）。上に ［＋ 記録する］ | 2 列 / 一覧と詳細の分割 | 1200px（文の段は 720px まで。分割の画面は窓いっぱいで、左の一覧は 440px） |

- する: 形は **キーボードを除いた幅と高さだけ** で決める。純関数 `lib/form-factor.ts`（前の大きさ・今の大きさ・キーボードが出ているか・今の形 → 形とナビの段）が 1 か所で決め、殻が `<html data-form="compact|landscape|wide">` と広い形のナビの段 `data-nav="rail|sidebar"`（幅 1280 の境）に書く。CSS は形とナビの段をメディアクエリでなくこの 2 つの属性で切り替える（テーマと同じく、描く前に `main.tsx` で当てる）
- する: **形を止めるのは、キーボードの開閉で大きさが変わったときだけ**（幅が変わらず、高さだけが変わった。`lib/keyboard.ts` の印がある間・編集できる欄にフォーカスがある間）。**向きが変わったとき**（幅と高さが入れ替わる・`orientationchange`・`screen.orientation` の `change`）と幅が変わったとき（折りたたみの開閉・窓の大きさ・画面の分割）は、入力中でもすぐ決め直す（決め直さないと前の形の並びが新しい幅に残り、横スクロールが出る。P7）
- する: 形が替わっても、入力中の欄の値とフォーカスを保つ。記録する・編集は、形が替わっても View を包む DOM を同じに保ち（同じ controller を描き直すだけで、作り直さない）、1 列 / 2 列も、全画面のシートかパネルかも、同じ要素のクラスと `data-form` の CSS だけで替える。殻が DOM の形を替える所（分割・ナビ・シートの見せ方）は、入力の欄を持たない側に限る
- する: pointer と hover は、ホバーの見た目（`@media (hover: hover)`）と押したときの縮み（`@media (hover: none)`）にだけ使う（指で触る PC・マウスをつないだタブレットで、同じ窓の大きさが違う画面にならないように）
- する: 高さを見る。スマホの横向き（844×390・932×430）は幅だけなら PC の側になるが、縦 400px 前後に上下の帯は置けないので「横」にする。横と広いは高さ 500 で排他（ノートの低い窓 1366×600・拡大 150% の 1280×620 も「広い」）
- 端末ごと: タブレットの縦（768×1024・Android の 800×1280）は「縦」（下のタブ + 640px の 1 列。2 列にすると 1 列がスマホより狭い）。タブレットの横（1024×768・1280×800）は「広い」。折りたたみの開いた縦（690×830 前後）は「縦」、開いた横は幅と高さしだいで「縦」か「広い」、閉じた外の画面（340px 前後）は「縦」。開閉は幅が変わるので、入力中でもすぐ決め直す（欄の値とフォーカスは保つ）
- する: View の中の並びの段（一覧の口座の位置・詳細の「エントリー … →」・レッグの表など、今の窓の幅 480 / 720 の段）は、窓ではなく列の幅のコンテナクエリにする（分割の左の列 440px で 720 以上の並びにならないように）
- する: 向きは固定しない（manifest に `orientation` を書かない。Web では iPhone の向きを固定できず、横で使う人もいる）。主の形は縦で、横は「崩れない・記録ができる」を守る
- しない: 形の境目を足す（境目は幅 600・1024・1280 と高さ 500 だけ）。形ごとに機能を落とす（P7）。幅の下限は 360px（P7。320px でも横スクロールを出さないのは目標で、検査はしない = P8 の組み替え）

同じ部品の 3 つの形:

| 部品 | 縦 | 横 | 広い |
|---|---|---|---|
| ナビ | 下のタブ + 真ん中の ［＋ 記録］ | 左のレール | 左のサイドバー（1024〜1279 はレール） |
| 画面の題 | 根は大きな題、次の画面は上の帯 | 列の先頭の小さな題（上の帯は置かない） | 中身の先頭の大きな題（上の帯は置かない） |
| 記録する | 全画面のシート・1 列・下の帯に判定。左上に ✕ | 全画面のシート（レールを隠す）・2 列（左 = 欄がスクロール / 右 = 判定と ［記録する］）。左上に ✕ | サイドバーを残した中身の面いっぱいのパネル・2 列・右 420px に判定と ［記録する］ を貼り付け。取引の欄は畳まない（#38）。パネルの左上に ✕。開いている間、サイドバーの ［＋ 記録する］ は選択中の表示で押しても同じ画面（主のボタンは右の列の 1 つ） |
| 取引の一覧と詳細 | 一覧 → 次の画面 | 分割（5 : 4） | 分割（440px : 残り）。行を押すと右だけ替わる |
| 下のシート | 下から | 右のパネル | 説明・操作 = 吹き出し / メニュー、入力 = 中央のダイアログ |
| 主役の数字 | 44px | 34〜36px | 44px |
| 押したときの返し | 面の色 + 縮み | 同左 | ホバー + 面の色 |

広い形のキーボード: `N` = 記録する、`G` の後に `H` / `T` / `R` / `S` = 各タブ、`J` / `K`・`↓` / `↑` = 一覧の次 / 前、`E` = 編集、`⌘ / Ctrl + Enter` = 記録する・保存、`Esc` = いちばん上の層を閉じる、`?` = ショートカットの一覧。1 文字のキーは欄にフォーカスがある間は効かせず、設定で切れる（WCAG 2.1.4）。

### 9.6 安全域とキーボード

- する: `index.html` の viewport に `viewport-fit=cover` と `interactive-widget=resizes-content` を足し、`apple-mobile-web-app-status-bar-style` を `black-translucent` にして、上の安全域まで面を敷く（ライトのテーマでは状態のバーの文字が白のままなので、上の安全域の面だけ暗くする）。`resizes-content` で Android の Chrome は窓がキーボードの分だけ縮み、下の帯がキーボードの上に付く。窓が縮んでも形は替えない（9.5。形はキーボードを除いた大きさで決める）
- する: 安全域は `env(safe-area-inset-*)` を受けるトークン `--safe-top / right / bottom / left` を通して使う（検査から値を差し替えられるように）。上の帯・タブ・レール・シート・トーストは `--safe-*` の分だけ内側に寄せ、面は端まで敷く。横の形ではノッチが左右どちらにも来るので、左右の両方に入れる
- する: 実機（ホーム画面に追加した iPhone）で安全域を確かめる（Chromium では `env()` が 0 で、`ui:check` は差し替えた値でしか見られない）
- する: キーボードが出ているかは `visualViewport` の `resize` を聞く薄い層（`lib/keyboard.ts`。純関数 + 糊）で決め、出ている間は `<html>` に印のクラスを付ける。その間、記録する画面の下の帯は判定の 1 行だけに畳む（［記録する］ を隠す）。Android（窓が縮む）では判定の 1 行がキーボードの上に付き、iPhone（窓が縮まない）では下の帯を隠す（キーボードの裏に置かない。判定はキーボードを閉じると戻る）。フォーカスした欄は見える範囲の中央へ送る（`scrollIntoView({ block: 'center' })`）
- する: 横の形でキーボードが出たら、左の列はフォーカスした欄だけが見えるように送り、右の列は判定の 1 行と ［記録する］ に畳む（列が左右なので、判定と欄が縦を取り合わない）
- する: 欄の種類は `inputmode="decimal"`（価格・数量）と `enterkeyhint`（LC の欄の Enter で一言の欄へ、一言の欄の Enter でキーボードを閉じる）。シートは `dvh` で高さを決め、キーボードで縮む
- しない: 下に固定した帯を、キーボードの裏に置いたままにする。`.style` で位置を書き換えて帯をキーボードに追わせる（P11）

### 9.7 行き来と戻る

iOS のタブの作法に寄せる。**タブはそれぞれ次の画面の積み重ねを持ち、戻るは今のタブの積み重ねを 1 つ戻る**。

規則:

1. **履歴の形は「ホーム + 今のタブの積み重ね」**（直接開いたときも 5 でこの形に揃える）: ブラウザの履歴は、いちばん下にホーム（`/`）、その上に今のタブの根（ホーム以外のとき）、その上に今のタブで開いた次の画面、の順に積む。シート（下のシート・全画面のシート）の段は、その上に `back-stack` の層として積む（URL は変えない。全画面のシートは今の URL `/record`・`/trades/{id}/edit` の 1 段）
2. **タブを切り替える**（A → B）: 先に開いている層を閉じ（`back-stack` の段を戻し終える。今の P6 の「置き換えの前に積んだ段を戻し終える」と同じ）、全画面のシート（記録する・編集）が開いていれば閉じて書きかけを残し「記録の入力は残っています」+ ［記録に戻る］ を出す（ADR-0019。全画面のシートはどのタブの積み重ねにも残さず、戻ったタブで黙って開き直さない）。A の積み重ねと各画面のスクロールの位置を記憶に残してから、履歴をホームの段まで `history.go(-k)` で戻し、B の根（B がホームなら根は戻った段そのもの）と B の記憶の積み重ねを 1 つずつ push し直す（B で前に開いていた次の画面が出る。#127 で決めた: 根の段を置き換えると前のタブの「進む」側の段が残り、進むで別のタブの画面へ入れてしまうため、置き換えずに積み直す。履歴の形は同じ）。戻す段の数は、今の項目の印の深さ（`appDepth`）で決める。画面が自分で積む段（用語集の中で言葉をたどった `#…` の段）も深さに数える（数えないと戻る段が足りず、タブの根の下に用語集が残る。#127 のレビュー B1）。戻すあいだの `popstate` は router が画面に出さない。push し直した項目はブラウザがスクロールの位置を正しく覚えていないので、記憶した位置を殻が戻す（いちばん上の画面は着いたとき、その下の段は後で戻って着いたとき。`back-stack` が積んでいる間の `scrollRestoration = manual` は今のまま、タブを替える前に層の段を戻し終えて auto に戻す。#127）。用語集の中でたどった段は、タブの記憶では用語集の 1 段にまとめる
3. **同じタブをもう一度押す**: 次の画面を開いていれば `history.go(-k)` で根へ戻り、記憶の積み重ねを捨てる。根にいれば先頭へ送って裏で読み直す
4. **戻る**（Android のキー・端からのスワイプ・ブラウザの戻る）: いちばん上の層があれば 1 つ閉じる → 全画面のシートなら閉じて書きかけを残す（「記録の入力は残っています」。ADR-0019）→ 次の画面なら 1 つ前へ → ホーム以外のタブの根ならホームへ（アプリの外へ出さない）→ **ホームの根ではアプリを出られる**（ブラウザ・OS に任せる。ホーム画面から開いたアプリなら閉じる。ホームの下に項目を足さない・`popstate` で押し戻さない。戻るを罠にしない）
5. **履歴を組み直すのは、アプリの印が無いときだけ**: 起動のとき、今の項目の `history.state` にアプリの印（`appDepth`・タブ・積み重ねの位置）が無いとき（新しく開いた・外のリンクから来た・ホーム画面のアイコン・共有）だけ、今の項目をホーム `/` に置き換え、URL から決まるタブの根と次の画面を push する（例: `/trades/a` → `[/, /trades, /trades/a]`、`/trades/a/edit` → `[/, /trades, /trades/a, /trades/a/edit]`、`/record` → `[/, /record]`、`/settings/accounts` → `[/, /settings, /settings/accounts]`）。ホーム画面のアイコンは `start_url` の `/` で開くので、組み直しは要らない（`[/]`）。**印があるとき（再読み込み・bfcache・前へ / 次へで戻ってきた）は組み直さない**。ブラウザが保っている履歴の並びのまま、今の項目の印からタブと積み重ねの記憶を戻す（二重に積まない）。今の項目が層の段（`back-stack` の印。シートを開いたまま再読み込み）なら、シートは開き直さず、画面に出さずに、層の印が持つ深さ n（たどった説明・重ねたシートで 2 段以上もある）だけ `history.go(-n)` で画面の段へ戻る（層の段に `replaceState` で印を外すだけだと、同じ URL の段が 2 つ並び、戻るが 1 回効かなく見えるため。前へ側に残った層の段は、次に積むときに消える）。それより前に「進む」で層の印を持つ段に入ったとき（URL は同じで、シートは開いていない）は、糊が開いていない層の段と見て、画面に出さずに同じ規則で画面の段へ戻す。**組み直しを履歴に書くのは、利用者の最初の操作（押す・キーを打つ = ユーザーのアクティベーション）のとき**（#127 で決めた）。起動の直後に操作なしで `pushState` すると、Chrome の「操作の無い項目を戻るで飛ばす」仕組みが戻るのボタンだけでなく `history.go` にも効き、直接開いた詳細でホームのタブを押すと、組み直した段を飛ばして前のページまで戻ってしまう（ui:check の V6 で再現した）。書くまでの間も、今の画面の印（タブ・深さ）は組み直した後の形として扱う。**既知の挙動: 直接開いて一度も触らずに戻ると、根やホームを通らずにアプリを出る**（Android の戻る・ブラウザの戻る・iPhone の端からのスワイプのどれでも。罠にはならない側の外れ）。一度でも触った後は組み直した並びで戻る。ログインの門が触る前に置き換えたとき（ログインしていないまま開いた）は組み直しを捨てて 1 段のまま残し、ログインした後の行き先への置き換え（ログインの押下が操作）で組み直す。ログアウト（ログインの画面への置き換え）はホームの段まで戻ってから置き換え、タブの記憶を捨てる（次にログインした利用者にタブ・積み重ねを持ち越さない）。タブは URL で決める（`/trades*` = 取引、`/review*` = 振り返り、`/settings*`・`/glossary` = 設定、ほか = ホーム）。ホームの行から開いた詳細はホームのタブの積み重ねで、その印も state に持つ
6. **全画面のシートの「前の画面」**: ✕（キャンセル）で入力が無いとき・保存の後に戻る先は、今の積み重ねの 1 つ下（`history.back()`）。5 の組み直しで直接開いても下にホーム（編集は詳細）があるので、`appDepth` が 0 になる場合は無くなる。再読み込みでは印の `appDepth` をそのまま使う（ADR-0019 の決定 5・11 への追記）
- `back-stack` との関係: 層の段は今の画面の項目の上に積む（URL は同じ・印は層）。タブの切り替え・画面の移り・組み直しの前に層の段を戻し終え、再読み込みで残った層の段は 5 のとおり画面の段に戻す。層の規則（戻るで 1 つ閉じる・UI で閉じたら糊が数を合わせる・close watcher）は P6・9.3 のまま
7. **広い形と横の形の分割で行を選ぶ**: `/trades/{id}` は置き換え（戻るで 1 件ずつたどらない）

### 9.8 動き

| 場面 | 動き | 作り |

- する: iPhone の端からの戻るのスワイプはブラウザが自前で動かすので、`popstate` の `hasUAVisualTransition` が true のときはこちらの動きを飛ばす（二重にしない）。9.7 の 2・3 の `history.go(-k)` の間の `popstate` も動かさない
- する: View Transitions・`@starting-style`（Safari 17.5 以降）が無いブラウザでは、動きなしで同じ結果にする（`startViewTransition` があるときだけ包む。`ui:check` の 1 状態で、無い場合を確かめる）
- しない: 飾りの動き（P9）。振動（`navigator.vibrate`。iPhone で動かない）

### 9.12 操作の形とボタンの重さ

オーナーの言葉（2026-11-20。モックの記録する画面の左上の「キャンセル」と要約の行の「直す」が、文字だけのリンクの見た目だったことへの指摘）:

> キャンセルの導線がハイパーリンクみたいなテキストなのやばいよ？あぷりのゆーあいちゃうやん

- する: 操作は **押せる形** にする。ボタン（下の 3 段）・チップ・押せる行（行全体が当たりで右に ›）のどれか。当たりは 44px 以上（P8）
- する: 閉じる・キャンセルは、全画面のシートの **左上** に置く（縦・横・広いのどの形でも、シートかパネルの左上）。✕ のアイコンのボタンで、読み上げの名前は「キャンセル」、当たりは 44px 以上。✕ の脇に文字を見せたいときは、枠か面のある 2 番目の重さのボタン（［キャンセル］）にしてよい（置き場は同じ左上）
- する: 「編集」「すべて」「振り返り ›」のような行の中・カードの中の操作は、面のあるボタンかチップにする。または、行全体を押せる行にして右に › を付ける
- する: 文字のリンクの見た目（下線・アクセントの色の文字だけ）は、**文の中で別の場所（用語集など）へ移るときだけ** に使う（P8 の「文の中の用語集のリンクは当たりの例外」と同じ範囲）
- しない: 文字だけのリンクの見た目の操作（「キャンセル」「編集」「すべて見る」「一覧を見る」「‹ 一覧」を本文の文字として置く）
- 言葉: 読み取った欄を書き換える操作は **「編集」**（8.1。「直す」は誤りを正す意味だけ）。モックの要約の行の「直す」は言葉の誤りで、［編集］ と読む
- 数え方（`ui:check`）: 押せる要素（`a`・`button`・`[role=button]`・`[role=link]`）のうち、面の色が親と同じで、枠の線も無く、アイコンも無い（文字だけの）ものを。右の › を擬似要素（`::after`）で描いた押せる行は、› をアイコンとみなして数えない（擬似要素の中身も見る）。これらを「文字のリンクの見た目の操作」と数える。用語集の文の中のリンク（説明の文・用語集の項目の中の言葉）は除く。今の件数は U1 の前に測って EPIC の as-is に入れる
