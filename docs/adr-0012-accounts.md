# ADR-0012: 口座を足し、取引ごとに口座を持つ。既定の口座は読むときに設定から 1 回だけ作る

- 状態: 採用
- 日付: 2026-11-18
- 関連: Issue #47（口座。PR-1 = 円の口座だけ、PR-2 = 通貨と為替）、Issue #59、EPIC #45（縦切り 2）、設計書 4 章・4.2・4.5・4.6・5.1・5.2・7.5・9.2・C41・C43、ADR-0004（記録の API・保存の形・snapshot）、`docs/ui-guidelines.md` P1・R12

## 背景

資金と許容リスクは設定に 1 つだけあった（設計書 4.5「口座は MVP では 1 つ」）。証券口座を分けて使うトレーダーは、口座ごとに資金が違うので、どの口座の資金に対するリスク（%）かが合わないと、過剰リスク（2% 超）の判定が外れる。取引は記録したときの資金・許容リスクを `snapshot` に写して持ち（C36）、判定・R は保存しない。既にある取引と設定の資金を、利用者の操作なしに新しい形へ移す必要がある。

## 決定

1. **口座の文書** = `users/{uid}/accounts/{id}`。`{name, nameKey, capitalYen, riskTolerancePct, capitalHistory: [{valueYen, at}], createdAt, updatedAt}`。銘柄と同じ作り（`nameKey` で名前の重複を 409、名前 1〜40 字、資金は正の数か null、許容リスク 0.5〜3%、資金の履歴は口座ごとに末尾 1,000 件）。並びは名前の順。消す・しまうは作らない。PR-1 の口座はすべて円（通貨の欄を持たない。無い = 円。通貨は PR-2）
2. **API**: `GET / POST /api/accounts`・`GET / PUT /api/accounts/{id}`。ほかの利用者の口座は読む・直すで 404、取引の作成・直しで指せば 400 `accountId notFound`
3. **既定の口座は決まった ID `default`（名前「口座 1」）**。取引の `record.accountId` は任意の欄で、無い = 既定の口座（移す前の取引・口座が 1 つの利用者の取引）。画面は口座が 2 つ以上のときだけ本文に `accountId` を入れる（口座 1 つの利用者の本文は今と同じ）
4. **移し替えは「読む・使うときに無ければ作る」**: 口座を読む・使う API の入口（口座の一覧・1 件・作る・直す、取引の作成・直し）で `accounts/default` が無ければ、`settings/current` を読み、その資金・許容リスク（無ければ 1%）・資金の履歴を写した文書を、**トランザクションの外で、決まった ID の `create`（無いときだけ作る）** で作る。既にあれば（AlreadyExists。ほかの要求が先に作った）作らない。口座を使うトランザクションの中で既定の口座が無いと分かったら、トランザクションを抜けて作ってから 1 回だけやり直す。作ったときだけログ `default_account_created`（設定から写したかの真偽と履歴の件数だけ）を 1 回出す。取引・設定は書き換えない
5. **snapshot の鍵は変えない**: `snapshot.capitalYen`・`snapshot.riskTolerancePct` を「記録したときの、その取引の口座の資金・許容リスク」と読む。`core/record.ts` の `toTradeInput` は変えない。直す（PUT）で本文に `accountId` が無ければ保存済みの口座を保ち、口座を付け替えたときだけ付け替え先の口座の今の値で写し直す（銘柄の付け替え C36 と同じ考え方。両者は独立に効く）。#31 で、付け替えの無い取引も、編集の画面で利用者が「今の値」を選んで保存したとき（PUT の `?snapshot=current`）だけ、取引の口座・銘柄の今の値で写し直せるようにした（設計書 C36）
6. **設定の文書と `GET / PUT /api/settings` の形は変えない**。設定の `capitalYen`・`riskTolerancePct`・`capitalHistory` は移し替えの元として残し、画面はもう読まない・書かない（`performanceUnit` と 403 の確かめは今のまま）

## 選択肢

- **移し替えを、口座を使うトランザクションの中で作る**（計画の最初の案）: エミュレーターで 8 本同時に口座を読むと、読みの競合で再試行を使い切り 500 になった。トランザクションの外で決まった ID の `create` にすれば、競合しても 1 つしかできず、負けた側は「ある」を読むだけになる。採らない
- **起動時に全利用者を一括で移す**: 本番の利用者の文書を一括で走査することになり、起動を遅くする（#60）。新しい利用者は別の道が要る。採らない
- **使い捨てのスクリプトで移す**: 本番を手で書き換える操作が増え、切り戻しと順番の管理が要る。新しい利用者は別の道が要る。採らない
- **snapshot に `account = {...}` を入れ子で持つ**: 既存の取引・fixture・`toTradeInput`・画面の参照を二重に読む必要が出る。PR-1 で足す値が無い。採らない（口座の通貨を写すのは PR-2）
- **設定の資金を消す・API から外す**: 切り戻した前の版が設定の資金を読めなくなる。後の掃除に回す

## 結果

- 口座が 1 つの利用者は、記録の手間も本文も今と同じ（口座の欄は出ない）。口座が 2 つ以上なら、記録する画面で口座を 1 タップで選び、その口座の資金でリスク（%）・過剰リスクが出る
- 既存の取引は書き換えない。移し替えで書くのは `accounts/default` の 1 文書だけで、何度・同時に走っても 1 つ。判定・R は前と同じ snapshot から出るので変わらない
- **GET が書く**: `GET /api/accounts` は既定の口座が無いときだけ 1 回書く。冪等で 1 文書だけなので許容する。API の `GET /api/trades` は書かないが、画面の一覧・詳細・ホームは口座も読むので、移し替えの前に最初に開いたときに既定の口座ができる。口座が読めない（503）と一覧・詳細も開けない（設定の読みと同じ扱い）
- **切り戻し**: 前の版は `accounts` を読まず、残してある `settings/current` を使うので動く。ただし次が起きる（オーナー 1 人・短い間なので許容し、PR 本文にも書く）
  - 切り戻しの間に記録した取引は、設定の資金・許容リスク（移す前の値。この版で口座の資金を直していても、その値ではない）を snapshot に写すので、リスク（%）・過剰リスクの B はその値で出る（表示だけでなく記録の値）
  - 切り戻しの間に設定の画面で直した資金は、もう一度デプロイしても既定の口座に移らない（既定の口座は既にあるので移し替えは走らない）。設定の画面の口座で直し直す
  - 切り戻すまでに `accountId` 付きで記録した取引を前の版で直すと `accountId` が落ち（前の版は知らない欄を保たない）、もう一度デプロイした後は既定の口座の取引として読まれる（snapshot は残るので 1R・リスク（%）・判定は変わらず、口座の付き先だけが既定に戻る）
- 古いキャッシュの画面が設定の資金を直しても口座には効かない（新しい画面に替われば起きない）
- Firestore では既定の口座を取引のトランザクションの外で先に作るので、取引の作成がその後で失敗しても既定の口座は残る（冪等の 1 文書で害は無い。テストの記憶の保存先も同じ順にした）
- 口座の数の上限は置かない（銘柄と同じ）。口座が 4 つ以上なら記録する画面の選び方は選択の欄（P1）

## PR-2 で決めたこと（通貨と為替。2026-11-19・#47 PR-2・#59・設計書 C43）

- **口座の通貨**: 口座の文書に `currency`（ISO 4217 の 3 文字。銘柄の `priceCurrency` と同じ検査）。無い = JPY（PR-1 で作った口座・移し替えで作った「口座 1」。書き換えない）。作るときは既定 JPY で必ず書き、応答はいつも `currency` を返す。直す PUT の `currency` は任意（省くと今のまま = PR-1 の画面のキャッシュが送る本文を 400 にしない）
- **取引の snapshot に `accountCurrency`**: 記録したとき・口座を付け替えたときの口座の通貨を写す（`account_snapshot` が資金・許容リスクと一緒に返す）。無い = JPY（移す前・PR-1 の取引）。口座の通貨を後で直しても記録済みの取引は変わらない（C36 と同じ）
- **金額の鍵の名前は変えない**: `capitalYen`・`statementPnlYen`・`fees[].amountYen`・`capitalHistory[].valueYen` は「口座の通貨の金額」と読む（円の口座では今と同じ円）。鍵を変えると本番の取引・口座・fixture を書き換えるか二重に読む必要が出て、変えないこと（KEEP）と切り戻しを危うくするため。名前と意味のずれは `core/record.ts`・`core/trade.ts` の注釈と設計書 4 章の冒頭に書いた。改名するなら、読むときの写しと一緒に別の Issue にする
- **為替**: 取引の `record.exit.fxRate` を「価格の通貨 1 単位 = 口座の通貨でいくら」と定める。計算の入力の `isJpy` を `priceInAccountCurrency`（価格の通貨 = 口座の通貨。未設定は false）に改名し、式は変えず条件だけを替えた（円の口座では前と同じ真偽 → 移す前の取引の値は同じ）。明細から逆算した為替は C32 の 1R の逆算と同じ条件で出し、見せるだけで保存しない
- **口座の通貨の固定**: 通貨が今と違う PUT で、その口座に取引が 1 件でもあれば 409 `currencyLocked`（文書は変えない）。「取引がある」は保存先の `update_account` のトランザクションの中で、通貨を変えるときだけ遅延で読む（普段の PUT は読みが増えない）。既定の口座は `accountId` の無い取引も数えるため、`record.accountId` だけの射影で取引を流して見る（Firestore は「欄が無い」を問い合わせられない。通貨を直すときだけ）。ほかの口座は `record.accountId ==` の 1 件（単一の欄の等号で自動の索引）
- **同時の記録との競合の窓**: 記録のトランザクションと通貨の直しが同時に走ると、取引のある口座の通貨が変わりうる。取引は snapshot に口座の通貨を写すので、その取引は写した通貨で計算され、数は狂わない。409 は画面の誤操作を防ぐ約束で、数の正しさは snapshot が守る。オーナー 1 人で実害は無い
- **資金の履歴**: 口座の履歴の新しい行にだけ `currency` を書く（通貨を直したときも資金が同じでも 1 行）。設定の履歴（移し替えの元）は今の形のまま（`{valueYen, at}`）
- **明細の読み取り**: 今の読み取りの指示は円の損益を読むので、JPY でない口座では損益・手数料を欄に入れない。口座の通貨で読む指示は自動判定の Issue で測り直しと一緒に
- **本番のデータの移し替え**: 要らない（無い = JPY と読む）。デプロイで本番のデータを書かない
- **切り戻し（PR-1 の版へ）**: PR-1 は口座の `currency`・snapshot の `accountCurrency` を読まないので、すべて円として動く。ただし (1) 切り戻した間に外貨の口座を PR-1 の画面で直すと、PR-1 の `update_account` は文書を作り直すので `currency` が落ちて JPY になる。(2) 付け替えると PR-1 の `account_snapshot` は `accountCurrency` を上書きしないので古い通貨が snapshot に残る。どちらも外貨の口座を作っていなければ起きない。外貨の口座を使い始めたら、切り戻しの前に確かめる
- 選ばなかった案: 鍵の改名 + 読むときの写し（上の理由）、口座の文書に「取引あり」の旗（PR-1 の口座と移す前の取引に旗が無く、結局取引を探す必要がある）、新しい ADR（同じ決定の続きなので、ここに足した）
