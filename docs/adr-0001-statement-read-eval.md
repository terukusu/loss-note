# ADR-0001: 決済明細の読み取りを測る道具

- 状態: 採用
- 日付: 2026-11-17
- 関連: Issue #14（spike）、EPIC #10（終了条件 8・10・11）、#11（読み取りの入口）、#15（記録する画面）、設計書 1.1・7.5・8.2・13.2・13.4、option-simulator の ADR-0005・ADR-0009

## 背景

縦切り 1 の「事後に 1 回・30 秒で記録する」入力は、決済明細のスクリーンショットから、計画と実行を比べるのに要る事実（建てた向き・建てた価格・決済の価格・損益）を AI で読み取れることに寄りかかっています。オーナーが使っている明細の形で読めるか、決済の注文の種類（逆指値）が明細に写っているか、何秒かかるかは測っていませんでした。#11 が満たすべき閾値（EPIC #10 の終了条件 8）を決めるには、実測と、実データを使わずに精度を確かめ直す手段が要ります。

## 決定

1. **独立した道具のプロジェクト `tools/statement-eval/`**（Python 3.13・uv）に置く。アプリ（`api/`）の依存・lock に Pillow や AI の SDK を入れない。確認コマンドと CI は lint とテストだけを回す
2. **AI は Claude Agent SDK（`claude-agent-sdk`）1 本で呼ぶ**。資格情報（API キー / サブスクの OAuth トークン）はまだ決まっておらず、Agent SDK ならどちらも同じ経路で扱える（サブスクの OAuth トークンは Messages API の直接呼び出しで 429 になる。option-simulator の ADR-0005）。SDK は依存グループ `ai` に入れ、手元で評価を回すときだけ入れる。子（同梱の CLI）の環境は許可リスト方式にする（CLI が動くのに要る変数 = PATH・HOME・言語・一時ディレクトリ・証明書・プロキシと、選んだ資格情報だけを渡し、ほかの親の変数は空で上書きする。SDK は親の環境に設定を重ねて子を起動するため、渡さない変数は空にして消す）。組み込みのツール・設定ファイル・テレメトリを切り、turn 1・ツール 1 本（フックで実行せずに入力だけを受け取る）にする
3. **読み取りの結果は形の決まった値だけ**（ツール `report_statement` の入力。知らない欄・列挙に無い値は結果全体を捨てる。銘柄の名前は文字の種類を絞る）。氏名・口座番号などの欄は形に無い
4. **向きは書かれた言葉のまま返させ、建てた向きへの直しはコードで行う**。明細の形によって向きの意味が違う（形 1 の「売約定 / 買約定」は建玉そのものの向き、形 2 の「決済売 / 決済買」は決済の向き）ので、AI には `side_written`（buy / sell）と `side_of`（position / close）を返させ、`score.opened_side` が L / S に直す。手数料も欄ごとの配列で返させ、合計はコードが出す
5. **採点の規則は `score.py` の純関数**に置き、Issue #14 の採点の例 #1〜#16 と #7b をテストで固定する。#11 の閾値の検査も同じ規則を使う
6. **合成の明細（架空の値の画像と正解）をコミットする**。#11 が同じ入力で閾値を満たすかを測れるようにするため（フォントや描画の環境の違いで入力が変わらない）。正解は値の表から機械的に出し、作り直しても同じになることをテストで確かめる
7. **評価の出力に値を出さない**。要約は件数・割合・秒数・費用・モデル名・欄名・場面 ID だけを持つ型（`report.Summary`）からしか作らず、偽の読み取りで回した出力に値の文字列が無いこともテストで確かめる。実物の画像と正解は `data/local/`（gitignore）にだけ置き、CLI の一時ファイルもその下に作って消す

## 選択肢

- **Messages API を直接呼ぶ（`anthropic` SDK）**: CLI の起動（約 1 秒）が秒数に入らず速い。ただしサブスクの OAuth トークンでは使えず、資格情報が決まるまで送り口が 2 本になる。#11 でどちらにするかは #11 で決める（この道具の秒数は保守側に出る）
- **HTML を headless ブラウザで描いて画像にする**: 見た目は実物に近づくが、ブラウザの取得という重い依存が増える。Pillow で表を描けば形（欄の並び・言葉・日時の書き方）は再現できる
- **画像を評価のたびに作る**: コミットが軽くなるが、フォントの版で入力が変わり、#11 と同じ入力で比べられなくなる

## 結果

- 秒数に CLI の起動が含まれる（要約の限界に書く）
- 合成の明細は形への対応だけを測り、実物の画質や撮り方での精度は測らない（option-simulator の ADR-0009 と同じ限界）。実物は手元でだけ、件数・割合・秒数だけを残す
- 実測の数字（欄ごとの割合・秒数・費用）はこの ADR に書かず、Issue #14 の結果のコメントを正とする
