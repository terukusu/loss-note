# 画面の原則（UI / UX ガイドライン）

loss-note の画面が沿う原則と規則、そのよりどころにした世の中のベストプラクティス、画面を触る PR のチェックリスト。

> Issue #3（画面のデザインの土台）で作成（2026-11-17）。option-simulator の `docs/ui-guidelines.md` の構成を移植し、原則を loss-note 向けに作り直した。価格・損益の例はすべて架空。

---

## 1. はじめに

**目的**: 画面を足す・直すときに「このアプリではこうする」を 1 か所で引けるようにする。

**読む人**: 画面を触る開発者、実装・レビューをする AI のエージェント、PR をレビューする人。初めて読む人向けに書く。

**ほかの文書との関係**:

| 文書 | 役割 |
|---|---|
| このガイドライン | **原則と規則**（なぜ・こうする / こうしない・何で確かめるか）。画面の中身が変わっても変わりにくいもの |
| `docs/design.md` | **設計書**（考え方・記録の形・判定・画面の一覧）。規則の出どころとして節番号で参照する（9.1 からこの文書へリンクしている） |
| `CLAUDE.md` | リポジトリの作りと確認の手順 |

食い違ったら、このガイドラインを直すか設計書を直すかを PR で決める（黙ってどちらかに合わせない）。

**このアプリの前提**: 裁量トレードの損失ノート。トレーダーが決済の後に 1 回、スマホで素早く記録し（設計書 7.5）、PC で広く振り返る（設計書 9.1）。物差しは「勝ったか」ではなく「計画どおりだったか」（設計書 1.1）。動機は「入力が面倒で記録が続かない」（設計書 K10）なので、**記録の手間を減らすことと、開きたくなる見た目は、機能と同じ重さ** で扱う（設計書 K2）。

## 3. 原則ごとの規則

各行は「こうする / こうしない」とアプリの中の実例。**検査** は機械で確かめているもの（`npm test` の vitest、`npm run ui:check`）。検査の無い規則は目で確かめる（6 章）。

### P1 記録の手間の予算

- する: 記録の画面は「スクショを貼る → LC と一言 → 3 つのタップ」の順に縦に並べ、主の動作（[記録する]）は 1 つ。スマホでは画面の下半分（親指の届く所）に押すものを寄せる
- する: 入力の既定値を置き、手で打つ欄を増やさない（設計書 C17・C19）。2〜3 択は `Segment`（タップ 1 回）で、プルダウンにしない
- する: 4 択以上（決済の理由など）は 1 行の `select`（`.select`。当たり 44px・文字 16px）。任意の欄は `<details>`（「ほかの欄（任意）」）に畳み、主の流れを短くする
- する: 主の動作（[記録する]）は幅 720px 未満で下部の行き先の上に貼り付け（sticky）、帯は 1 段（1 行の状態の文 + [記録する]）で幅 360px で 64px 以下にする（入力中の欄を隠さない。#33）。幅 720px 未満は幅いっぱい・不透明で下部の行き先に付け、下の文字を透かさない。状態の文は 360px で切れない短さにする（長い知らせは判定の枠の案内に全文で）。保存の失敗の知らせ（[ログインし直す] を含む）が出ている間だけ伸びてよい。保存の後のボタン 1 つは帯に包まない
- する: 押せない理由は、帯には数（「あと 7 欄」「誤り 1 欄」）か一言（「明細を読み取っています」）だけ、欄の名前は判定の枠の案内に文で出し、[記録する] の読み上げの説明（`aria-describedby`）に結ぶ（色だけに頼らない）。そろったら帯に判定の要約を文字だけで出す（バッジ・色を使わない）
- する: 判定の枠は 3 つのタップ（見出し「決済までの振る舞い」）の枠のすぐ後に置き、タップの後に判定が出ていれば判定のバッジと R の行を見える範囲へ寄せる（`scrollIntoView` の `nearest`。見えていれば動かさない。押したタップを上へ隠さない。動きを減らす設定では動きを付けない。フォーカスは動かさない）
- する: 開いた直後の 1 画面に [スクショを選ぶ] と銘柄の欄が入るようにする（画面の説明文を付けない。送る前の注意は 3 つの中身を畳まずに 3 行以下、補足は「詳しく」に畳む。PC だけの貼り付けの案内は指で触る端末では出さない）
- する: 行き先（ホーム・記録する・一覧・設定）は幅 720px 未満で画面の下に固定し、どの画面からも 1 タップ
- しない: 記録の途中に確認・説明のダイアログを挟む。任意の欄を必須にする
- 検査: `ui:check` の V6（幅 360 の全画面から 4 つの行き先へ 1 タップ）、記録する画面の R1〜R10（R10 = 明細を貼って打つ 2・選ぶ 3 で判定まで）、帯の高さと状態の文の行数・切れ（幅 360 の全状態。`--inject-clip` の帯の見本で見逃さないことを確かめられる）、R11（判定が見える範囲の外で最後のタップを座標で押す → アプリが寄せ、判定のバッジと R が見える）・R12（開いた直後の 1 画面・注意 3 行以下・全長 2,550px 以下）。`record-view.test.tsx`「帯には数、名前は判定の枠」。30 秒の人の実測は [`record-timing-check.md`](record-timing-check.md)

### P2 色は規律を表す

- する: 判定の段のトークンは `--tier-{plan,break,worst,neutral}-{ink,bg,line}`。段と判定の対応は `ui/src/lib/badge.ts` の 1 か所（A・計画どおりの勝ち = 計画どおり、B・危ない勝ち = 崩れ、C = 極悪、判定なし = 中立）
- する: 強調の色（`--accent`）は操作（主のボタン・今いる画面・フォーカス）にだけ使い、判定の段の色と混ぜない
- しない: 損益・R の正負で文字や面の色を変える。判定の段の色を判定以外（入力の誤りなど）に使う（入力の誤りは `--danger`）
- する: 判定の枠の LC の物差し（#34。`components/Ruler.tsx`）は色を足さない。線・点・文字は文字と線のトークン（`--ink*`・`--line*`）だけで、点の種類（イン・決めた LC・動かした LC・決済・TP）は形で見分ける（判定の段の色も使わない。窓・滑りの A で越えた区間が「計画どおり」の色にならないように）
- 検査: `badge.test.ts`、`cssTokens.test.ts`「段の色が互いに違う」「バッジの段のクラスは段のトークンだけ」「物差しの CSS は文字・線・段のトークンだけ」

### P3 数字は符号と単位で読ませる

- する: R は小数 1 桁 + `R`、円は 1 円単位で 3 桁区切り + `円`。丸めは 0 から遠い側（四捨五入）。負の符号は `−`（U+2212）、ちょうど 0 は `±`、丸めて 0 になっても元の符号を残す（`−0.0R`。設計書 C29）
- する: 表示は `ui/src/lib/format.ts` の `formatR` / `formatYen` だけを通す（`RNum` / `YenNum` の部品）。本文の書体の桁の揃う数字（`tabular-nums`。等幅の書体にしない）で、大きさは `num--lg`（22px）/ `num--xl`（36px）。数値の入力欄も同じ。等幅（`--mono`）は ID・コードだけ（`.mono`）
- する: 資金のような符号の無い金額（損益ではないもの）は `formatAmountYen`（`1,000,000円`。+ を付けない）で出す（Issue #5）
- する: 判定の枠の R・リスク・損益はラベルの上端を揃える。値が出ないときは場所に「—」を出し、理由は数の段の下の注記に 1 回だけ（一覧と同じ形「リスクの「—」: 損益（円）を入れると出ます」）。LC が無い取引は R・リスクの段を出さず「LC が無いので R・リスクは出ません」の 1 行にする。ホーム・一覧の「—」の理由は一覧の下の脚注に 1 回だけ
- しない: 数字の部品（`.num`）に色を付ける。ハイフン（-）を負の符号に使う。R・円以外の番号に `.num` を使う（ID・コードは `.mono`）
- しない: `.num` を色のある親の中に置く（`.num` は色を宣言せず親の文字の色を継ぐので、判定のバッジ（`.badge`）・誤りの文（`.field__error`）の中に置くと段の色・誤りの色が付いてしまう）。バッジ・誤りの文と並べるときは、数字をその外に出す
- 検査: `format.test.ts`、`cssTokens.test.ts`「数字の部品は色を持たない」「本文の書体の桁揃え」、`ui:check` の R13（大きな R の計算後の大きさ 36px・等幅でない・ラベルの上端の差 1px 以内）

### P4 取り消せるなら確認しない

- する: 消すは即実行 + トーストの [元に戻す]（部品 `components/Toast.tsx`・`lib/deletions.ts`。#9。アプリの殻に 1 つで、画面を移っても取り消せる。取り消しの時間は 8 秒、トーストにフォーカス・ポインタがある間は止める。[消す] の後は [元に戻す] にフォーカス。トーストにはどの取引かを出す。ADR-0007）。直すは保存の前に判定の変化を見せる明示の保存で受ける（直した後の [元に戻す] は別 Issue）。戻せない操作（アカウントの削除）だけ確認する
- する: 誘惑ガード（保有中に LC を下げる・時間足を長くする。設計書 7.1）は、意図して 1 手を足す唯一の場所
- しない: 「本当に削除しますか？」のダイアログ
- 検査: `ui:check` の T-X1・T-X2、`tests/ui/deletions.test.ts`・`trade-screens-rules.test.ts`（ダイアログの不在）

### P5 値と警告は見える、色だけに頼らない

- する: 判定のバッジは文字（ラベル）・段ごとに形の違う記号（計画どおり = ○、崩れ = △、極悪 = ×、中立 = −。SVG で `aria-hidden`）・段の色の 3 つ。読み上げはラベルの文字
- する: 入力の誤りは枠の色に加えて文言を出す（`NumberField` の `error`。`aria-invalid`・`aria-describedby`）
- する: 選ばれた選択肢は面の濃さ・枠・文字の前のチェックの記号で示す（ネイティブの radio の checked）
- する: 判定の枠は同じ説明を 2 回出さない。「過剰リスクは見ていない」は理由の一覧から分けた注記の 1 行にする（文言は理由のまま）。C の添え書きと同じ理由（LC を決めずに入った）は箇条に重ねない。判定の段の色は地の淡い色・左の帯・バッジまで（枠の線は他のカードと同じ）
- しない: 記号に絵文字を使う。値・警告を ⓘ の中に隠す
- する: 詳細の 3 つのタップの答え（判定の枠の中の札）で計画から外れた答え（決めていない・下げた / 上げた・長い足へ、または時間足がチャートから判定に効いた）は、札の枠を本文の色で太くし、形の印（`Icon` の `offPlan`。角の丸い四角に感嘆の形）・見える「外れ」の文字・読み上げの「計画から外れた」で示す。判定の記号（○ △ × −）を流用しない（段の記号は判定だけの意味に保つ。#34）。内輪の言い方（「申告」「判定に使用」）を出さず、利用者の答えは「あなたの答え」と書く
- する: 物差しは区間を線の太さと種類で見分ける（決めた LC〜動かした LC = 破線の太線、決済が LC を越えた区間 = 実線の太線、入る前に決めていない LC = 破線の縦線と「−1R（後から）」）。同じ価格の点が重なって消えないよう、動かした LC は線の上側に置く
- する: 物差しの図（SVG）は `aria-hidden` にし、同じ点を文字の一覧（「LC の物差し」という名前の `ul`）で読ませる
- 検査: `badge.test.ts`（記号は `aria-hidden`・`currentColor`）、`ruler-screens.test.tsx`（物差しの図・一覧・5 種類の形・タップの答えの印）、`ui:check` の T-D3

### P6 戻るで迷わない

- する: 画面ごとの URL（`/`・`/record`・`/trades`・`/trades/<id>`・`/trades/<id>/edit`・`/settings`・`/login`。開発の時だけ `/dev/parts`）。行き来は History API（ADR-0002）。アプリの中のリンクは `Link`（左クリックだけを横取りし、新しいタブで開く等はブラウザに任せる）
- する: 知らない URL は履歴を **置き換えて** ホームへ（戻るで知らない URL に戻らない）。詳細の ID が無い取引は、詳細の画面に「この取引は見つかりません」と一覧へのリンク
- する: 画面が変わったら見出し（`h1`、`tabindex="-1"`）にフォーカスを移し（フォーカスでスクロールさせない）、`document.title` を「<画面の名前> — loss-note」にする
- する: 新しい画面へ進んだ（push）ときだけ先頭へスクロールし、戻る・進むではブラウザが元の位置を戻す（`history.scrollRestoration` の既定）。一覧をスクロールして詳細を開き、戻ったら同じ位置
- しない: ハッシュ（`#/trades`）の URL。画面の状態を端末に保存して URL と食い違わせる
- 検査: `routes.test.ts`（V1〜V6・`safeNext`・行き来の種類 push / pop）、`ui:check` の V1〜V6・S1（長い画面でスクロール → 進む → 先頭、戻る → 元の位置）

### P7 どの幅でも崩れない

- する: 幅の段は 720px の 1 つ（未満 = 下部の行き先、以上 = 上の帯の行き先）。中身の幅は `--content-max`
- する: 数字・ボタン・バッジ・セグメントの項目は `white-space: nowrap`。3 択のセグメントの文言は幅 360px で入る短さ（4〜5 字）にする（入らなければ `ui:check` の「部品のはみ出し」が拾う）。入らないものは説明の文だけ折り返す。狭い幅で入らない補助の情報は隠す（部品の見本のバッジ一覧の段の名前）
- する: 枠（四辺の線か、親と違う面の色を持つ箱。入力欄・ボタン・セグメントの項目・画像・canvas を含む）の入れ子は 2 段まで（面の上の枠 → その中の入力の部品）。カードの中では内枠を作らず、区切りは 1 辺の線か余白で示す（#33）
- しない: 幅ごとに別の画面を作る。スマホだけ機能を落とす。カード → 内枠 → 部品の 3 段の入れ子
- 検査: `ui:check`（枠の入れ子 3 段以上 0 件（擬似要素・影・輪郭は数えない。`--inject-clip` の入れ子の見本で見逃さないことを確かめられる）、横スクロール 0px、折り返さない部品（ボタン・セグメント・バッジ・行き先など）のはみ出し 0 件 = 部品の中で文字が横・縦に箱を超える・部品ごと親の左右を超える・overflow の祖先で切られる。`--inject-wide 400` と `--inject-clip` で検査が崩れを見逃さないことを確かめられる）

### P8 指でもキーでも読み上げでも使える

- する: 押せるもの（リンク・ボタン・選択肢・入力欄・行き先）の当たりは 44×44px 以上（`--tap`）。セグメントの radio は項目の全面に透明で重ね、当たり = 項目
- する: フォーカスの輪は `:focus-visible` で `--focus`。数値の入力欄は文字 16px 以上（iOS の自動拡大を避ける）
- する: 入力の部品（入力欄・セグメント）の枠（`--field-line`）とフォーカスの輪（`--focus`）は、面に対して両テーマで 3:1 以上（WCAG 1.4.11）
- する: 選んだ選択肢は面の濃さ・強調の枠・文字の前のチェックの記号の 3 つで示す（遠目・屋外でも分かる。色だけに頼らない。記号は項目の中に収め、文字に重ねない）
- する: 文字のトークン（`--ink`・`--ink-2`・`--ink-3`）× 面（`--bg`・`--s1`〜`--s3`）、`--on-accent` × `--accent`、バッジの文字 × 地、`--danger` × 面は両テーマで 4.5:1 以上
- しない: `div` に `onClick` だけ付けてボタンにする。記号だけのボタンに名前を付けない
- 検査: `ui:check`（幅 360 の当たり < 44 の件数）、`cssTokens.test.ts` (d)・「入力の部品の枠とフォーカスの輪は 3:1」

### P9 速く、動きは因果の分だけ

- する: 動き（押した手応え・面の色の切り替え）は `--dur-fast` / `--dur-base` と `--ease` だけで書く。`prefers-reduced-motion: reduce` ではトークンを 0s にする
- しない: 飾りのアニメーション（浮き沈み・跳ねる）。ms の直書き
- 検査: 目で（6 章）

### P10 利用者の言葉

- する: 相場の言葉（LC・TP・イン・建てる・玉・枚・ロング / ショート）はそのまま。判定はオーナーの言葉（A いい損失 / B 悪い損失 / C 極悪な損失 / 計画どおりの勝ち / 危ない勝ち）
- しない: 開発中の合言葉・内部の識別子（tier・grade・route など）を画面に出す
- 検査: 目で（6 章）

### P11 安全な作り

- する: スタイルはクラスと `data-*` / ARIA 属性だけで切り替える。テーマは `<html data-theme>`（`applyTheme`）。ビルドの `index.html` はインラインの script / style・style 属性・外部 URL を持たない
- する: 画面から API へは `/api/...`（同一オリジン）だけで、`ui/src/auth/session.ts` の `api` を通す（ログイン中の ID トークンを付け、ログインしていなければ送らない）。Firestore・Storage の SDK を画面で読み込まない（firebase は `firebase/app`・`firebase/auth` だけ）
- する: ログインできないときは決まった文言だけを出し（「ログインのサービスにつながりません」など）、コード・例外の本文を出さない。白い画面にしない（ADR-0003）
- する: 画像のプレビューは canvas に描く（決済明細の読み取り。#15）。object URL・data URL を作らない（CSP の img-src に `blob:`・`data:` を足さない）
- しない: `innerHTML` などの HTML の文字列を DOM に入れる API、JSX の `style`、`.style` の書き換え。外部のフォント・CDN・画像を読む。`createObjectURL`・`toDataURL`・`FileReader`
- 検査: `csp-check.sh`、`source-rules.test.ts`（自己テスト付き。object URL・data URL の規則は #15 の AC-13）、`cssTokens.test.ts`「url() も @import も書かない」

### P12 見た目はトークンで

- する: `tokens.css` は「テーマに依らない `:root`（文字・余白・角丸・動き・大きさ）」と「テーマの 2 つの定義（`:root, :root[data-theme="dark"]` = 既定のダーク、`:root[data-theme="light"]`）」だけ。色・影の値は 2 つの定義の中にだけ書き、名前の組をそろえる
- する: 部品の CSS（`components.css`）・枠の CSS（`layout.css`）は `var(--…)` と、トークン同士の `color-mix()` だけで色を書く。TSX はクラス名だけを持ち、見た目の値を持たない
- する: 角丸は `--radius-lg` 12px・`--radius-md` 8px・`--radius-sm` 6px と丸い形の `--radius-pill` だけ。部品の CSS に px の角丸を直書きしない（#33）
- する: テーマは OS の設定で選ばない（既定はダーク。選んだテーマは端末に記憶）
- する: 開発の時だけの部品の見本の CSS は `ui/src/pages/dev/parts.css` に置き、見本の画面からだけ読み込む（本番の CSS に入れない）
- 検査: `cssTokens.test.ts` (a)(b)(c)「prefers-color-scheme を使わない」「TSX に色の直書きが無い」「角丸のトークンと直書き 0 件」

## 7. 決めたこと

1. **当たりの最小は 44×44px**（Issue #3 の仮定。option-simulator はスマホの記号ボタン 32px）。記録はスマホで素早く 3 つのタップを押すので、押し間違いのほうが高くつく
2. **色は規律、数字は無色**（設計書 C34。オーナーの確かめで違えば戻す。トークンの差し替えで戻せる）
3. **画面の検査は手元で流し、出力を PR に貼る**（CI に入れるのはブラウザとエミュレーターの費用を決める後段）
4. **見た目の値（色・文字・余白・角丸・影）はトークンと部品の CSS に閉じ込める**。部品の DOM の形・クラス名・ARIA はロジックの側の約束として固定し、見た目の作り直しは CSS の差し替えで済ませる
