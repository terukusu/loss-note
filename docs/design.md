## 1. なぜ作るか

裁量トレードで最も大切なのは **損失のコントロール**。「エントリーの根拠が崩れた」と判断できる状態になったときに決済できていて、かつ損失が許容範囲（資金の 1〜2%）に収まっていること。

それには、ポジションを持つ時点で次の 4 つを決めておく必要がある。

1. 明確な **エントリーの根拠**
2. その根拠が **崩れる条件 = LC**（金額ではなく、思惑が外れたと確認できる価格）
3. **TP**（エントリー時の根拠からの推定でよい）
4. LC での損失が資金の 1〜2% に収まる **数量**

loss-note は、それが **できているかを振り返り、客観視し、心理的な影響を排除できるようになるための道具**。

### 1.1 このアプリの考え方（設計の芯）

0. **記録が続くことが、すべての前提**（K10）。オーナーのシートは、良い列を足しても入力が重くて運用されなくなった（○ / × と感情の列は非表示のまま）。書くのが面倒なら続かず、続かなければ振り返りも規律も生まれない。そこで **記録の手間の予算** を決め、それを超える機能は作らない
   - 記録は **事後に 1 回**（K12）: 決済明細と根拠の足のチャートのスクショを貼る + LC と崩れの条件の一言 + 3 つのタップ（LC を入る前に決めていたか・LC を動かしたか・時間足を変えたか）。**30 秒以内**、手で打つのは LC と一言だけ
   - 新しい機能が入力を 1 つでも増やすなら、どこかで減らすか任意の項目にする。必須の項目を足すのは予算と引き換え
1. **良し悪しの物差しは「計画どおりだったか」**。勝ったか負けたかではない。負けても計画どおりならいい取引、勝っても計画外なら危ない取引
2. **規律が崩れるのは保有中**。後から振り返るだけでは遅い。崩れそうな瞬間（LC を動かす・時間足を変える・負けの直後に入る）に、入る前の自分の言葉を突きつける（7 章）
3. **お金を見ると心が動く**。成績は R（計画のリスクの何倍か）で見せ、円は必要なときだけ出す
4. **振り返りは行動に戻す**。気づきを「自分ルール」に昇格させ、次の計画の入力に出す。書いて終わりにしない

## 2. スコープ

### 2.1 MVP と縦切り

| 縦切り | 中身 | 終わったと言える状態 |
|---|---|---|
| 1. 手元で回る | **事後の 1 回の記録**（7.5）: 決済明細のスクショの読み取り → 根拠の足のチャート・LC・一言・3 つのタップ → 判定・理由・R。手での入力（スクショなし）、見送り、一覧と詳細、設定（資金・許容リスク・銘柄）。SPA + API + Firestore / Auth / Storage のエミュレーター | 手元で 1 人の利用者が、架空の決済明細とチャートから 30 秒以内に記録でき、オーナーが架空の取引で判定に納得する |
| 2. 本番で回る | 専用の GCP プロジェクト、Terraform、ログイン、デプロイ、オーナーのデータの取り込み | オーナーが本番で毎日の記録に使える |
| 3. 気づきと集計 | 規律の指標、規律コストの曲線（6.2）、気づき → 自分ルール（7.3）、ティルトの停止条件（7.2）、入る前の計画（任意）と誘惑ガード（7.1・7.4、C16） | オーナーが「どの崩れ方でいくら失ったか」を見て、自分ルールを 1 つ作れる |
| 4. AI の振り返り | 負けの直後の AI の聞き取り、期間の振り返り、言い訳の言葉の検知（8 章） | AI が根拠つきで規律の崩れのパターンを指摘し、気づきに採用される |

各縦切りが EPIC になる。縦切りを終えるたびに、オーナーが使って次の 3 つに答える（答えは件数と場面の要約だけ残す）。縦切り 1 は手元で触って答え、1〜2 週間続けて使う確かめは縦切り 2 から（C25）。

1. 取引のたびに記録できたか（記録した件数 / 実際の取引の件数）。できなかった取引は、なぜできなかったか
2. 判定に違和感があった取引はあったか。どんな場面か（場面は 5.6 の例の表に足す）
3. 画面を見て、次の取引で変えたことはあったか

### 2.2 受け入れ基準（AC。縦切りの EPIC で細かくする）

- AC1: LC を入れた時点で、資金に対するリスク（%）がその場で出る（入る前の記録なら、許容リスクに収まる最大の数量も出す）
- AC2: 事後の 3 つのタップ（LC を入る前に決めていたか・LC を動かしたか・時間足を変えたか）から判定される。決済明細に注文の種類が写っていれば、それも判定の理由（証拠）に使う（C26）。入る前に記録した取引では、保有中の変更の履歴からも判定される（縦切り 3）
- AC3: 決済すると、5.3・5.4 の規則で判定（A / B / C、計画どおりの勝ち / 危ない勝ち）と理由と R 倍数が出る。5.6 の例の表のすべての行がテストで通る
- AC4: 見送りを 1 タップで記録でき、一覧・集計で取引と区別される（縦切り 3。C24）
- AC5: 利用者は自分の記録だけを読み書きできる（他の利用者の記録は API が返さない。テストで固定する）
- AC6: 幅 360px から PC まで、横スクロールなしで使える
- AC7: 記録の手間の予算（1.1 の 0）に収まる。決済明細と根拠のチャートを貼り、LC と崩れの条件を入れ、3 つのタップを選べば、判定まで残る（ほかの欄は読み取りか任意）

### 2.3 スコープ外（MVP では作らない）

- 課金（K5）
- 証券会社・取引所との連携（約定の自動取り込み）。手入力が前提
- 価格・為替の自動取得（為替は手入力。銘柄の価格の通貨が口座の通貨と同じなら 1。C43）
- 部分決済（決済は 1 回。分けたいときは別の取引として記録する）。買い増し・ナンピンは扱う（C5）
- チームでの共有・他の利用者の記録の閲覧
- スマホのネイティブアプリ（PWA は後段）

## 3. 用語

相場の言葉はそのまま使う。判定の名前はオーナーの言葉を使う（C9）。

| 言葉 | 意味 |
|---|---|
| 計画 | ポジションを持つ前に決めること。根拠・時間足・崩れの条件・LC・TP・数量・許容リスク |
| 根拠 | なぜここで入るのか。文章 + セットアップのタグ + チャート |
| 時間足 | 根拠にした足（1 分足〜月足）。計画の一部で、保有中に長い足へ変えると B（K9） |
| 崩れの条件 | 根拠が崩れたと判断できる状態の説明。LC はこの条件を価格にしたもの |
| LC の根拠 | LC の価格をどう決めたか: チャートの根拠が崩れる価格 / 金額から決めた（C3） |
| 資金 | リスクの分母。利用者が設定する口座の資金。取引ごとに、計画した時点の値を写して持つ |
| 許容リスク | 1 取引で失ってよい資金の割合（既定 1%） |
| 1R | 計画のリスク（円）= `|イン − LC| × 数量 × 乗数 × 為替`。買い増しがあれば各エントリーの合計 |
| R 倍数 | 実際の損益 ÷ 1R。計画どおりの LC なら −1R 前後 |
| いい損失（A）/ 悪い損失（B）/ 極悪な損失（C） | 負けの判定（5.3） |
| 計画どおりの勝ち / 危ない勝ち | 勝ちの判定（5.4） |
| 規律コスト | B・C の負けと危ない勝ちで、計画どおりなら避けられた損失の合計（6.2） |
| 自分ルール | 気づきから昇格させた、次の計画に効かせるルール（7.3） |
| 見送り | 計画を立てた（または入りたくなった）が、入らなかった取引 |

## 4. 記録の形（データ）

利用者ごとに分ける（`users/{uid}/...`）。計算に要る値は口座の通貨（円の口座なら円）と銘柄の価格の単位で持ち、表示用の丸めはしない。金額の鍵の名前は歴史的に `…Yen`（`capitalYen`・`statementPnlYen`・`fees[].amountYen`・`capitalHistory[].valueYen`）のままで、外貨の口座ではその通貨の金額と読む（C43）。

保存した記録から計算の入力を組み立てる（判定・R は保存しない。`core/record.ts` の `toTradeInput`）。取引は記録したときの、その取引の口座の資金・許容リスクと銘柄の値（乗数・数量の刻み・価格の通貨・原資産の種類・商品の形）を写して持ち、後で口座・銘柄を直しても変わらない（C36・C41。ADR-0004・ADR-0012）。

### 4.1 銘柄（Instrument）

| 項目 | 例（架空） | 備考 |
|---|---|---|
| 名前 | `US30` | |
| 原資産 | `日経225` | 先物・オプションのときの元の指数・商品（C28）。それ以外は名前と同じ |
| 原資産の種類 | 株価指数 / FX / 商品 / 仮想通貨 / 株式 / その他 | 集計の切り口（6.1）。日経225 の先物もオプションも「株価指数」 |
| 商品の形 | 現物・CFD / 先物 / オプション | 集計の切り口（6.1）。先物・オプションは原資産 + 商品の形で 1 つの銘柄にする（限月・P / C・行使価格は取引の欄。C28） |
| 価格の通貨 | `USD` | 口座の通貨と同じなら為替は 1 で固定。違えば取引に為替の欄（任意）を出す。空 = 未設定（口座の通貨と同じとみなさず、為替の欄も出さない。C43） |

### 4.6 口座（Account。C41・#47・ADR-0012）

| 項目 | 例（架空） | 備考 |
|---|---|---|
| 名前 | `口座 A` | 1〜40 字。利用者の中で重複しない（銘柄と同じ同一視） |
| 通貨 | `JPY` | 口座の通貨（ISO 4217 の 3 文字。既定 JPY・無い = JPY）。その口座に取引が 1 件でもあれば変えられない（C43） |
| 資金 | `1,000,000` 円 | 口座の通貨（円の口座は整数・外貨の口座は小数 2 桁まで）。未設定（空）でもよい（リスク（%）が出ない。C33）。変更の履歴つき（口座ごと。履歴の行は #47 PR-2 からその行の通貨を持つ。通貨を直したときも 1 行。月初に見直しを促すのは縦切り 3） |
| 許容リスク | `1` % | 既定 1%、0.5〜3%、2% 超は警告（C8） |

- 保存は `users/{uid}/accounts/{id}`。#47 PR-1 で作った口座・移し替えで作った口座には通貨の欄が無い（= JPY。書き換えない）。消す・しまうは作らない
- 通貨を変えるのは取引の無い間だけ（取引があるかは通貨を変える PUT のときだけ探す。既定の口座は `accountId` の無い取引も数える）。記録と通貨の直しが同時に走ると、取引のある口座の通貨が変わる窓は残るが、取引は snapshot に口座の通貨を写すので計算は狂わない（ADR-0012）
- **既定の口座**: 決まった ID `default`・名前「口座 1」。口座を読む・使う API の入口で無ければ、設定の資金・許容リスク（無ければ 1%）・資金の履歴を写して 1 回だけ作る（移し替え。トランザクションの外で決まった ID の create。何度・同時に走っても 1 つ。取引・設定は書き換えない）
- 取引は口座を 1 つ指す（`record.accountId`。無い = 既定の口座）。口座を付け替えたときだけ、付け替え先の口座の今の資金・許容リスクで写し直す（C36 の銘柄と同じ）。同じ口座のままでも、編集の画面で「今の値」を選んで保存すれば今の値で写し直す（C36・#31）
- 口座が 1 つなら、記録する・直す画面に口座の欄を出さない（記録の手間を増やさない）。2〜3 は Segment（項目は名前の長さに合わせた幅。長い名前は「…」）、4 以上は選択の欄（`docs/ui-guidelines.md` P1）
- **明細の覚え**（#66・C45・ADR-0017）: 記録する画面の口座の既定は前回の口座（#47 R4）だが、貼った明細の特徴の鍵で前に記録した口座があれば（口座 2 つ以上・今の一覧にある・本人がまだ選んでいない）、その口座を選ぶ。覚えは `users/{uid}/statement_profiles/{鍵}` = `{accountId, updatedAt}` だけ（会社の名前・口座番号・読み取りの値は持たない）。口座を消す機能は無いので、覚えの口座が一覧に無いのは手でデータを消したときだけ（そのときは提案しない）

## 5. 計算と判定

計算はすべて **純関数**（DOM・通信・現在時刻に依存しない）。規則は TypeScript の純関数を正とし、API が保存・集計で使う場合は同じ例の表（5.6）を Python でも通す。

### 5.1 損益と R

- 符号 `s` = L なら +1、S なら −1
- 金額は口座の通貨（円の口座なら円。C43）。為替 = 銘柄の価格の通貨 1 単位 = 口座の通貨でいくら。価格の通貨 = 口座の通貨なら 1（価格の通貨が未設定なら 1 とみなさない）
- 損益 = Σ エントリー `s × (決済 − イン_i) × 数量_i × 乗数 × 為替`
- **事後の記録（エントリーが 1 つ。C18）**:
  - R 倍数 = `s × (決済 − イン) ÷ |イン − LC|`（為替も乗数も要らない）
  - 1R = `|手数料を除いた損益| × |イン − LC| ÷ |決済 − イン|`。手数料を除いた損益 = 明細の損益 + 手数料の合計。それが 0、R と符号が食い違う、決済 = イン、明細の損益が無い、のどれかなら `|イン − LC| × 数量 × 乗数 × 決済の為替`（価格の通貨 = 口座の通貨なら為替 1）。それも出せなければ 1R とリスク（%）は出さない（C32）
  - 明細から逆算した為替 = `手数料を除いた損益 ÷ (s × (決済 − イン) × 数量 × 乗数)`（価格の通貨 ≠ 口座の通貨・事後の 1 エントリーの取引のときだけ。1R の逆算と同じ条件で出さない。見せるだけで保存しない。C43）
  - LC は入る前に決めた LC（C30）
  - 損益は明細の値（手数料を含む実損）を正とする（為替を入れていても明細の値）。R は価格だけから出す（手数料・為替を含まない）
- **入る前の記録・買い増しがあるとき**: 1R（円）= Σ エントリー `|イン_i − LC_i| × 数量_i × 乗数 × 計画時の為替`（LC が無ければ定義しない）、R 倍数は価格だけ: `Σ s × (決済 − イン_i) × 数量_i ÷ Σ |イン_i − LC_i| × 数量_i`（為替・手数料を含まない。為替が同じなら 損益 ÷ 1R と同じ）。入る前の記録かどうかは 5.5 の「事前の計画あり」と同じ定義で見分ける
- リスク（%）= 1R ÷ 資金 × 100。資金は記録したときの、その取引の口座の資金（snapshot。C41）（資金が未設定なら出さず「資金を設定すると表示されます」。資金があっても 1R が出なければ、価格の通貨が口座の通貨と違えば「為替か損益を入力すると表示されます」、同じ・未設定なら「損益を入力すると表示されます」、LC が無ければ「LC が無いので表示されません」）
- リスク（%）の表示は小数 1 桁へ **切り上げ** る（誤差 1e-9 は切り上げない。2.01% → 2.1%、2.00% → 2.0%）。2% を超えた取引が 2.0% と出て、過剰リスクの理由と食い違うのを防ぐ（#13）

例（架空）: L、イン 100.00、LC 99.50、数量 10,000、乗数 1、為替 1、資金 1,000,000 円 → 1R = 5,000 円、リスク 0.5%。決済 99.40 → 損益 −6,000 円、−1.2R。

例（架空・事後の記録）: L、イン 100.00、LC 99.50、決済 99.40、明細の損益 −9,000 円（外貨建て。為替は打たない）→ R 倍数 = (99.40 − 100.00) ÷ 0.50 = −1.2R、1R = 9,000 × 0.50 ÷ 0.60 = 7,500 円。

例（架空・#47 F1）: 円の口座（資金 1,000,000 円）・USD 建て、L、イン 100.00、LC 99.50、決済 99.50、数量 100、為替 150 → 損益 = −0.50 × 100 × 150 = −7,500 円、1R = 7,500 円、リスク 0.75%（表示 0.8%）、−1.0R。

例（架空・#47 F3）: 同じ口座・USD 建て、決済 99.40、明細の損益 −9,100 円・手数料 100 円、為替は空 → 手数料を除いた損益 −9,000、値動き −60 → 明細から 1 USD = 150.00円（見せるだけ）、1R = 9,000 × 0.50 ÷ 0.60 = 7,500 円 = 0.50 × 100 × 150。

例（架空・#47 F9）: USD の口座（資金 10,000 USD）・USD 建て、数量 100、決済 99.50 → 為替 1、損益 −50.00 USD、1R 50.00 USD、リスク 0.5%。

注: オプションの R は、イン・LC・決済をプレミアム（オプションの価格）で入れたときのプレミアムの値動きで出る（原資産の価格ではない）。損益（円）は明細の値を正とするので、乗数の誤りは R に効かない（C18・C28）。

### 5.2 許容リスクからの数量の提案

最大の数量 = `資金 × 許容リスク ÷ (|イン − LC| × 乗数 × 計画時の為替)`（資金・許容リスクは取引の口座の値、為替は価格の通貨 1 単位 = 口座の通貨。C41・C43） を数量の刻みに切り捨てる。LC を動かすとその場で変わる。切り捨ては小数の誤差で 1 刻み落とさない（例: 0.3 ÷ 0.1 を 3 刻みに数える）。刻みに満たなければ 0（資金・LC が無い、LC の向きが逆のときは提案しない）。

事後の振り返り（#67・C42）: 記録した取引ごとに **数量の比** = 1R ÷ 許容額（許容額 = 資金 × 許容リスク ÷ 100。資金・許容リスクは取引の snapshot。比 × 許容リスク = リスク（%））と、**提案の数量** = 数量 × 許容額 ÷ 1R を数量の刻みに切り捨てた値（その LC で入れた最大の数量。上の式を 1R から逆算した形なので、為替・乗数を聞かずに明細の損益から 1R を出した取引でも出せる）を出す（`core/sizing.ts` の `reviewSizing`）。比はリスク（%）と同じく小数 1 桁へ切り上げて「2.5 倍」と書き、判定の枠では実際の数量と提案の数量を並べた後ろの括弧に下げる（「数量 10,000 · 提案の数量 4,000（2.5 倍）」。リスク（%）と同じ数を主役に重ねない）。提案が刻みに満たなければ 0 で「最小の数量でも許容リスクを超えます」。エントリーが 2 つ以上なら比だけ（「数量 10,000（許容リスクの 0.4 倍）」。数量は合計）。1R・資金が無い（LC なし・資金が未設定・外貨建てで為替も明細の損益も無い）とき、取引の LC が無い（エントリーごとの LC だけの）ときは出さない。判定は変えず、保存しない（記録したときの snapshot で出すので、後で口座の資金を直しても変わらず、口座を付け替えたときだけ変わる）。

例（架空）: L、イン 100.00、LC 99.50、決済 99.50、数量 10,000、資金 200,000 円・許容 1% → 1R 5,000 円、許容額 2,000 円、比 2.5 倍、提案の数量 10,000 × 2,000 ÷ 5,000 = 4,000、判定の枠は「数量 10,000 · 提案の数量 4,000（2.5 倍）」（判定は過剰リスク（2.5%）の B のまま）。

### 5.3 負けの判定（K8・K9・C1〜C3・C5・C8）

勝ち負けの境は C29（R が 0 以上は 5.4、0 未満は 5.3。R が出なければ損益（円）の符号で、0 円は勝ちの側）。決済済みの取引だけを判定する。上から順に、当たったものすべてを理由として出し、いちばん重いものを判定にする（理由は複数並ぶ。「LC を広げた」かつ「時間足を変えた」など）。

| 判定 | 条件 | 理由の表示（例） |
|---|---|---|
| **C 極悪な損失** | LC が無い、または「LC を入る前に決めていなかった」 | 「LC を決めずに入った」 |
| **B 悪い損失** | LC を広げた（リスクが増える向きに動かした。履歴または事後の「広げた」） | 「LC を広げた（99.5 → 99.2）」 |
| **B 悪い損失** | 時間足を長い足へ変えた（履歴・事後の「長い足へ」・エントリー時と決済時のチャートの時間足の違い） | 「時間足を変えた（4 時間足 → 日足・チャートから）」（チャートの時間足の違いから出たときは「・チャートから」を添え、タップの申告と見分ける。#12） |
| **B 悪い損失** | 決済価格が LC より不利で、決済の注文が逆指値と読めず（成行・指値・不明）、決済の理由が「窓・滑り」でもなく、損失が 1R を超えた（持ち続けた） | 「LC で切らずに持ち続けた（−1.8R）」 |
| **B 悪い損失** | 計画のリスクが 2% を超えていた | 「過剰リスク（2.8%）」 |
| **B 悪い損失** | LC の根拠が「金額から決めた」 | 「金額ありきの LC」 |
| **B 悪い損失** | 含み損で買い増した（ナンピン） | 「ナンピン」 |
| **A いい損失** | 上のどれにも当たらない（窓・滑りで LC より不利に約定したものを含む） | 「決めた LC で切れた」。決済の注文の種類が写っていて逆指値なら「逆指値で切れた（証拠あり）」。不明なら「決めた LC で切れた」のまま |

- 「持ち続けた」の比較先は最後の LC（C30。広げた後の値。値が無ければ「広げた」の取引では持ち続けたを出さない）。「窓・滑りでしたか」が未回答なら「いいえ」と同じに扱う
- LC を広げた取引では、R の分母が入る前の LC なので「1R を超えた」の条件は絞りにならない。広げた後の LC をわずかに滑っても持ち続けたが並ぶが、判定は既に B で、「窓・滑りでしたか」で救える
- 「LC が無い」（C の条件）と「金額ありきの LC」の「LC がある」は、エントリーごとに見る。取引の LC が無くても、すべてのエントリーにそのときの LC があれば LC ありとみなす（R・1R の計算と同じ定義）。エントリーの LC が 1 つでも欠けていれば LC 無し
- 資金が未設定、または 1R が出ないときは過剰リスクを見ず、理由に「資金が未設定なので過剰リスクは見ていない」（1R が出ないときは「1R が出ないので過剰リスクは見ていない」）を添える（C33）。資金は取引の口座の資金で、過剰リスクの境目の 2% は口座によらず固定（C8・C41）
- 理由の中の価格は保存した数のまま出す（丸めない・末尾の 0 は落ちる。#13）。整数部だけ 3 桁区切りにする（`38,250`・`1.08345`。価格・数量の表示はすべて同じ書き方。入力の欄の値には区切りを入れない。#40）
- LC を不利な側へ動かしたことは L / S で同じ言葉で「LC を広げた（150.5 → 151）」と言い、事後のタップの選択肢も L / S で同じ「そのまま / 狭めた / 広げた」（保存の値 `tightened` / `widened` の意味のまま）。価格の向き（L は下・S は上）は、広げた後の LC の入力の誤りの知らせ（「広げた後の LC は、入る前の LC より下にしてください」。S は「上に」）だけで出す（#56。#13 の S の「上げた」を置き換えた）
- 「持ち続けた」は、決済価格が LC より不利で、逆指値の約定でも「窓・滑り」でもないことで判定する（逆指値で約定したものは、不利に滑っても A。自己申告の「窓・滑り」が多すぎる人は 6.1 の集計で見える）
- 決済の注文の種類が「不明」（明細に写っていない）は「逆指値でない」と同じに扱う（証拠が無いので救済しない）。その代わり C19 の「窓・滑りでしたか」の 1 タップで救う（C26）
- 判定は手で上書きできるが、元の判定と上書きした事実は残す
- ナンピン = 2 つ目以降のエントリーのインが、それまでのエントリーの数量で重みを付けた平均のインより不利（L は下・S は上。同じ値は含まない）
- 買い増しの取引の「持ち続けた」の比較先は、最後のエントリーのそのときの LC
- 注記（判定の重さに数えない。6.1 で数える）: 逆指値の A に「逆指値で切れた（証拠あり）」、窓・滑りで救った A に「窓・滑り」、決済の理由が「崩れる前に怖くなって」なら勝ち負けによらず「早逃げ」
- R も損益（円）も出ない（LC が無く、外貨建てで為替も明細の損益も無い）ときは、価格の動きの符号で勝ち負けを分ける（C29 の補い。0 は勝ちの側）
- 過剰リスクの 2%・勝ち負けの境・「持ち続けた」の 1R 超えの比較は、小数の誤差（1e-9）を許す（ちょうど 2.0% は過剰でない、R が −1e-15 は負けにしない）

### 5.4 勝ちの判定（C4）

| 判定 | 条件 |
|---|---|
| **危ない勝ち** | 5.3 の C・B の条件のどれかに当たる勝ち（LC 無し・LC を広げた・時間足を変えた・過剰リスク・ナンピンで助かった など） |
| **計画どおりの勝ち** | それ以外（TP・崩れの条件で手仕舞い・LC を狭めて刈られた ±0 を含む） |

危ない勝ちは、ホームで負けと同じくらい目立たせる。「勝ったから正しかった」を断つため。

### 5.5 事前の計画あり（C6）

記録の基本は事後なので、後付けは印にしない。入る前に記録した取引（計画の時刻がエントリーより前）には「事前の計画あり」を付け、集計で分けて見られるようにする。逆指値を入れていたかを集計に出す。

## 6. 振り返り（集計）

### 6.1 規律の指標

期間・銘柄・原資産の種類・商品の形・セットアップ・時間足・感情・曜日 / 時間帯で絞り込める。件数が少ない切り口（5 件未満）は値を出さず「件数が少ない」と出す（偶然を癖に見せない）。

| 指標 | 中身 |
|---|---|
| 計画どおり率 | **判定の出た取引**（取り込みを除く。保存した記録から計算できず判定の出ない取引は分母に入れない）のうち、A と計画どおりの勝ちの割合。5 件未満の判断もこの件数で数える（判定の出た取引が 5 件未満なら率を出さない）。表示は整数の %（四捨五入）だが、100% はすべてそろったときだけ・0% は 1 件も無いときだけ（199 / 200 は 99%。#88・C44） |
| 判定ごとの件数と損益 | A / B / C / 計画どおりの勝ち / 危ない勝ち |
| 崩れ方の内訳 | LC を広げた・時間足を変えた・持ち続けた・過剰リスク・金額ありき・ナンピン・LC 無し、それぞれの件数と規律コスト |
| R の分布 | R 倍数のヒストグラム。−1R の壁で止まっているか、左に長い裾があるか |

| 負けの後 | 負けの直後（同じ日）の取引の計画どおり率 |
| 我慢した見送り | 件数。褒める |

### 6.2 規律コストの曲線（看板の画面）

実際の損益の曲線に、**「計画どおりだったら」の曲線** を重ねる。

- B・C の負けを −1R（LC が無い C は、許容リスクの額）に置き換えた損益。ただし置き換えるのは **R が −1.0R より小さい（大きく負けた）B・C だけ** で、−1.0R 以上の B・C（例: 金額ありきの LC で −0.5R）は実際の R のまま（−1R に置き換えると「守っていれば損が増えた」になり、計画どおりだったらと逆になるため。#88）
- 危ない勝ちはそのまま（助かった分は運として別に表示する）
- **R が出ない取引**（LC が無い C など）は曲線と規律コストに入れず、件数を添える（R の曲線に円の額を混ぜない。#88。LC が無い C を許容リスクの額で置き換えるのは円の表示を足すときに決める）
- 置き換えは損を小さくする向き（−1.0R より小さい R → −1.0R）だけなので、計画どおりの累積はどの時点でも実際の累積を下回らない。2 本の線は交差せず、差の面はいつも「計画が上・実際が下」の区間で、右端の差（実際 − 計画）= 規律コスト。−1.0R 以上の B（金額ありきの LC で −0.5R など）は置き換えないので差を生まない（2 本は重なる）。例: −1.6R の B の後は計画が実際より 0.6R 上に開いたまま進み、その後の A・勝ちでは同じ幅で並ぶ（#88 の例の表 S1）
- 2 本の曲線の差が **規律コスト**（= Σ（実際の R − 計画どおりの R）。0 以下）。一言は 2 行で、主役（1 行目・いちばん大きな数）は崩れで失った R「崩れで −◯◯R」、2 行目に「守っていれば +◯◯R · 実際 +◯◯R」（円なら ◯◯ 円。#88）。差が 0 なら「崩れなし ±0.0R」だが、R が出ず曲線の外にある取引（LC の無い C など）がある期間は「崩れなし」と言い切らず「R で測れる崩れ ±0.0R」とし、曲線の外の件数を添える（いちばん重い崩れを褒めない）
- 曲線の横軸は取引の順番（決済の古い順。時刻の間隔ではない）、0 から始める。ホームでは期間を選んで出す（9.2・C44）

手法の良し悪しと規律の良し悪しを、1 枚で分けて見せる。

### 6.3 成績は R で見せる

成績の既定の表示は R。円は切り替えで出す。「お金を儲けたい」という気持ちが入りの理由になっていた（オーナーのシートの総評）ので、成績からお金の刺激を外す。

## 7. 規律を守らせる仕掛け（保有中と入る前に効かせる）

振り返りだけでは、崩れる瞬間に間に合わない。崩れそうな瞬間に、冷静なときの自分の判断を差し出す。

### 7.1 誘惑ガード（保有中。任意の機能、縦切り 3。C16）

入る前に記録した取引だけに効く。事後の記録が基本なので、入る前に記録したい人向けの任意の機能。


保有中に LC を広げる・時間足を長い足に変えようとすると、変更の前に 1 枚のカードを挟む。

- エントリー時の自分の言葉を引用する: 「あなたは入る前にこう書きました: 『直近安値 99.50 を割ったらサポートが崩れる』」
- 変えた場合に増えるリスクを R と % で出す: 「LC を 99.20 にすると、この取引のリスクは 1.6R（資金の 1.6%）になります」
- 30 秒待ってから [それでも変える] が押せる。[思いとどまる] はすぐ押せる
- どちらを選んだかを記録する（思いとどまった回数は 6.1 で褒める）

### 7.2 ティルトの停止条件（冷静なときに決める）

冷静なとき（設定の画面）に、自分で停止条件を書いておく。例: 「1 日に 2 回 B 以下の負けが出たら、その日は新しい計画を作らない」「1 日の損失が資金の 3% に達したら終わり」「負けてから 30 分は入らない」。

- 条件に当たると、新しい計画の画面の前に停止のカードが出る（自分で書いた条件を引用する）
- 解除はできるが、解除した事実が残り、その後の取引に印が付く
- 負けの直後の取引・サイズを増やした取引も自動で印を付ける（リベンジトレードの検知）

### 7.3 気づき → 自分ルール

気づきを自分ルールに昇格できる。例: 気づき「大きな暴落を見ると、MA や過去の安値付近でお試し買いをする。それもオーバーサイズで。そして負ける」→ 自分ルール「条件: セットアップが『暴落からのリバ狙い』/ 守ること: 許容リスクを 0.5% にする」。

- 新しい計画で条件に合うと、ルールが計画の画面に出て、提案の数量もルールに従う
- 守ったか破ったかを記録し、6.1 でルールの効果（守ったとき / 破ったときの平均 R）を出す
- 効果が無いルールは見直しを促す

### 7.4 入る前の 30 秒（任意の機能、縦切り 3。C16）

入る前に記録したい人向け。事後の記録（7.5）と同じ欄を、入る前に埋める。


- 根拠にした足のチャートのスクショを貼る（貼り付け・ファイル選択。スマホは共有から）。写っている時間足の表示だけを読み取り、時間足の欄の候補にする（価格は読まない。K11）
- 手で入れるのは LC と崩れの条件の一言。銘柄・L / S・イン・数量は、入る前なら手で、入った直後なら約定明細のスクショからでもよい（どちらも任意。決済明細で後から埋まる）
- 銘柄・イン・LC がそろった時点で、リスク（%）と提案の数量が出る
- 「LC を決めずに入る」もできるが、ボタンの色と言葉で「極悪な損失の候補」と分かるようにする

### 7.5 事後の 1 回の記録（30 秒。K10〜K12）

**流れ**

1. 決済明細のスクショと、根拠にした足のチャート（エントリー時。任意で決済時も）を貼る（貼り付け・ファイル選択。スマホは共有から）
2. AI が決済明細を行ごとに読み取る（銘柄・L / S・建てた価格と時刻・決済の価格と時刻・数量・手数料・損益・決済の注文の種類（写っていれば。C26））。向きは書かれた言葉のまま（売 / 買と、それが建玉の向きか決済の向きか）、時刻は書かれた並びを見分けて明細の時間帯のまま読み、L / S と日本時間への直しは API の純関数で行う（C27。時間帯が書かれていなければ日本時間とみなさず確かめる）。手数料は欄ごとに読み、合計は純関数で出す。チャートからは時間足の表示だけを読む（価格は読まない。K11）。**読み取りを待たずに、貼った直後から 3〜4 を入れられる**（C23）
3. 手で入れるのは LC と崩れの条件の一言（一言は任意。C17）。LC を決めていなかったときは「なし」を選ぶ（C37）。LC を入れた時点で R とリスク（%）が出る
4. 3 つのタップ: LC を入る前に決めていたか / LC を動かしたか / 時間足を変えたか（C15）
5. 判定・理由・R がその場で出る（5.3・5.4）。根拠の一文・感情・総評は任意
6. 1 枚の決済明細に複数の行があれば、行ごとに取引の下書きを作り、順に記録する（1 行 = 1 取引。C20）。入る前に記録した取引との突き合わせは縦切り 3
7. スクショが無いとき・読み取れないときは、同じ欄を手で入れられる。「取引」の枠の欄は 銘柄 | 数量 / L / S / イン | 決済 /（銘柄の価格の通貨が口座と違うときだけ）為替 | 「1 USD = ? 円」の 1 行 / エントリーの時刻（任意）| 決済の時刻 の順（どの通貨でも欄の位置を変えない）（エントリーの時刻は任意のまま「ほかの欄」から「取引」の枠へ出し、決済の時刻と並べる。足りない欄に数えない。#58）

**画像の扱い**

| 画像 | 読み取るもの | 保存 |
|---|---|---|
| 決済明細・約定明細 | 銘柄・L / S・価格・時刻・数量・手数料・損益と、損益・手数料の通貨・決済の注文の種類（写っていれば）・明細を出した会社の名前（#66） | しない（C13）。読み取った値だけを、確かめてから保存。会社の名前は API の中で明細の特徴の鍵に変えて捨て、鍵 → 記録した口座だけを覚える（C45・ADR-0017） |
| 根拠の足のチャート（エントリー時・任意で決済時） | 時間足の表示だけ（4H・日足など。価格は読まない。#27） | 非公開で保存（API が中継し、Firestore に取引と同じトランザクションで。ADR-0006）。取引の詳細でエントリー時と決済時を並べて見せる（#9） |

- エントリー時のチャートと決済時のチャートの時間足が違えば、「時間足を変えた」の証拠として判定の理由に添える（K9）
- 読み取りの結果は形の決まった値だけ（自由な文字列を返さない）。画像に氏名・口座番号が写っていても、結果・画面・ログに戻る経路を作らない（C14）
- 送る前に、AI の提供元に送ること・口座番号などは切り取ってほしいこと・明細の画像は保存しないことを、常に見える形で示す（毎回の確認ダイアログにはしない）。補足は「i」の吹き出しに置く（#57）
- 読み取った欄には「読み取り」の印を付け、利用者が直せる（直した L / S・日本時間の時刻も同じ）。確かめずに記録へ入る経路は無い
- 読み取りの入口は API の `POST /api/statement-reads`（画像の生のバイト。PNG / JPEG・500,000 B 以下・長辺 2,000 px 以下。画像も結果も保存しない。#11・ADR-0005）。指示・結果の形・直しの純関数は評価の道具と共有のパッケージ `packages/statement-read/` に 1 つだけ置く
- 画面の振る舞い（#15）:
  - 貼った・選んだ画像は追加の操作なしで送る（記録する画面の文字の欄の外ならどこに貼っても受ける。画像が無い貼り付けと、文字の欄への文字を含む貼り付けは、画像を含んでいても横取りしない。文字の欄でも画像だけの貼り付けは受ける。表計算のコピーは文字と画像の両方を持ち、意図しない画像を送らないため）。送る前に端末で必ず描き直す（PNG → JPEG の品質を下げる段、長辺 2,000 px 以下・500,000 B 以下。上限の内側でも描き直してメタデータを落とし、作ったバイト列の形式・寸法・バイト数を送る前に確かめる。ADR-0005 の決定 5）
  - プレビューは送るものと同じ画像を canvas に描く。object URL・data URL を作らない（10.1 の CSP の img-src を広げない）。画像・読み取りの値は記憶の中だけで、端末の保存先・URL・履歴に書かない。保存の後・やめた後・画面を離れた後に捨てる
  - 読み取り中も全欄を入れられるが保存はできない（理由「明細を読み取っています」）。[やめて手で入れる] でやめられ、後で届いた応答は捨てる。画面の待ちは API の締め切りと後始末より長く 30 秒
  - 応答の値は読み取りの欄 9 つ（銘柄・L / S・イン・決済・数量・決済の時刻・建てた時刻・損益・手数料の合計）に入れる。読めなかった欄は空にして印を付け、開いたときの既定値を残さない。貼った後に手で入れた欄は上書きしない。直した欄の印は「直した」
  - 損益・手数料は、読んだ通貨が口座の通貨と同じとき、または口座が JPY で通貨が読めず銘柄の価格の通貨が JPY か未設定のとき（今と同じ）だけ欄に入れる。違えば入れず（空・印なし）、その 2 欄の下に「明細の損益は USD です（口座 A は JPY）。USD の口座を選ぶか、円の損益を入力してください」（通貨が読めず入れなかったときは「明細の損益の通貨が読めませんでした。円の損益を入力してください」）と出す。貼った後に口座を替えたら、読み取りで入れた損益・手数料についてだけ同じ規則をやり直す（合わない口座では空に戻し、合う口座へ戻したら入れ直す。手で入れた値は残す。#66・C45。#47 PR-2 の「外貨の口座では入れない」を置き換えた）
  - 明細から口座を選ぶ（#66・C45）: 応答の明細の特徴の鍵で前に記録した口座があり、口座が 2 つ以上・その口座が今の一覧にある・その明細で本人がまだ口座を選んでいない（読み取り中に選んだ・その場で足したを含む）ときだけ、その口座を選んで口座の欄に印「自動で選択」を付ける（読み上げは「前にこの明細で選んだ口座を自動で選びました。違うときは選び直してください」。損益・手数料はその口座の通貨で流し込み、提案の口座の通貨が明細の損益と合わなければ印は付けない）。本人が直すと印は消える（「直した」にはしない。口座は読み取りの欄ではない）。口座の欄の下の 1 行: 損益の通貨が今の口座と合わずその通貨の口座が一覧にあれば「明細は USD です。USD の口座は 口座 D です」、そうでなく覚えの無い明細で本人がまだ選んでいなければ「この明細の口座を選んでください。次から自動で選びます」。覚えが無かった・覚えと違う口座で記録したときは、保存の後の 1 行に「次からこの明細は 口座 B を自動で選ぶようにしました」（口座 2 つ以上のときだけ）。明細から作った下書きを記録したら、鍵 → 記録した取引の口座を覚える（飛ばした行・明細の無い記録・直す画面では覚えない。失敗は知らせずに捨てる）。複数行の次の行は前の行の口座を引き継ぐ（#47 R4）。鍵と提案の口座は記憶の中だけで、端末の保存先・URL・履歴に書かない。会社の名前が写っていない明細（上部を切り取った）は提案なし・覚えない
  - 注文の種類が逆指値と読めたときだけ、決済の理由 = LC・LC を入る前に決めていた を既定で選ぶ（印「明細から」。本人が先に選んでいればそちらが正）。取引には注文の種類と「逆指値を入れた」を残す（C19・C26）
  - 時間帯が明細に無い時刻は、書かれた時刻を入れて [日本時間で合っている] か欄の直しまで保存しない（押すと日本時間として端末の時刻の欄に写し直す。端末の時間帯に依らない）
  - もう 1 枚貼ると前の読み取りを捨てて読み直す。前の読み取りの後に直した欄は上書きせず、前の読み取りが「明細から」の既定で選んだ値は戻す（出どころを失った既定が本人の答えに見えないように）。読み込み中・保存中に貼ったときは捨てずに「もう一度貼ってください」と知らせる
  - 複数行は「i / N 行目」で 1 行ずつ記録する。[この行を飛ばす] で記録せずに次の行へ（保存と同じく次の行へスクロールして知らせる）。最後の行を飛ばしたら読み取りを終えて空の下書きに戻る
  - 失敗は決まった文言だけを出し、入れていた値は残って手で記録できる（流れ 7）。1 日の上限（8.2）に当たったときは「今日の読み取りの上限に達しました。手で入れてください。」（429 `read_limited`。回数と費用のどちらで止まったかは出さない。#44）
- 根拠の足のチャートの枠（#12・ADR-0006）:
  - 記録する画面にエントリー時・決済時の 2 枠（各 1 枚・どちらも任意）。枠の下に撮る足（「エントリーの根拠にした足」「決済の判断に使った足」）を添える（別の足で撮っただけで「時間足を変えた」にならないように）
  - 枠を選んで（クリック・Tab でフォーカスして）貼る・[チャートを選ぶ] とその枠に入り、明細の読み取りには送らない。枠を選ばない貼り付けは今までどおり明細の読み取りへ（R1）。同じ枠にもう 1 枚で置き換え、[外す] で画像と時間足を消す
  - 画像は明細と同じく端末で描き直し（PNG / JPEG・500,000 B・長辺 2,000 px）、canvas にプレビューを描くだけで、[記録する] まで送らない。保存は取引と一緒に 1 要求（multipart）で、チャートを保存できなければ取引も保存しない。保存の後・次の行・画面を離れたら捨て、端末の保存先・URL・履歴に書かない
  - 各枠の時間足（1 分足〜月足の 9 つ・任意）はチャートのある枠でだけ選べ、選ばなくても記録できる。手で打つ欄 2・選ぶ欄 3 は変わらない。枠に入れ直すと時間足は空に戻る（選び直し）
  - API は `POST /api/trades`（multipart。部分 `record`・`entryChart`・`exitChart`・付属の `x1Chart`〜`x5Chart`）と、差し替え・外す・読み戻しの `/api/trades/{id}/charts/{slot}`。チャートの無い枠に時間足は 400
  - 追加のチャート（#89）: 見出し「チャート（任意）」の行の右端の [＋ 追加]（480px 以上は「＋ チャートを追加」。リンクの色で、畳んだ欄の開く印と見分ける。読み上げの名前は「チャートを追加」）で、2 枠の下に小見出し「追加のチャート（判定には使いません）」を 1 つ置き、その下に追加の枠（「追加のチャート n」・実線の枠）を末尾に足す（最大 5 枚・追加した順）。見出しの行に置くのは、2 枠の下に 1 行を足すと記録する画面の全長の上限（ui:check の R12）を超えるため（記録の手間の予算。最初は畳む）。各枠は 2 枠と同じ操作（貼る・選ぶ・チャートのある枠の [差し替え]・右上の [削除]・時間足の読み取り。時間足を読むために AI に送るので、送る前の注意は 2 枠と同じ）に、チャートのある枠だけ任意の一言（40 字まで）。判定には使わない（別の足で撮った資料で「時間足を変えた」にしない）
  - 編集の画面（#89）: 記録する画面と同じ枠（保存済みのチャートは読み戻してプレビュー）で追加・差し替え・削除・付属の枠ができる。変更は [保存する] まで送らず、[保存する] で取引の欄とチャートの変更を 1 要求（`PUT /api/trades/{id}` の multipart。差し替え・足す画像 + 外す枠 `removeChart`）で送り、API が 1 トランザクションで書く（失敗すれば取引もチャートも前のまま）。[キャンセル] で捨てる（画面を移っても書きかけとして残る。9.1・#75）。足した枠の時間足は空から読み取りで埋まる。エントリー時・決済時の枠を差し替えたときは前に保存した時間足を残し、読めたときだけ置き換える（読み取りが失敗で終われば「前のチャートの時間足（日足）のままです。違えば選んでください。」）。読み取りの途中で保存したら、前のチャートの時間足を新しいチャートに付けず、その枠は「指定なし」で保存する（保存の前の帯に「決済時の時間足は読み取りの途中なので指定なしで保存します」。利用者が選んでいればその値）。[元に戻す]・使えない画像で戻すときは、追加の枠の一言と並びの位置も保存した値へ戻る。保存済みのまま触らない枠は読み取りに送らない。追加の枠は時間足が読めなくても知らせない（判定に使わず、時間足の無い資料も入る）。時間足の選択肢の空は「指定なし」。差し替えの画像が使えなければ（描き直しの途中にもう 1 枚入れた・続けて失敗したを含め、どの順でも）前のチャート・保存済み・削除した状態のまま知らせる。保存で removeChart を送るのは利用者が [削除] した保存済みの枠だけ。削除した保存済みの追加の枠は 5 枚に数えない（その枠を新しい行に使う）。変えた枠の名前の横に印「差し替え」「追加」、削除した保存済みの枠は「チャートなし（保存で削除）」と [元に戻す]（保存済みのチャートと時間足に戻る）を残し、保存の帯に「判定: 前 → 後」（段と R が同じでも理由が変われば「判定は … のまま・理由が変わります」）と「・チャート n か所を変更」（判定が同じなら「判定は同じ（…）・チャート n か所を変更」に縮めて 1 行）。[キャンセル] は [保存する] の左に横並び。変えた枠の印は状態の言葉（「差し替え済み」「追加（未保存）」「削除（未保存）」）。チャートを送る保存は、時間の上限を送る大きさで延ばし（30 秒 + 1 MB ごとに 10 秒）、送っている間は「チャートを送っています…」
- チャートの時間足の表示の読み取り（#27・ADR-0015）:
  - 枠の画像が使えるようになったら（描き直しの後）追加の操作なしで `POST /api/chart-reads`（画像の生のバイト。明細と同じ上限）に送る。AI は写っている時間足の表示を書かれたまま返し（「4H」「240」「日足」など）、API の純関数が 9 つの列挙か空に直す（C27）。読めない・列挙に無い足（2 時間足など）・2 通りに読める表記（「1M」= 月足か 1 分足）・時間足の違う複数のチャートは空（読み違えるより空。空なら判定は壊れない）。応答は「チャートか」と時間足（列挙か空）だけで、書かれた表記は応答・ログに出さない。画像も結果も保存しない（チャートは [記録する] で取引と一緒に保存する）
  - 枠の時間足が空で、利用者がその枠の時間足を触っていなければ読んだ値で埋め、印「チャートから」（札と欄の左の線）を付ける（利用者が直すと消える）。利用者が違う値を選んでいれば上書きせず、欄の下に「チャートからは 〈日足〉 と読めました [日足にする]」を出す（1 タップで直せる。押したときだけ置き換えて印）。差し替え・外す・記録・画面を離れた後に届いた応答は捨てる
  - AI の読み取りは 1 つずつ送る（明細が先、チャートはその後に枠の順。同時の予約と CPU の取り合いを減らす）。読み取り中も [記録する] を押せる（時間足は任意の欄。帯に「待たずに記録できます」（時間足の読み取り中は枠に「時間足を読み取っています…」））。記録した時点で終わっていない読み取りは止めて結果を捨て、時間足は利用者が選んだ値（無ければ空）のまま保存する。失敗（上限・形の外・時間切れ・通信）・読めない・チャートでない（「明細なら枠の外に貼ってください」）は決まった文言で知らせ、欄は空のまま（手で選べる・選ばずに記録できる）
  - 3 つ目のタップの答え（「変えず」「短い足へ」）とチャートの時間足の違い（長い足へ）が食い違うときは、判定の理由の 2 行目に「あなたの答え: 変えず ／ チャート: 4 時間足 → 日足」、タップの下に「チャートでは 4 時間足 → 日足」を並べる（責める語・警告の色を使わず、どちらを正とするかを迫らない。判定の規則は 5.3 のまま）
  - 送る前の注意は主語を分けて常に出す: 明細の枠に「明細の画像は AI の提供元（Anthropic）に送って読み取り、保存しません。口座番号・氏名は切り取って貼ってください。」、チャートの枠の見出しの下に「時間足を読むため AI（Anthropic）に送ります。チャートは記録と一緒に保存します。」（C38）
  - 1 日の上限は明細の読み取りと同じ財布で数える（8.2）。精度は架空の合成のチャート（`tools/statement-eval/synthetic-charts/`。表示の形 5 通りと、表示なし・列挙に無い足・時間足の違う 2 つ・チャートでない画像）で、「表示があるのに列挙の別の値に読み違えた件数」と「表示が無いのに値を作った件数」がどちらも 0 であることを確かめる（空は許す）
- 読み取りの精度と速さは、架空の値の合成の明細（`tools/statement-eval/`。#14・ADR-0001）で確かめる。#14 の実測: 合成 14 枚で判定と R に効く 4 欄（L / S・建てた価格・決済の価格・損益）は 3 モデルとも全件一致、1 枚の最大は数秒（数字は Issue #14 の結果のコメントを正とする）。#66 で合成の明細は 16 枚（上部に架空の会社の名前 2 通り・USD の損益の明細 2 枚）になり、損益の通貨の一致と会社の名前の鍵の安定（同じ会社は同じ・違う会社は違う）も数える

## 8. AI の振り返り

### 8.1 何をするか

- **負けの直後の聞き取り**: B・C の決済のあと、AI が 2〜3 問だけ聞く（説教しない）。「LC を広げたとき、何を考えていましたか」「入る前の自分にひとこと言うなら」。答えは気づきの候補になる
- **言い訳の言葉の検知**: 保有中のメモ・総評に「長期的に見れば」「そのうち戻る」「取り返す」のような言葉が出たら、時間足の変更・リベンジの兆候として印を付ける（取引ごとの AI の振り返りで指摘）
- **期間の振り返り**: 週・月の取引・見送り・気づき・自分ルールを読み、崩れ方のパターンを、根拠になった取引を挙げて指摘し、自分ルールの候補を 1 つ出す
- AI は売買の推奨をしない。規律と心理の振り返りに限る

### 8.2 作り

- AI の呼び出しは API から行う。ブラウザに資格情報を置かない
- 送るのは振り返りに要る項目だけ（チャート画像は利用者が選んだときだけ）
- 利用者ごとの 1 日の回数と費用の上限と、全体の 1 日の費用の上限を持つ。上限を受けない利用者（バイパス）のリストを持つ（#51・ADR-0014。下の決済明細の読み取りの節）
- 初めて使うときに、記録の一部が AI の提供元に送られることを示して同意を得る（決済明細の読み取りは、縦切り 1 では 7.5 の常に見える注意で代える。C38）
- 資格情報は Anthropic API のキー（従量課金）か Workload Identity Federation（#55・ADR-0011）。他の利用者に提供するサービスに、オーナーのサブスクの資格情報は使わない（オーナーだけが使う間は、決済明細の読み取りに限って OAuth トークンも使える。他の利用者を受け入れる前に federation か API のキーへ移る）。モデルは実装時に最新の一覧から選ぶ（聞き取りは速いもの、期間の振り返りは賢いもの）
- 決済明細の読み取り（7.5）は Claude Agent SDK を通す（#14 の評価の道具と同じ送り口・同じ部品。モデルは claude-sonnet-5-5・effort low・締め切り 20 秒）。資格情報は環境変数で受け、`STATEMENT_READ_CREDENTIAL` で 3 つの方式を切り替える（#55・ADR-0011）: `api_key`（既定）/ `oauth_token` / `federation`（Cloud Run の実行用のサービスアカウントの ID トークンを要求ごとにメタデータ サーバーから取り、要求ごとの一時ファイルで渡す。取れなければ AI を呼ばずに 502 `read_failed`・数えない）。起動の種類（手元 / 本番）で方式を制限しない。子の CLI に渡す環境は方式ごとの許可リストで組み立て、選ばなかった方式・送り先の変数は子の環境に名前ごと置かない（空の文字列も資格情報の優先順位の枠を占めうるため）。要求ごとの HOME・設定の置き場にはファイルを置かない
- 決済明細の読み取りの本番の資格情報と上限（#44・ADR-0010）:
  - 資格情報: 方式は repository variable `STATEMENT_READ_CREDENTIAL` で選ぶ（未設定なら載せない。#55）。Anthropic API のキー（本番専用のワークスペースのもの）と OAuth トークンはそれぞれ Secret Manager の入れ物 1 つ（東京に複製・削除の防止）に置く。federation の識別子は GitHub の secrets から伏せた Terraform の変数で Cloud Run の環境変数に渡す（秘密は置かない）。以下はキーの入れ物の例:読めるのは Cloud Run の実行用のサービスアカウントだけ（入れ物の単位の付与）。値はオーナーが GCP のコンソールの Secret Manager の画面で新しい版として貼り（ターミナル・会話に通さない）、Terraform の宣言・state・plan・リポジトリ・ログに値を入れない。キーの版が入るまでは Cloud Run に参照を付けない（版の無い参照ではインスタンスが起動しない）ので、読み取りは 503・ほかの機能は動く
  - 利用者ごとの回数: 1 日（日本時間の 0:00 で区切る）30 回。31 回目からはその日は 429 `read_limited`（AI を呼ばない）
  - 全体の費用: 全利用者の合計で 1 日 2.00 USD。送る前にその要求の費用の上界（予約額）を足して、計上額 + 予約額 ≤ 2.00 USD のときだけ送る。送った後は、使ったトークン × 料金表と SDK の合計額の大きい方に直す。受け取れなかった回（締め切り超え・途中の失敗）は予約額のまま数える（多めに数える側）。予約額 = 入力の上界（画像 1 枚の上界 5,334 + 指示・ツールの定義の UTF-8 のバイト数 + CLI の上乗せ 20,000 トークン）× 入力の最高単価（1 時間の cache 作成）+ 最大出力 × 出力の単価。最大出力は CLI に 16,000 トークンを渡して抑え（結果の最も長い形でも約 15,000 B）、Sonnet 5.5 で約 0.28 USD。同時に 7 枚まで送れる
  - 数えるもの: 認証・資格情報の有無・画像の上限の検査を通って AI へ送る要求だけ（送った後の失敗も数える）。401・400・503 は数えない。数える場所（Firestore の日の文書。トランザクション）を読めない・書けないときは AI を呼ばずに 503 `read_unavailable`（閉じる側）。同時の要求でも上限を越えて送らない。計上に残すのは日付・回数・金額だけ（利用者の日の文書 `users/{uid}/statement_read_days/{日付}` = 回数・金額〔金額は #51 から〕・全体の日の文書 `statement_read_spend/{日付}`）
  - 利用者ごとの費用（#51・ADR-0014）: 1 日 1.00 USD（全体の半分で、1 人の連打・盗まれたトークンで全体を使い切れない。予約額の 3 回分が入る）。全体と同じ予約 → 精算で、利用者の日の文書にも金額を残す（欠け・負の金額は回数 × 予約額に見積もる）。判定の順は 回数 → 利用者の費用 → 全体の費用（どれも 429 `read_limited`。理由はログだけ）。方式（`oauth_token` を含む）によらず同じ額で数える（`oauth_token` の額は「従量課金なら」の換算額）
  - バイパス（#51）: リスト（メール。許可リストと同じ形・照らし方。本番は Secret Manager の参照）の利用者は、利用者ごとの回数と費用の上限を受けない。全体の上限（ブレーカー）は受ける（足りなければ全体の上限を上げる。最後の歯止めは Console の月の上限）。計上には残す
  - 上限の値は環境変数で変えられる（#51・ADR-0014。ADR-0010 の「コードの定数」を上書き）。未設定・空なら上の既定。形の誤り（空白だけを含む）は既定値に戻さず 503 `read_unavailable`（閉じる側。準備の入口も）。上の天井は設けず Console の月の上限に任せる。手元の開発にも同じ上限を掛ける。上限に当たっても記録・一覧などほかの API は動く
  - チャートの時間足の読み取り（7.5・#27・ADR-0015）も同じ財布で数える（同じ日の文書・同じ判定の順。明細とチャートを合わせて利用者ごとの回数・利用者ごとの費用・全体の費用。バイパスの利用者は明細と同じく利用者ごとの上限を受けず全体の上限は受ける。上限の値の形の誤りは明細と同じく 503 `read_unavailable`）。予約額は種類ごと（チャートは指示・ツールの定義が短く、最大出力 2,000 トークンなので Sonnet 5.5 で 130,164 µUSD。明細は 282,012 µUSD。#66 で会社の名前・損益の通貨の指示とツールの欄の分だけ 278,736 から上がった。値を固定するテストは `packages/statement-read/tests/test_pricing.py` の 1 か所）。画面は AI の読み取りを 1 つずつ送り、予約の重なりを減らす。先立ての CLI（#65）は明細の読み取り専用で、チャートの読み取りはその場で立てる
  - 見張り: 日ごとの回数・金額は本番の Firestore から読める（infra/README.md）。本番のキーの属するワークスペースに Anthropic Console の月の上限 20 USD を置く（日の上限が働かない不具合への二重の安全弁。オーナーの手作業）
  - 使った量の見せ方（#62）: 設定の画面のカード「AI の利用状況」に、**本人の分だけ** を出す。今日（日本時間）は回数・金額の **残り**（「あと 27 回」「あと 0.88 USD」）を主に、使った量・上限・割合を添え、今月（日本時間の 1 日〜今日）は回数・金額の合計を同じ行の組みで出す。入口は `GET /api/ai-usage`（本人の日の文書を文書 ID の範囲で読む。最大 31 件。書かない）。数え方は判定と同じ（金額の欠け・負は回数 × 予約額）。次の読み取りが本人の上限で止まるとき（金額は 計上額 + 予約額 > 上限 なので割合が 100% 未満でも止まる）は「今日」の見出しのすぐ下のまとめの 1 行（左の線・上限の記号）で「上限に届きました」と出し、使えない残りを棒の上で点線の枠で示す。80% 以上は「上限に近づいています」。上限を受けない利用者は「あなたの 1 日の上限: なし」と、全体の上限に届いたら止まることの 1 行。全体の上限は **値** だけ見せ、全体の使った量（すべての利用者の合計）は見せない（1 人の利用者でもほかの利用者の使い方が引き算で分かるため）。金額は USD（円に換算しない。使った量は 1 セント未満を切り上げ、残りは切り捨て）で、行の名前は「金額（目安）」、カードの説明に「従量課金の料金表で換算した目安で、あなたに請求されるものではありません」と書く。今月の額は日の計上の合計で、提供元の Console の月の上限とは別の数字（運営者向け。infra/README.md）。色は判定の段を使わず、状態は文字と形で出す。上限の値の形が誤っていれば 503 `read_unavailable`（割合を出さない）

## 9. 画面

### 9.1 原則

- モダンでかっこいい SPA（K2）。ダークを既定にし、ライトも用意する。数字は桁の揃う書体（本文の書体の tabular-nums）で大きく、判定と損益は色だけに頼らず符号とラベルを添える
- スマホ（360px）から PC まで同じ機能。入るときはスマホで素早く、振り返りは PC で広く
- 取り消せる操作は確認を出さず [元に戻す] で戻す。確認を挟むのは誘惑ガード（7.1）だけ。意図して手間をかける場所はここだけにする。取引を消す [元に戻す] は、画面で隠して取り消しの時間（8 秒）が過ぎてから API の削除を送る方式（保存の形を変えない。途中でタブを閉じると取引は残る側に倒れる。ADR-0007）
- **書きかけは黙って消さない**（#75・ADR-0019）: 記録する画面・編集の画面の書きかけ（欄・明細の読み取りの結果と残りの行・チャートの画像と時間足）は、画面を移っても同じタブの記憶に残し（端末の保存先・URL・履歴には書かない。7.5 の「画像を保存しない」）、戻ると復元する。離れたら「〜は残っています」+ [記録に戻る] / [編集に戻る] のトースト。[キャンセル]（記録する画面は見出しの右・幅 720 以上は帯にも、編集の画面は [保存] の左。保存中は押せない）は入力が無ければ前の画面へ、あれば確認なしに捨てて「〜を破棄しました」+ [元に戻す]（8 秒。削除と同じ）。明細の読み取り中の [キャンセル] は先に読み取りを止める（1 日の上限の数え方は変えない。8.2）。確認のダイアログはタブを閉じる・再読み込み（書きかけが消える）のブラウザの確認だけ。ログアウトで全部捨てる。借り直したら見出しの下に「前の入力の続きです（N 分前）」（決済の時刻が開いたときのままならその旨）、離れて残している間はナビの [記録する]・詳細の [編集] に印の点（黙って戻さない）
- **色は規律を表す**: 色を使うのは判定の段（計画どおり = A・計画どおりの勝ち / 崩れ = B・危ない勝ち / 極悪 = C / 中立 = 判定なし）だけ。R・円の数字には色を付けず、符号（+ / − / ±）と単位で読ませる（C34）
- 判定に効く言葉（3 つのタップ・判定・R・LC の物差し・詳細のタップの答えの札）の横に「i」の説明（押して開く吹き出し。3 つのタップは選択肢を隠さないよう上を先に開く。もう一度押す・Esc・戻る・外を押すで閉じる。戻るで画面ごと前へ移らない）。説明の文の中の用語集の言葉はリンクで、押すとその言葉の説明へ替わり、何段たどっても戻る・Esc で 1 つずつ前の説明へ戻って最後に閉じる。説明の文は用語集のデータ `ui/src/lib/glossary.ts` の 1 か所だけに置き、定義は 3 章・5 章のまま言い換える（定義を足さない。値・警告は入れない）。判定の名前はバッジと同じ言葉。送る前の注意の補足も同じ「i」にする（3 つの中身は畳まない。7.5）（#57）。同じデータの用語集の画面（`/glossary`。設定と「i」の「用語集で見る」から開く。項目の中の言葉からページの中のリンクでたどり、戻るで 1 つずつ戻る）を置く（#76）
- **画面の言葉は [`docs/ui-guidelines.md`](ui-guidelines.md) 8 章の用語集が正**（#74）。この設計書とコードは内部の呼び名（崩れの条件・3 つのタップ・建てた時刻 など）のまま使い、画面には用語集の対応表（8.3）の言い方（根拠が崩れる条件・決済までの行動・エントリーの時刻 など）で出す。操作の言葉は一般的なアプリの言葉（キャンセル・追加・削除・保存・再読み込み など）にそろえる
- 画面の原則・規則・画面を触る PR のチェックリストは [`docs/ui-guidelines.md`](ui-guidelines.md)（#3 で option-simulator の文書から移植した）。見た目の値はトークン（`ui/src/styles/tokens.css`）に閉じ込め、幅 360〜1440px の崩れと当たりの大きさは `npm run ui:check` で数値で確かめる

### 10.1 セキュリティとプライバシー

- 利用者の分離は API で強制する（AC5 をテストで固定）
- 本番はオーナーだけが使う（許可リストを API で強制。C39）。画面の 403 の表示は見た目で、守りは API
- CSP（インラインの script / style なし、HTML 文字列を DOM に入れない）。本番の CSP のヘッダの土台は #42（すべての応答。`api/src/loss_note_api/web.py`）
- Google ログインはポップアップのまま、本番の CSP のヘッダで gapi の script（`https://apis.google.com`）・authDomain の iframe（`frame-src`）・Identity Toolkit と Secure Token の API（`connect-src`）だけを足す。style・font・img は自分のオリジンだけのまま（gapi は iframe の位置・大きさを style の属性ではなく値で付けるので掛からない見込み。本番で違反が出たら ADR-0003 に書いて直す）。authDomain は変数から受ける（C40・ADR-0003）
- ログに記録の中身・メールを出さない
- リポジトリは公開なので、追跡中のファイルに個人の値（メール・ホームのパス・プロジェクト ID と番号・Cloud Run と Firebase のホスト名・スプレッドシートの ID・オーナー名・トークンと鍵）が無いことを CI で検査する（形の検査と、secrets から渡した値の検査。検査に実値を書かない。出力はファイル名と行番号だけ。#80）
- 決済明細の読み取りで読んだ会社の名前は API の中で利用者ごとの一方向の鍵（秘密の値を使わない仮名化。uid と保存先を読める人は候補の総当たりで戻せる）に変えてすぐ捨て、応答・画面・ログ・保存先に出さない。覚えるのは鍵 → 口座の ID と時刻だけ。口座番号・氏名は読まない（記録する画面で切り取ってほしいと頼んでいるのと食い違わないため。C45・ADR-0017）。鍵は覚える要求の URL のパスとして基盤のリクエストのログに残る（uid は残らない）
- データの書き出し（JSON / CSV）とアカウントの削除を MVP に入れる
- 利用規約・プライバシーポリシーは、オーナー以外の利用者を受け入れる前に用意する

## 11. オーナーのデータの取り込み（K7）

一度だけの作業で、製品の機能にしない（画面・API・保存の形は変えない。#29）。

- **写しと道具**: シートは .xlsx に書き出し、チャート画像のファイルと一緒に手元の `data/local/`（gitignore）に置く。取り込みの道具（使い捨て）もそこに置き、リポジトリに入れない。道具は手元の写しだけを読み、元のシート・Drive・Sheets の API には触れない。検査と文書の組み立ては API のモジュール（記録の検査・銘柄の検査・名前の同一視・snapshot の組み立て・チャートの検査）を同じプロセスで使い、取引の文書は API が作るものと同じ形にする
- **リハーサル**: 本番の前に同じ写しを手元のエミュレーターの架空の利用者に通し、取り込む件数・取り込まない件数（理由ごと）・判定の分布（`core` の判定）・元の判定との食い違い・チャートの枚数を数える。本番で流した後に同じ数が出ることを確かめる。Issue・PR には件数と割合だけを書く
- **取り込む行**: 日時・銘柄・L / S・イン・数量・決済・損益がそろう行だけ。そろわない行は取り込まず、理由ごとの件数を報告する
- **写し方**: 決済済みの取引として、出どころ「取り込み」・口座は付けない（= 既定の口座。C41）。日時 → 決済の時刻（日本時間。日付だけの行は 0:00）/ イン・数量 → 1 つ目のエントリー / 決済 → 決済の価格 / 為替 → 決済の為替 / 損益 → 明細の損益 / TP は数のときだけ / 優位性 → 根拠 / 総評 → 決済時の総評。手数料なし。注文の種類・決済の理由・窓・滑り・逆指値を入れた・LC の根拠は既定値（不明・その他・未回答・未回答・チャート）。「〃」は直前の行の同じ列の値
- **LC**: 数で、L はインより下・S はインより上のときだけ LC に入れる。「-」・空・利益の側・インと同じは LC を空にし、総評の先頭に「シートの LC は使えない形（利益の側 / インと同じ / なし）」と書く（保存の検査 C11 を通らず、入る前の LC も分からないため）。LC を空にした行は「判定が当てにならない行」として別に数える
- **3 つのタップ**（シートに無い）: LC を入る前に決めていたか = 損失種別が C なら「決めていなかった」、ほかは「決めていた」。LC を動かしたか・時間足を変えたかは「動かしていない」「変えていない」。シートに事実の無いものを損失種別から推さない（推すと 5.3 の判定が元の判定の写しになり、比べる意味が無くなる）。オーナーは直す画面で直せる
- **資金**: 当時の資金が分からないので、取り込んだ取引の資金は未設定で写す（過剰リスクは見ない。C33）。許容リスクは既定の口座の値。今の口座・設定は変えない
- **元の判定**: シートの損失種別（A / B / C / 空）は欄を足さずに、総評の先頭の 1 行「【取り込み】元の判定 B」の形で残す。5.3 の判定との食い違いは取り込みのときにクロス表の件数で報告する（元の判定を画面に並べて出す機能は作らない）
- **銘柄**: 名前の同一視（4.1）で既存の銘柄に合わせ、無いものだけ作る（乗数 1。価格の通貨はその銘柄の行の為替がすべて 1 なら JPY、ほかは未設定。原資産の種類は名前から当て、当たらなければ「その他」・商品の形は「現物・CFD」）
- **チャート**: 1 取引 2 枚まで（シートの 1 枚目 → エントリー時、2 枚目 → 決済時。3 枚目は枠が無いので取り込まない）。上限（ADR-0006）を超える画像は縮める。時間足は空。取り込まなかった枚数を理由ごとに報告する
- **二重にしない・やり直せる**: 取引と取り込みで作った銘柄は決まった ID（シートの行番号から）で作り、既にあれば書かない。取り込み済みのアカウントにもう一度流すと何も書かずに止まる。消す手順は、取り込んだ取引・そのチャート・取り込みで作った銘柄（ほかの取引が指していないもの）だけを消し、手で記録した取引・前からある銘柄・口座・設定は残す
- **集計**: 取り込んだ取引は計画どおり率などの集計から既定で外す（6.1。計画の時刻も保有中の履歴も無いため）。判定の印は一覧・詳細に出る
- 為替・損益はシートの値をそのまま使う（5.1 の式と食い違う行は件数だけを報告する）
- **取り込まないもの**: 気付きのタブ（気づきの記録 4.4 を作る Issue で扱う）、オプションのシート（組み合わせのポジションの形が要る。#32）、非表示の「実」の列

| 数十件で崩れ方の傾向が読める | 件数の少ない切り口を出さない（6.1）。期間の振り返りを月単位にする |

### 13.4 リスク
