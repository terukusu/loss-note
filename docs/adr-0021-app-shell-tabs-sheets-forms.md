# ADR-0021: 画面をアプリの殻（下のタブ・3 つの重ね方・3 つの形）で組み、依存を足さずに作る

- 状態: 採用
- 日付: 2026-11-20
- 関連: 設計書 0.4（K16〜K18）・9 章、`docs/ui-guidelines.md` 9 章（P1・P5〜P9・P12 の一部を置き換え。9.11）、ADR-0002（画面の行き来）、ADR-0007（削除の [元に戻す]）、ADR-0018（サービスワーカーを置かない）、ADR-0019（書きかけ）、Issue #38・#68・#86・#110・#117・#121・#123

## 背景

画面は機能を足した順に、1 枚のページへ縦に積んできた。390×844 で、主な 6 画面のうち 1 画面に収まるものは 0（ホーム 1,418px・振り返りに取引があると 2,022px・開いた直後の記録する画面 2,528px・設定 2,287px。架空の値の検査の画像で測った）。どの画面にも同じサイトのヘッダーと大きな h1 があり、階層はすべて「その場で開く」折りたたみと吹き出しで、開くたびにページが下へ伸びる。[記録する] は 3 か所にあり、記録中も下のタブが出て、下に固定の帯が 2 段（128px）重なる。境目は幅 720px の 1 つで、スマホの横向き（844×390）は PC の形（上の帯 60px のナビ）になり、記録する画面の見える範囲は 270px ほどしか残らない。[キャンセル]（文字だけの ghost）や本文の「‹ 一覧」のように、文字だけのリンクの見た目の操作もある。

オーナーの言葉（2026-11-19・20）:

> なんかゆーあいがうぇぶっぽくない？さいしょのがめんなんかきじかのようにしたにつらつらつづいてるし。

> 画面デザイン ui/uxはそろそろ本格的なのにしないとあとからかえづらくない？

> pc番もデザインしているよね？横長の。あと、スマホの横中もどうするか考えないとだよ。

> キャンセルの導線がハイパーリンクみたいなテキストなのやばいよ？あぷりのゆーあいちゃうやん

第一原則は記録の手間の予算（事後に 1 回・30 秒。設計書 1.1 の 0）で、決済の直後にスマホの縦で片手で記録する。今の形では、読み取った欄を確かめた後に、手で入れる LC が 2 画面目、3 つのタップが 2〜3 画面目にあり、探す時間とスクロールが 30 秒を削る。オプションの画面（#117）・good / more（#123）・気づき（#86）がこれから入るので、作り直すなら今が手戻りの少ない時期になる。

## 決定

1. **アプリの殻**（`layout/Shell.tsx`）が、ナビ・画面の重ね方・画面の形・行き来を 1 か所で持つ。画面の View は形を知らない（View の中の並びの段は列の幅のコンテナクエリ）
2. **ナビは下のタブ 4 つと真ん中の ［＋ 記録］**: ホーム・取引・振り返り・設定（K16）。タブは行き先、記録は作業で、［＋ 記録］ は決済の記録へ直行する。5 つ目のタブは作らない
3. **行き来は iOS のタブの作法に寄せる**: タブはそれぞれ次の画面の積み重ねを（タブの記憶の中に）持ち、切り替えると前の積み重ねが戻り、同じタブをもう一度押すと根へ戻る。ブラウザの履歴はいつも「ホーム + 今のタブの積み重ね + 開いている層」の形に保つ（切り替えは `history.go(-k)` で根まで戻して置き換え、記憶の積み重ねを push し直す）。戻るは今のタブの積み重ねを 1 つ戻り、ホーム以外のタブの根ではホームへ、ホームの根ではアプリを出られる（ブラウザ・OS に任せる）。履歴を組み直すのは、今の項目の `history.state` にアプリの印が無いとき（新しく開いた・外から来た・共有）だけで（`/trades/a` → `[/, /trades, /trades/a]`）、再読み込み・bfcache・前へ / 次へでは組み直さず印から記憶を戻す。再読み込みで今の項目が `back-stack` の層の段なら、黙って 1 つ下の画面の段へ戻る。全画面のシートはどのタブの積み重ねにも残さず、タブを替えたら閉じて書きかけを残す。規則と例は `docs/ui-guidelines.md` 9.7
4. **重ね方は 3 つ**: 次の画面（横から。タブは残る）・全画面のシート（下から。記録する・編集。タブ・レールを隠す。広い形はサイドバーを残したパネル）・下のシート（補足と小さな入力）。部品は `<dialog>` の 1 つ `Sheet` で、戻るの層 `back-stack` に載せる。Android の Chrome が戻るを dialog の close に回す（close watcher）ときは、UI で閉じたのと同じに扱って段を戻す。その場で伸びる折りたたみと欄に重なる吹き出しは使わない
5. **形は 3 つ**: 縦（下のタブ・1 列）・横（高さ 500px 未満かつ幅 600px 以上。左のレール・2 列）・広い（幅 1024px 以上かつ高さ 500px 以上。左のサイドバー・2 列 / 一覧と詳細の分割）。**キーボードを除いた** 幅と高さだけで決め、pointer は形に使わない。純関数 `lib/form-factor.ts` が決め、殻が `<html data-form>` に書き、CSS はこの属性で切り替える（メディアクエリで形を決めない）。形を止めるのはキーボードの開閉で高さだけが変わったとき（`interactive-widget=resizes-content` で窓が縮んでも替えない）。向きが変わったとき（`orientationchange`・`screen.orientation`）と幅が変わったとき（折りたたみの開閉・窓の大きさ）は入力中でもすぐ替える。記録する・編集は形が替わっても View を包む DOM を同じに保ち、`data-form` の CSS だけで並びを替えるので、入力中の欄の値とフォーカスは残る。広い形のナビの段（1280 の境）も `data-nav` に書く。シートは形で見せ方を替える（縦 = 下から・横 = 右のパネル・広い = 吹き出し / 中央のダイアログ）
6. **タブの根は 1 画面**（等倍の文字のとき）: ホームは直近の流れ（主役）・今月の規律の 2 つの数字・直近の取引 3 件で、390×844 の縦のスクロール 0px（K18）。記録する画面は読み取った欄を要約に畳み、LC・一言・3 つのタップ・判定を 1 画面に置き、**読み取りを待たずに** 開いた直後から入れられる（K17・C23。読み取りの結果は要約に流れ込むだけ）。文字の拡大では縦のスクロールを許し（WCAG 1.4.4）、横スクロールは 0 のまま。規律の振り返りは振り返りのタブ（`/review`）へ移す
7. **操作は押せる形**: ボタンは 3 段（面の塗り = 1 画面に 1 つ / 枠か薄い面 / アイコン）とチップと押せる行（右に ›）。全画面のシートのキャンセルは、どの形でもシートかパネルの左上の ✕ のアイコンのボタン（読み上げの名前「キャンセル」）。文字のリンクの見た目は文の中で用語集などへ移るときだけ
8. **依存を足さない**: CSS（`@starting-style`・`dvh`・`env()`・コンテナクエリ）と、ブラウザの `<dialog>`・View Transitions API・`visualViewport` だけで作る。無いブラウザでは動きなしで同じ結果にする
9. **安全域とキーボード**: viewport に `viewport-fit=cover` と `interactive-widget=resizes-content`、安全域はトークン `--safe-*` を通す。キーボードは `visualViewport` の薄い層（`lib/keyboard.ts`）で印のクラスを付け、記録する画面の下の帯を判定の 1 行に畳む（窓が縮む Android ではキーボードの上に付き、縮まない iPhone では隠す。裏に置かない）
   - 2026-11-21 の追記（#172・#173）: キーボードの間の下の帯の扱いを替えた。「判定の 1 行に畳み、Android ではキーボードの上に残す」をやめ、**キーボードが出ている間は下に貼り付いた帯を隠し、閉じたら戻す**。入力中の欄は中央へ送らず、見える範囲に入るだけ動かす。決定キー（`enterkeyhint`）で次の欄へ進み、最後の欄で閉じる。理由は、キーボードの上に帯を残すと入れている欄の見える所が無くなること（オーナーの実機の指摘）。規則は `docs/ui-guidelines.md` 10.1・9.6
   - 2026-11-22 の追記（#183）: 帯を隠すだけでは、キーボードを閉じないと ［記録する］ に届かなかった（スクロールしても出てこない）。**キーボードが出ている間は、下に貼り付いた帯を隠さず、スクロールする本文の最後に置く**（同じ要素の位置だけを CSS で替える。ボタンは 1 つのまま）。キーボードの上に帯を残さないこと・入力の欄の場所を狭めないことは前のまま。押したときだけ送り（欄の Enter の暗黙の送信は止める）、送る前にフォーカス中の欄を外して入力を確定させる。閉じたら下の端に貼り付いた帯に戻す（ui-guidelines 10.1）
10. **URL は変えない**（ADR-0002・P6）: 記録するは `/record`、編集は `/trades/{id}/edit` のまま見せ方だけが全画面のシートになる。振り返りの `/review` と設定の下の画面の経路を足す
11. **段階で入れる**: EPIC の子 Issue（1 Issue = 1 デプロイ）が、縦の形（殻 → ホームと振り返り → シート → 記録する → …）から順に入れ、横と広いの形は後に入れる。どの Issue でも、マージした時点で 3 つの形のどれでも使えることを保つ。殻（U1）の時点で振り返りのタブは出し、行き先の `/review` は今のホームの規律の振り返りの部品をそのまま出す（ホームにも残る）。U2 で振り返りのタブを作り直し、ホームから外す。作り直していない画面は今の形のまま動く。記録する画面は U4 で新しい View を全部の幅に 1 列で出し、全画面のシートで見せるかだけを殻が選ぶ（旧の View を形ごとに残さない。2 列は U10）

## 選択肢

- **今の縦に積むページのまま、見た目（トークン）だけを整える**: 変更は小さいが、1 画面に収まらない・その場で伸びる・下に帯が 2 段・横向きで中身が残らない、の構成の問題は残る。オーナーの「うぇぶっぽい」「あとからかえづらくない？」に答えない。採らない
- **ルーターごと入れ替える**（タブごとの履歴の積み・シートの経路を持つ外部のルーター）: タブごとの状態の保持は手で書かずに済むが、ADR-0002 の History API の作り・`back-stack` の層・書きかけの置き場（ADR-0019）・`appDepth` の「前の画面」を作り直すことになる。今の router に「タブごとの積み重ねを記憶に持ち、切り替えで `history.go(-k)` して push し直す」「直接開いたら履歴を組み直す」「シートは層」の規則を足せば足りる。採らない
- **依存を足す UI ライブラリ**（シート・タブ・トランジションの部品集）: 部品は早くそろうが、CSP（インラインの style を使わない。P11）・トークンに見た目を閉じる約束（P12）・判定の色の約束（P2）に合わせる手間が大きく、直接の依存の 14 日の規則と版の固定の手間が増える。`<dialog>` と View Transitions で同じことができる。採らない
- **記録する画面を手順に分ける**（貼る → 確かめる → LC と答え → 判定。［次へ］ で進む）: 初めてでも迷わず、読み取った値を必ず目で通るが、タップが 2〜3 回増え、判定がその場で変わるのが見えない。オーナーが 1 画面（K17）を選んだ。採らない
- **設定をタブにせず歯車にする（タブ 3 つ）**: タブが「見るもの」だけになるが、真ん中のボタンが置けず ［記録］ が親指から遠くなる。オーナーがタブ 4 つ（K16）を選んだ。採らない
- **右下に浮かぶ ［記録］（FAB）**: 一覧の行の右端（R）を隠し、iPhone のアプリの作法と違う。採らない
- **形の境目を幅だけにする（M3 の Window size classes）**: スマホの横向きが PC の形になる。高さを見る。採らない
- **形をメディアクエリだけで決める**: 作りは簡単だが、`interactive-widget=resizes-content` の Android でキーボードが出ると窓の高さが縮み、折りたたみの開いた縦（690×830 前後）やタブレットの横（1280×800）が「横」に替わって入力中の欄が作り直される。形はキーボードを除いた大きさで純関数が決め、入力中は固定する。採らない
- **入力中は向き・幅が変わっても形を止める**: 入力中の欄は作り直されないが、横の 2 列が縦の 390px に残って横スクロールが出る（P7 に反する）。DOM を同じに保てば止める必要が無い。採らない
- **`interactive-widget` を足さない**: 形は替わらないが、Android でキーボードの分だけ窓が縮まず、下の帯がキーボードの裏に残る。形を固定する規則があれば足してよい。採らない
- **タブの切り替えで履歴をすべて置き換える（タブごとの積み重ねを残さない）**: 作りは簡単だが、取引の詳細を見ている途中で設定を見て戻ると詳細が消え、iOS のタブの作法と違う。採らない

## 追記（2026-11-20。#127 の実装）

- 決定 3 の「切り替えは `history.go(-k)` で根まで戻して置き換え」は、**ホームの段まで戻して B の根と記憶を push し直す** に読み替える（置き換えると前のタブの「進む」側の段が残り、進むで別のタブの画面へ入れるため。履歴の形は同じ）。戻る段の数は今の項目の印の深さで決め、画面が自分で積む段（用語集の中でたどった `#…`）も深さに数える
- 決定 3 の「印の無いとき履歴を組み直す」は、**組み直しを書くのを利用者の最初の操作のときにする**（操作なしで積んだ段は Chrome が戻るのボタンと `history.go` で飛ばすため）。既知の挙動として、直接開いて一度も触らずに戻るとアプリを出る（Android の戻る・iPhone の端からのスワイプとも）。ログアウトはホームの段まで戻ってからログインの画面へ置き換え、タブの記憶を捨てる。ログインの後の置き換えで組み直す
- 規則と例は `docs/ui-guidelines.md` 9.7 の 2・5

## 追記（2026-11-20。#129 の実装）

- 決定 4 の `Sheet` は、広い形の説明の吹き出しを CSS の anchor positioning（`position-area`・`position-try-fallbacks`）で「i」に付ける（最上層の dialog では `.info-wrap` に対する絶対配置が使えず、style 属性も使えないため。`infoPlace` は外した）。anchor positioning が使えないブラウザでは中央に置く
- close watcher の制約: Android の Chrome は、利用者の操作をはさまずに続けた 2 回目の戻るの `cancel` を取り消させないので、たどった説明を見ている間でもシートごと閉じる（画面は移らない）。キーの Esc は dialog の `keydown` を取り消して自分で扱い、1 つずつ戻す
- シートの中のリンクで別の画面へ進む（「用語集で見る」）ときは、層の段を巻き戻してから積む（印の深さと実際の段をそろえ、タブの切り替えの `history.go` がホームに届くように）

## 結果

- 既存の画面の 3 層（純関数 → controller → hook を持たない View）は保つ。変わるのは View と CSS と殻で、controller と純関数はほぼそのまま使う。形を知るのは殻と `lib/form-factor.ts` だけ
- 書きかけの置き場（ADR-0019）・一覧の入れ物（ADR-0016）・戻るの層（`back-stack`）・削除の [元に戻す]（ADR-0007）は、そのまま土台に使う。ADR-0019 の決定 5（`appDepth` の前の画面）・11（同じ URL の push は置き換え）は決定 3 の行き来の規則に読み替える（ADR-0019 に追記した）
- `docs/ui-guidelines.md` の P1（行き先・貼り付きの帯・折りたたみ・開いた直後の 1 画面・口座の Segment）・P2（強調の色の使い所）・P4（[キャンセル] の ghost）・P5 / P8（「i」の吹き出し）・P6（タブの履歴）・P7（720px の 1 つの段）・P9（動き）・P12（角丸の値）の一部を、9 章の規則で置き換えた（9.11）。判定・計算・保存の形・API は変えない
- `ui:check` の窓が 4 から 9 に増え（844×390・932×430・1024×768・1280×800・1280×600）、「1 画面に収まる」（等倍の文字）・境目の両側・安全域の差し替え・キーボードの状態とキーボードで形が替わらないこと・シートが窓の中・文字のリンクの見た目の操作の数の検査を足す。記録する画面の全長の上限（R12）は読み取りの後のスクロール量に置き換える
- 移行の間は、新しい形の画面と古い形の画面が混ざる
- 安全域・状態のバーの色・キーボードの出入りは Chromium で確かめられないので、実機（ホーム画面に追加した iPhone）での確かめが殻の Issue に要る
- View Transitions・`@starting-style`・`interactive-widget` はブラウザの版で対応が分かれる。無いときは動きなし・今の動きに落ちる
- #38（広い画面の 2 列）は広い形の 2 列の一部として入る。#110 の吹き出しの件はシートで解ける。#117（オプションの画面）は刷新の後に新しい構成（足の札 → 足のシート）で作る
