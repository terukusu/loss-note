# ADR-0019: 記録・編集の書きかけは、画面を移っても同じタブの記憶に残し、[キャンセル] は捨てて [元に戻す] で戻す

- 状態: 採用
- 日付: 2026-11-19
- 関連: Issue #75（記録する画面と編集の画面にキャンセル）、設計書 7.5・9.1・C38、`docs/ui-guidelines.md` P4・P6、ADR-0002（画面の行き来）、ADR-0005（明細の画像を保存しない）、ADR-0007（削除の [元に戻す]）、ADR-0010（明細の読み取りの 1 日の上限）、ADR-0013（読み取りの準備）

## 背景

記録する画面と編集の画面の controller は画面ごとに作られ、画面を離れると捨てていた。下のナビ・ブラウザの戻る・「用語集で見る」で移るだけで、入力・貼り付けた明細の読み取りの結果・チャートが確認なしに消える（#57 は、そのために記録する・編集の画面から用語集へ移らないようにした）。記録は「事後に 1 回、30 秒」が第一原則で、1 回でも消えると記録をやめる理由になる。一方で「入力を破棄しますか？」のダイアログは P4（取り消せるなら確認しない）に反し、30 秒も食う。

## 決定

1. **書きかけの置き場**（`ui/src/lib/drafts.ts`）をアプリの殻に 1 つ置く。記録する画面は 1 つ、編集の画面は取引ごとに、controller ごと預かる。画面は開くときに借り（残っていれば読み込み直さない）、離れるときに返す
2. **残すかどうか**は書きかけの状態（`ui/src/lib/draft-status.ts`）で決める。入力がある（記録: 開いたときの既定から欄が変わった・明細・チャート・付属の枠・口座の追加の欄 / 編集: 開いたときから欄・チャート・付属の枠・計算に使う値が変わった）・保存中なら残し、入力が無い・保存し終えたなら捨てる（次に開くと既定と今の時刻で作り直す）。記録する画面で離れている間に保存し終えた結果は、戻ったときに 1 度見せる
3. **離れたとき**: 入力があれば「記録の入力は残っています」/「編集の変更は残っています」+ [記録に戻る] / [編集に戻る] のトースト（8 秒で閉じる。書きかけは残る）。明細の読み取り中に離れても読み取りは止めず、戻ったときに結果が入っている
4. **[キャンセル]**（記録する画面は見出しの右 = 下の帯は 1 段・文 1 行のまま 360px に収める #33。幅 720 以上は帯の [記録する] の左にも。編集の画面は [保存] の左。どちらも文字だけの ghost。保存中は押せない）: 先に明細の読み取りを止め（要求を中断。1 日の上限の予約は今のまま精算まで残る = ADR-0010 は変えない）、入力が無ければそのまま前の画面へ。入力があれば確認なしに取り消し待ちの 1 枠へ移し、「〜を破棄しました」+ [元に戻す]（削除と同じ 8 秒・フォーカスとポインタで止まる）。[元に戻す] でその画面へ進み、同じ controller が戻る。時間が過ぎた・次の破棄・閉じた・同じ画面を開き直したら本当に捨てる（画像のプレビューを閉じる）
5. **前の画面**: router が `history.state` にアプリの中で進んだ深さ（`appDepth`）を持ち、深さがあれば `history.back()`、無ければ（URL を直接開いた）記録する画面はホーム・編集の画面は詳細へ置き換える。戻るの層（`back-layers.ts`）は state を写して段を積むので深さは保たれる
6. **記憶の中だけ**: 書きかけ（画像を含む）は端末の保存先・URL・履歴に書かない（ADR-0005・C38）。そのため再読み込み・タブを閉じると消えるので、書きかけがある間だけ `beforeunload` でブラウザの確認を出す（このアプリで確認を出す唯一の場所）
7. **ログアウト**（ログインが切れたを含む）で書きかけを全部捨てる（次の利用者に見せない）。取引の削除が確定したら、その取引の編集の書きかけも捨てる
8. #57 で止めた「記録する・編集の画面の『i』の『用語集で見る』」を戻す
9. **黙って戻さない**: 離れていた書きかけを借り直したら、見出しの下に「前の入力の続きです（N 分前）」（決済の時刻が開いたときの自動の値のままなら「決済の時刻は開いたときの 〈時刻〉 のままです」）と [キャンセル] への導きを 1 行出す。離れて残している間は、ナビの [記録する]・詳細の [編集] に印の点（読み上げ「入力の途中あり」）
10. **知らせは 1 つ**: 新しい知らせは前の知らせを置き換え、押さなかった破棄の [元に戻す] はそのとき確定して画像を捨てる。画面を開いたときに閉じるのは、その画面自身の知らせと、別の取引の編集の知らせ（編集を開いたとき）だけ（記録を破棄して前の画面 = 編集に戻っても [元に戻す] を押せる）。離れたまま保存し終えたら印の点を外し、保存の後の [次の取引] には続きの 1 行を出さない。今いる画面のナビを押したときは積まずに置き換えるが、見出しへのフォーカスと先頭へのスクロールは今までどおり。編集の知らせには取引の短い名前（削除のトーストと同じ）、破棄の知らせには画像の枚数（「チャート 2 枚・明細を含む」）を添え、書きかけの [元に戻す] の読み上げは「記録の入力を元に戻す」「編集の変更を元に戻す」（削除の [元に戻す] と見分ける）
11. **同じ画面への行き来は積まない**: 今と同じ URL（パス + 検索）への push は置き換える（ナビで今の画面を押しても同じ URL が 2 つ積まれず、[キャンセル] の戻るが画面を移す）
12. **読み取りの準備（ADR-0013 の追記 12）は画面に出ている間だけ送る**: 書きかけを借り直したときは読み込み直さないので、開いたときの準備の代わりに `refreshWarm()` の規則（前に送ってから 60 秒以上）で送る（`enterRecordScreen`）。書きかけを残して画面の外にいる間は送らない（離れるときに終わっていない読み取りが後で返っても送らない）。そのあいだに送り直せなかった分は、戻ったときに 60 秒を待たずに送る

## 選択肢

- **確認のダイアログ（[破棄] / [編集を続ける]）**: 標準的だが、毎回読まれなくなり 30 秒を食う。P4 と設計書 9.1 に反する。採らない
- **端末の保存先（sessionStorage・IndexedDB）に下書きを書く**: 再読み込みにも耐えるが、明細・チャートの画像を端末に置くことになり ADR-0005 の「画像を保存しない」に反する。画像を除いて欄だけ書く案も、復元したときに画像だけが無い半端な下書きになる。採らない
- **controller を残さず下書きの値だけを写して残す**: 明細の読み取りの途中・チャートの読み取りの途中を引き継げない。採らない

## 結果

- 画面を移っても書きかけが消えない。[キャンセル] で捨てても 8 秒は戻せる
- 書きかけの画像は同じタブの記憶に残り続ける（編集の書きかけの数に上限は置かない。手で開いた数だけで、タブを閉じれば消える）
- 再ログインで書きかけは持ち越さない（後で要るなら別の Issue）
- 確認の画面が出るのはタブを閉じる・再読み込みのときのブラウザの確認だけ（文言はブラウザが決める）

## 追記（2026-11-20。ADR-0021）

- 決定 4 の [キャンセル] の置き場は、全画面のシートの左上の ✕ のアイコンのボタン（読み上げの名前「キャンセル」。広い形はパネルの左上）に置き換える（`docs/ui-guidelines.md` 9.3・9.12）。捨てて [元に戻す] で戻す規則は変えない
- 決定 5 の「前の画面」と決定 11 の「同じ URL への push は置き換え」は、ADR-0021 の決定 3（タブごとの積み重ね・履歴はいつも「ホーム + 今のタブの積み重ね」・直接開いたら履歴を組み直す）の上で読む。直接開いても下にホーム（編集は詳細）が敷かれるので、`appDepth` が 0 で置き換える場合は無くなる。戻るで全画面のシートを閉じたときは書きかけを残す（決定 3 のまま）
- 書きかけの印の点は、下のタブの真ん中の ［＋ 記録］ と詳細の ［編集］ に付ける
- 再読み込み・bfcache・前へ / 次へでは履歴を組み直さず、`history.state` の `appDepth` などの印をそのまま使う（組み直すのは印の無い最初の起動だけ。ADR-0021 の決定 3。組み直しを書くのは利用者の最初の操作のとき = #127。触る前の戻るではアプリを出る）。今の項目が `back-stack` の層の段なら、黙って 1 つ下の画面の段へ戻る
- 広い形で記録する・編集のパネルを開いたままタブを替えたら、閉じて書きかけを残し「記録の入力は残っています」+ [記録に戻る] を出す（決定 3 と同じ。タブの積み重ねに全画面のシートを残さない）
