# ADR-0004: 記録の API（ID トークンの検証・エミュレーターの守り・保存の形）

- 状態: 採用
- 日付: 2026-11-17
- 関連: Issue #4（API で記録を読み書きする）、EPIC #10（終了条件 2・4）、設計書 4 章・10 章・10.1・2.2 AC5・C21・C36、ADR-0003（ログイン。エミュレーターの ID トークンには署名が無い）

## 背景

記録は利用者ごとの個人の金銭と心理の情報で、正直に書けるのは本人しか見ないと信じられるときだけ（設計書 13.4）。画面の門は見た目だけで（ADR-0003 決定 6）、守りの本体は API での ID トークンの検証と、uid で絞った読み書き。手元と CI は Firebase のエミュレーターで回すが、**Auth のエミュレーターが出す ID トークンには署名が無く、誰でも作れる**（ADR-0003「結果」）。この切り替えが本番で誤って有効になれば、誰でも他人になりすませる。

また、判定は「そのとき決めていたこと」との比較なので、保存して読み戻した記録から同じ判定・理由・R が出なければならない。後で設定の資金や銘柄の乗数を直したときに、過去の取引の 1R・リスク・判定が黙って変わってはいけない。

## 決定

1. **ID トークンの検証は firebase-admin**（`auth.Client.verify_id_token`。署名・kid・alg・iss・aud・exp・公開鍵のキャッシュ）。資格情報は使わない（空の資格情報を渡し、ADC を探しに行かない）。例外の文言にはトークンと aud が入るので、ログにも応答にも型の名前しか出さない。**公開鍵を取れないとき（こちらの都合の失敗）は 401 でなく 503 `unavailable`** にする（401 だと画面がログアウトへ誘導しうる）
2. **起動の判定は純関数 `decide_runtime(env)`**（`api/src/loss_note_api/runtime.py`）:

   | エミュレーターの接続先（Auth / Firestore / Storage） | プロジェクト ID（`GOOGLE_CLOUD_PROJECT`、無ければ `GCLOUD_PROJECT`） | 結果 |
   |---|---|---|
   | どれかあり | `demo-` で始まらない（空を含む） | **起動しない**（`StartupRefused`） |
   | Auth と Firestore の両方あり（`host:port` の形） | `demo-` で始まる | `emulator`（署名の無いトークンを受ける） |
   | 片方だけ / どちらも無い | `demo-` で始まる | 起動しない（誤設定を早く知らせる） |
   | どれも無い | `demo-` 以外で空でない | `verify`（署名を検証） |
   | どれも無い | 空 | `unconfigured`（`/api/health` だけ動き、記録の API は 503） |

   firebase-admin は呼ぶたびに環境変数でエミュレーターかを決めるので、検証の時点の環境が起動の判定と食い違えば 401 にする（守りを重ねる）
3. **トークンの後の検査 `check_claims`**: どのモードでも `exp` が今より後（firebase-admin はエミュレーターでは exp を見ない）、uid が `^[A-Za-z0-9_-]{1,128}$` で、Firestore が予約している `__x__` の形でない（エミュレーターでは誰でも sub を作れるので、`/` を含む uid で他人の場所を指させない）。パスの ID は `^[A-Za-z0-9]{1,40}$` で無ければ保存先に触れずに 404
4. **読み書きは `users/{uid}/...` だけ**（取引 `trades/{id}`・銘柄 `instruments/{id}`・設定 `settings/current`）。ほかの利用者の資源は 404（あるか無いかも分からない）、ほかの利用者の銘柄を指す取引の作成は 400。未認証は資源の有無に依らず 401
5. **取引は記録したときの値を `snapshot` に写して持つ**（資金・許容リスクと、銘柄の乗数・数量の刻み・価格の通貨・原資産の種類・商品の形）。API が作成のときに写し、本文では受けない。直す（PUT）では保ち、銘柄を別の銘柄に付け替えたときだけその銘柄の今の値で写し直す。銘柄・設定を直すと以後に記録する取引に効く（設計書 C36。C21 の「後から設定で直せる」はこれからの記録に効く）
6. **判定・R・損益は保存しない**（設計書 4.2 導出）。保存の形から計算の入力への写しは TypeScript の純関数 `core/record.ts` の `toTradeInput` が正（画面が使う。判定の Python 版は縦切り 3）。TS と Python の項目のずれは、共有の合成の fixture（`tests/fixtures/records/`）を両方のテストに通して捕まえる
7. **本文の検査は純関数**（`api/src/loss_note_api/schema.py`）。知らない項目・列挙外・有限でない数・真偽値の数・C11 の LC の向き・必須の欠け・上限超え（Issue #4 の「入力の上限」）は 400 で、何も保存しない。応答の `issues` は既知の項目の道筋と種類だけで、送った値も知らない項目の名前も返さない。本文は `parse_constant` で NaN・Infinity を拒む自前の読み取り（Flask の `get_json` はそれらを受ける）。文字列は制御文字・孤立したサロゲート・書式文字（`Cf`。双方向の上書き・ゼロ幅文字など）を拒む（長い文章の欄の改行・タブと、絵文字の組み立てに使う ZWJ（U+200D）は受ける）
8. **ログは 1 行 1 JSON の決まった鍵だけ**（出来事・メソッド・ルールの型・状態・時間・例外の型の名前）。本文・トークン・uid・メール・例外の文言・文書のパスは出さない。すべての例外を受けて 500 の決まった本文にし、Flask が例外を自分でログに出す経路を通さない
9. **取引の作成・銘柄の付け替えは、銘柄（と設定）の読みと取引の書き込みを 1 つのトランザクションで行う**。銘柄の削除（指している取引の問い合わせと削除）と同時に走っても、無い銘柄を指す取引を残さない。トランザクションの競合で再試行を使い切ったとき（`Aborted`）・保存先につながらないときは 503 `unavailable`
10. **保存先は約束（`Store`）で抽象化**し、本物の `FirestoreStore` と、テスト用の記憶の保存先で **同じ API のテストを回す**。エミュレーターを使う結合のテスト（Auth のエミュレーターが出した本物のトークン・Firestore の読み書き・ルールがすべて拒否であること）を **CI と確認コマンドに入れる**（`npm run test:api:emulator`。`LOSS_NOTE_REQUIRE_EMULATOR=1` でスキップを失敗にする）

## 選択肢

- **自前の JWT の検証**（PyJWT と公開鍵の取得）: 依存は小さいが、kid の取り回し・公開鍵のキャッシュ・iss / aud / exp の検査を自前で持つことになり、誤りの余地が大きい。採らない
- **銘柄を ID で指し、写すときに今の銘柄の値を使う**（Phase 1 の案）: 自動で足した銘柄（乗数 1）を直すと過去の取引にも効く利点があるが、後から銘柄を直すと過去の取引の 1R・リスク・判定が黙って変わり、「そのとき決めていたこと」との比較が壊れる。採らない（今の値で写し直す操作は #31 で扱う）
- **偽の保存先だけでテストする**: 速いが、Firestore のトランザクション・問い合わせ・型（int / float）の往復と、ルールがすべて拒否であることを確かめられない。エミュレーターの結合のテストを足す
- **エミュレーターだけで API のテストを回す**: 手元の `pytest` に Java を要求し遅くなる。記憶の保存先と両方で回す

## 結果

- 本番でエミュレーターの接続先が誤って入っても、プロジェクト ID が `demo-` で始まらない限り API は起動しない。本番の設定でプロジェクト ID を忘れると記録の API は 503 になる（閉じる側に倒れる）
- 依存が増えた（firebase-admin・google-cloud-firestore と、grpcio などの推移的な依存）。CI と確認コマンドに Java（Temurin 21）とエミュレーターの起動（約 30 秒）が加わる
- 資金を設定する前に記録した取引は `snapshot.capitalYen` が null のまま（リスク（%）は出ず、判定は出す。C33）。銘柄の値を写し直す操作が無いので、自動で足した銘柄（乗数 1）を後で直しても、それまでの取引は乗数 1 のまま（明細に円の損益があれば 1R は明細から逆算するので影響しない。C32）。その後 #31 で、編集の画面で利用者が違いと判定の 前 → 後 を見て「今の値」を選んで保存したときだけ、PUT の `?snapshot=current` で資金・許容リスクと銘柄の値を今の値で写し直す道を足した（黙っては変えない。設計書 C36）
- 一覧は利用者の全件を読んで並べる（#9 は全件を読む。ページ分けは #29 の取り込みの後に件数を見て別 Issue）。一覧の並びは決済の時刻を使う。縦切り 3 で決済の無い取引（計画中・保有中）を受けるときは並びのキーを見直す
- 連打の制限・本番の資格情報（ADC）・Cloud Run の設定は縦切り 2
- ログインの画面に「記録は本人だけが見られます。」を出す（ADR-0003「結果」の約束の文言）
- 本番の使える利用者（Issue #43・ADR-0003「縦切り 2 で決めたこと」・設計書 C39）: ID トークンの検証の後に許可リスト（確かめ済みのメール）を重ね、外れたら 403。起動の判定の表（決定 2）は変えていない。エミュレーターの起動では許可リストの変数が無ければ制限しない
