# 記録の 30 秒を測る手順

事後の 1 回の記録が **記録する画面を開いた時点から判定が出るまで 30 秒以内** に収まるかを、人の手で測る手順です（設計書 1.1 の 0・7.5・13.2 の 1 行目。Issue #15 の AC-15、EPIC #10 の終了条件 11）。画面と部品の速さは自動の検査（`npm run ui:check` の R10）で見ていますが、実物の明細での読み取りの秒数と、人の操作の速さはこの手順でしか測れません。

## 何を測るか

- 始まり: 記録する画面（`/record`）が開き、入力の欄が出た時点
- 終わり: 判定の枠に判定（A / B / C・危ない勝ち・計画どおりの勝ち）と R が出た時点（[記録する] を押す前）
- やること: 決済明細のスクショを 1 枚貼る（PC は Ctrl+V、スマホは [スクショを選ぶ]）→ 読み取りの値を確かめる → LC と崩れの条件の一言を打つ → 3 つのタップを選ぶ
- 手で打つのは LC と一言の 2 つ、選ぶのは 3 つだけです（自動の検査で固定しています。`tests/ui/record-controller.test.ts` の「E1（AC-4）」と `ui:check` の R10）
- 上の手順は明細だけです。チャートの画像（設計書 7.5 の流れ 1）も貼る測り直しは、下の「チャートも貼って測る（#27）」の手順です

## 用意するもの

- 手元の起動（[`README.md`](../README.md) の「手元で動かす」）。端末 2 の API は「決済明細の読み取りを試す」の手順で、AI の SDK と資格情報を入れた端末で起動します（資格情報は環境変数 `STATEMENT_READ_CREDENTIAL` と `ANTHROPIC_API_KEY` または `CLAUDE_CODE_OAUTH_TOKEN`。値は画面・ログ・メモに出さないでください）
- 明細の画像
  - 練習と手順の確かめ: 架空の値の合成の明細 `tools/statement-eval/synthetic/s01.png`〜`s14.png`
  - 本番の計測: 自分の実物の決済明細のスクショ。**口座番号・氏名などは端末の機能で切り取ってから** 使ってください。画像はリポジトリ・Issue・PR に置きません（明細の画像はアプリも保存しません）
- ストップウォッチ（スマホの時計など）

## 手順

1. ログインして、ホームから [記録する] を開く手前で止まる
2. 明細の画像をクリップボードに入れておく（PC）か、写真に入れておく（スマホ）
3. ストップウォッチを始めると同時に [記録する] を開く
4. 画像を貼る（PC: 画面を開いたまま Ctrl+V。スマホ: [スクショを選ぶ] から選ぶ）。「明細を読み取っています…」が出る
5. 読み取りを待たずに、LC と崩れの条件の一言を打ち、3 つのタップ（LC を入る前に決めていたか・LC を動かしたか・時間足を変えたか）を選ぶ
6. 読み取りの値が欄に「読み取り」の印つきで入ったら、銘柄・L / S・イン・決済・数量・時刻を目で確かめる（違えば直す。直した欄は「直した」の印に変わる）
7. 時間帯が明細に無い時刻なら [日本時間で合っている] を押す（違えば欄を直す）
8. 判定と R が出たらストップウォッチを止める
9. [記録する] で保存する（測った取引を残したくなければ、保存せずに画面を離れてかまいません）

## 合否と書き方

- 実物の明細で 3 回測り、**3 回の最大が 30 秒以内** なら合格です
- PR・Issue には **秒数と端末の種類（例: PC の Chromium・iPhone の Safari）だけ** を書きます。明細の中身・銘柄・価格・損益は書きません
- 直した欄の数と、面倒だと感じた所があれば、件数と場面の要約だけを書きます（EPIC #10 の価値の問い 2）

## チャートも貼って測る（#27）

EPIC #10 の終了条件 11 の測り直しです。明細に加えて、根拠の足のチャートを 2 枚（エントリー時・決済時）貼り、チャートの時間足の読み取り（設計書 7.5）も含めて測ります。

- 始まりと終わりは上と同じ（記録する画面が開いた時点 → 判定と R が出た時点）
- 用意するもの: 上の明細に加えて、自分の実物のチャートのスクショ 2 枚（エントリーの根拠にした足・決済の判断に使った足）。練習には架空の合成のチャート `tools/statement-eval/synthetic-charts/c01.png`〜`c14.png` を使えます。実物のチャートも口座の情報などが写っていれば切り取り、リポジトリ・Issue・PR に置きません（チャートは [記録する] で取引と一緒に保存されます）

手順:

1. 上の手順 1〜4 で明細を貼る（読み取りを待たない）
2. エントリー時の枠をクリックして（スマホは [チャートを選ぶ]）エントリー時のチャートを貼る。決済時の枠も同じ
3. 読み取りを待たずに、LC と崩れの条件の一言を打ち、3 つのタップを選ぶ
4. 枠の時間足の欄に「チャートから」の印つきで時間足が入ったら、目で確かめる（違えば選び直す。読めなかった欄は空のままでよい）
5. 明細の欄を確かめ、判定と R が出たら止める。時間足の読み取りは明細の読み取りの後に 1 枚ずつ進みます。読み取り中も [記録する] は押せます（帯に「待たずに記録できます」（時間足の読み取り中は枠に「時間足を読み取っています…」））。待たずに止めた回は、時間足が埋まっていたかも書き留めます

合否と書き方は上と同じ（実物で 3 回・最大が 30 秒以内。秒数と端末の種類だけを書く）。3 回のうち 1 回は **チャートを先に貼ってから明細を貼る順** で測ります（AI の読み取りは 1 つずつなので、明細は送っているチャートの応答を待ってから送られます。この待ちが 30 秒の予算に響くかを見ます）。あわせて、時間足を直した回数と、読めずに空だった回数を件数だけ書きます（Issue #27 の価値の確かめ方）。

チャートの読み取りの精度（読み違い・作り話の件数）は、合成のチャートで道具を流して確かめます（手元。AI の SDK と資格情報が要ります）:

```
cd tools/statement-eval
uv sync --locked --group ai
uv run --locked python -m statement_eval eval-charts --credential api_key --preset app
```

出力の「読み違い」と「作り話」がどちらも 0 なら合格です（空は許す）。PR・Issue には件数と秒数だけを書きます。実物のチャートで測るときは、画像と `answers.json`（`file`・`kind`・`timeframe`・`label_shown`）を `data/local/` の下に置き、`--set real --dir data/local/<置き場所>` を足します。

## 端末ごとの確かめ

- iPhone の Safari: 写真（HEIC）を選んで読み取りまで進むか。読めない画像は「画像を読み込めませんでした。PNG か JPEG のスクショを貼ってください。」が出て、送りません（スクショは PNG なので通常は通ります）
- PC: 画面を開いてすぐ Ctrl+V で貼れるか（枠をクリックしなくてよい）。文字の欄に文字を貼ったときは読み取りに送らず、その欄に入るか

## 実装の担当が架空の画像で通した結果（目安）

2026-11-18、PC の Chromium（Playwright の自動の操作）。合成の明細 `s05.png` を [スクショを選ぶ] で選び、打つ 2・選ぶ 3 を入れて判定・R が出て保存するまで、**画面と部品の側は約 0.5 秒**（`npm run ui:check` の R10。読み取りは偽の応答で、すぐ返します）。

これに、実際の読み取りの秒数（#14 の実測で 1 枚の最大は数秒。API の締め切りは 20 秒）と、人が 2 つ打ち 3 つ選ぶ時間（目安 10〜15 秒）が加わります。読み取りを待たずに入力できるので、両者は重なり、目安の合計は **20 秒前後** です。実際の AI を呼んだ人の計測はオーナーが行います（上の「合否と書き方」）。
