# ADR-0017: 決済明細から口座を選ぶ手がかりは、会社の名前から作った利用者ごとの一方向の鍵だけを覚え、損益は通貨が口座と合うときだけ流し込む

- 状態: 採用
- 日付: 2026-11-19
- 関連: Issue #66、Issue #47（口座・口座の通貨）、ADR-0005（画像も結果も保存しない）、ADR-0010（1 日の上限・予約額）、ADR-0011（資格情報の方式）、ADR-0012（口座）、ADR-0014（利用者ごとの費用）、設計書 4.6・7.5・8.2・10.1、0.2 の C14・C41・C43・C45

## 背景

#47 で口座が 2 つ以上になると、記録のたびに「どの口座か」を確かめる操作が増える。既定は「前回の口座」なので、口座をまたいで取引した日に選び忘れると、別の口座の資金で割られてリスク（%）と過剰リスクの B が黙って誤る（資金 1,000,000 の口座と 200,000 の口座では、同じ取引が 0.5% と 2.5%）。どの会社の明細かは、もう貼っている明細のスクショに写っている。最初の 1 回は本人が選び、それを覚えて次から使いたい（オーナーの「教師データ」）。

また、今の読み取りは「円の損益を読む」指示なので、外貨の口座では損益・手数料を流し込めず（#47 の R7）、円の口座に USD の明細を貼ると USD の数を円として入れうる（1R が約 150 分の 1 に縮み、過剰リスクを見逃す）。

一方で、ADR-0005 は「画像も結果も保存しない」、設計書 C14 は「結果は形の決まった値だけ」と決めている。会社の名前は自由な文字列で、口座の持ち主に結び付く。

## 決定

1. **読み取りは損益・手数料の通貨と、明細を出した会社の名前も読む**。ツール `report_statement` の行に `pnl`（書かれた損益。前の `pnl_jpy` を改名）と `pnl_currency`（英字 3 文字か `unknown`。形が外れたら `unknown`）、最上位に `issuer`（書かれたまま。銘柄の名前と同じ文字の制限・40 字。外れたら捨てる）を足す。AI の呼び出しは 1 枚 1 回のまま。口座番号・氏名・残高・証拠金は今までどおり返さない
2. **会社の名前は API の中で鍵に変えてすぐ捨てる（仮名化）**。鍵 = sha256(`loss-note/statement-profile/v1` ∥ uid ∥ 会社の名前の比べる形 ∥ 行の `side_of` の集合 ∥ 行の通貨の集合) の 16 進の先頭 32 文字（`api/src/loss_note_api/statement_profile.py`）。比べる形は NFKC・大文字小文字・前後と間の空白の違いを同じにする（`statement_read.values.issuer_key`。評価の道具の採点と共有）。読めなかった `side_of`・`unknown` の通貨は集合に入れない。会社の名前が読めない・許さない文字（銘柄の名前と同じ制限。`&`・`,`・`'`・`+` なども外れる）を含む・型が外れたときは鍵を作らない（結果のほかの欄は捨てない）。名前は応答・画面・ログ・保存先のどこにも出さない（応答の `profile` は鍵と口座の ID だけ、ログは `profile=hit|miss|none|unavailable` だけ）。秘密の値を使わない sha256 なので **仮名化に留まる**: uid と保存先を読める人（運営者・バックアップ）は、会社の名前の候補 × 向きの集合 × 通貨の集合を総当たりして鍵から会社の名前を戻せる。会社の名前の機微度（同じ場所に本人の取引の銘柄・価格がある）と、秘密の値を持つ費用（Secret Manager の値・回すときに覚えが全部外れる）から、今はこれで受け入れる（main の決定）。鍵は `PUT` の URL のパスとして基盤（Cloud Run）のリクエストのログに残るが、uid は残らないので総当たりの材料にはならない
3. **覚えるのは鍵 → 口座の ID と時刻だけ**。`users/{uid}/statement_profiles/{鍵}` = `{accountId, updatedAt}`。読み取りは覚えを 1 文書読むだけ（書かない。読めなくても 200 で提案なし）。覚えるのは画面が明細から作った下書きを記録した後の別の要求 `PUT /api/statement-profiles/{鍵}`（本文 `{accountId}`・204）で、口座の存在の確かめと上書きを 1 つのトランザクションで行う（後に記録したものが勝つ）。鍵の形が外れたら保存先に触れずに 404、口座が無ければ 400 notFound。失敗しても記録は成功のまま（画面は黙って捨てる）
4. **提案の口座は条件つき**。口座が 2 つ以上・提案の口座が今の一覧にある・その明細で本人がまだ口座を選んでいない（読み取り中に選んだ・その場で足したを含む）ときだけ、提案の口座を選んで印「自動で選択」を付ける。本人が直したら印は消え、記録すれば覚え直す
5. **損益・手数料は、読んだ通貨が口座の通貨と同じとき（口座が JPY で通貨が不明のときは、銘柄の価格の通貨が JPY か未設定のときだけ）流し込む**。価格の通貨が USD などと決まっている銘柄で通貨が読めないと、USD の損益を円として入れうるので入れない（レビュー P3・main の決定）。違えば入れず、欄の下に理由を出す。口座を替えたら読んだ値についてだけ同じ規則をやり直す（#47 の R7 を置き換える）。API は前からの `pnlYen`・`feesTotalYen` を、通貨が JPY か不明のときだけ値・ほかは null にして返す（古い画面が開いたままでも USD を円として入れない）
6. **口座番号は読まない**。記録する画面で「口座番号・氏名は切り取って貼ってください」と頼んでいる（C38）のと食い違わないため。同じ会社に口座が 2 つ以上あるときは、行の向きの書き方・通貨の違いと「直したら覚え直す」で見分ける（main の決定。足りないかは価値の確かめで見る）
7. **予約額は同じ式で出し直す**。指示とツールの定義が長くなった分だけ、Sonnet 5.5 の明細の予約額は 278,736 から 282,012 µUSD に上がる（ADR-0010 の式のまま。利用者 1.00 USD に 3 回分・全体 2.00 USD に 7 回分が入る形は変わらない）。値を固定するテストは `packages/statement-read/tests/test_pricing.py` の 1 か所にし、ほかのテストの例の表は予約額の式で境界を書く

## 選択肢

- **会社の名前を保存して、設定の画面に覚えの一覧を出す**: 消す・直す画面が作れるが、自由な文字列を保存する（C14・ADR-0005 の守りを崩す）。一覧は後の Issue（直して記録すれば覚え直せる）
- **向きの書き方と通貨だけの鍵（会社の名前なし）**: 会社の名前を扱わずに済むが、会社をまたいで同じ鍵になりやすく、誤って選ぶとリスク（%）の分母が誤る。選ばないほうが安全
- **口座番号の末尾を鍵の材料にする**: 同じ会社の 2 口座を見分けられるが、切り取ってほしいと頼んでいる値を読むことになり、口座に結び付く値を残す
- **覚えを取引の作成と同じトランザクション・同じ本文に混ぜる**: 要求が 1 つ減るが、取引の保存の形と共有の fixture を変え、覚えの失敗が記録を止めうる
- **鍵を API の秘密の値で HMAC にする**: uid と保存先を読める人が候補の総当たりで会社の名前を戻すのを防げるが、秘密の値の管理（Secret Manager の値・回すときに覚えが全部外れる）が増える。鍵は本人の場所にだけあり、uid を混ぜて利用者をまたいで同じにならないので、今は仮名化の sha256 で受け入れる（決定 2）

## 結果

- 2 回目以降の同じ会社の明細で口座が選ばれ、選び忘れでリスク（%）の分母が誤るのを減らす。口座 1 つの利用者は何も変わらない（欄も印も出ない）
- 外貨の口座でも、明細の損益の通貨が口座と合えば損益・手数料が入る。円の口座に USD の明細を貼っても USD の数を円として入れない
- 保存先に増えるのは `statement_profiles` の文書（鍵・口座・時刻）だけ。Firestore のルールは今までどおりすべて拒否（API だけが読み書き）。インデックスは要らない（鍵で 1 文書を読む）
- 鍵の安定（実際の AI が同じ会社の名前を毎回同じに読むか）は、評価の道具の合成の明細（架空の会社の名前 2 通り・16 枚）で `eval --preset app` を手元で流して測る（自動のテストは鍵の作り方と結果の検査だけを見る）。揺れが大きければ鍵の材料を減らす（向きの書き方を外す）か、指示を直す
- 会社の名前が写っていない明細（上部を切り取った）は提案なし・覚えない
- 切り戻すと、前の版は覚えの文書を読まず、`pnl_jpy` の指示に戻る（円の口座の振る舞いは前に戻る。覚えの文書は残っても害は無い）。切り戻しの後に新しい画面が開いたまま古い API に当たると、応答に `pnl` が無いので損益・手数料は「読み取れませんでした」になる（誤った値は入らない。同じ Cloud Run から配るので窓は短い）
- 覚えの文書の数に上限は無い（鍵は画面から送る値で、利用者は自分の場所に形の合う鍵をいくらでも作れる。ほかの利用者に影響しない）。SaaS として開く前に、利用者ごとの覚えの件数の上限（古いものから消す）を後の Issue で決める
- 画面（レビューで決めた見せ方）: 自動で選んだ口座の印は「自動で選択」（読み上げは「前にこの明細で選んだ口座を自動で選びました。違うときは選び直してください」。提案の口座の通貨が明細の損益と合わないときは印を付けない）。覚えの無い明細では口座の欄の下に「この明細の口座を選んでください。次から自動で選びます」、損益の通貨が今の口座と合わずその通貨の口座が一覧にあれば「明細は USD です。USD の口座は 口座 D です」を優先して出す。損益・手数料の下の理由には次の行動（「USD の口座を選ぶか、円の損益を入力してください」）。覚えが無かった・覚えと違う口座で記録したときは、保存の後の 1 行で「次からこの明細は 口座 B を自動で選ぶようにしました」（送信の失敗は知らせないので弱い言い方）
- 評価の道具は、会社の名前の比べる形の一致・明細の組の鍵の安定に加えて、同じ明細を繰り返し読んだときに鍵の材料（会社の名前・向きの集合・通貨の集合）が回をまたいで同じだった枚数を数える（`--repeat` を 2 以上にしたとき意味がある）
