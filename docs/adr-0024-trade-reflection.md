# ADR-0024: 取引の Good / More を取引の文書の最上位に持ち、専用の入口で置き換える

- 状態: 採用
- 日付: 2026-11-24
- 関連: 設計書 C58・C55・4.2・9.4、ADR-0022（心理のタグの保存の形と入口）、ADR-0020 の決定 7（保存の形の版）、Issue #123・#220（保存の後のシートの段）・#221（話題ごとの集計）

## 背景

取引に Good（良かった行動）と More（もっとこうすべきだった行動）を、それぞれ複数残したい（#123）。よく書く行動は決まった話題（ID）から選び、どれにも当たらない一言は自分で書く。付けるのは判定と R を見た後（取引の詳細。後で記録の保存の後のシート = #220）で、押した・足した時点で保存する。

条件は心理のタグ（ADR-0022）と同じ。

1. 後で話題ごとに数える（#221）ので、話題は名前ではなく固定の ID で持つ
2. 判定・R・集計の入力（`record`・`snapshot`）は変えない
3. 前の版へ戻したとき・古いタブの直す画面が保存したときに落とさない

加えて、自分で書いた行（自由記述）を持つ。

## 決定

1. **取引の文書の最上位に `reflection`**（`record` の外）。形は `{"good": {"topics": [ID], "notes": [文]}, "more": {...}}`。話題は側ごとの一覧の順・重複なし。行は足した順。**両側とも空なら鍵ごと消す**（何も付けていない取引は前と同じ形）。取引の応答は付いている取引だけに鍵を足す
2. **書く入口は `PUT /api/trade-reflections`** 本文 `{"tradeIds": [1〜20 件], "good": {"topics", "notes"}, "more": {...}}`（4 つの欄はすべて必須）。指した取引すべての Good / More を 1 トランザクションで **置き換える**（同じ本文を送り直しても同じ結果）。応答は正規化した `{good, more}`。1 件でも無い（ほかの利用者の取引を含む）なら 404 で何も書かない。知らない版の取引には書かない（409 `unknownSchemaVersion`）。保存先の書き口は心理のタグの `Store.set_emotion_tags`（取引の集合を読んで mutate を当てて書く口）を共有する
3. **行の検査**: 0〜10 行。前後の空白を除いて 1〜100 字（コードポイント）、改行・制御文字・書式文字（ZWJ を除く）・行と段落の区切りなし。保存は除いた後の値。誤りの応答は道筋と種類だけで、送った文を映さない
4. **`schemaVersion` は上げない**（ADR-0022 の決定 3 と同じ理由。取引の PUT・チャートの入口・心理のタグの入口は文書を `{**doc, ...}` で組むので鍵を保つ）
5. **話題の ID の一覧は 2 か所で、fixture で突き合わせる**: 画面は `core/reflection.ts`、API は `api/src/loss_note_api/reflection.py`。`tests/core/reflection-fixture.test.ts` が `tests/fixtures/records/reflection-topics.json` を作り、`api/tests/test_reflection_fixture.py` が突き合わせる。ID は足すだけにする
6. **画面は押す・足す・消すたびに値を送り、要求は 1 本ずつ**（`ui/src/lib/reflection-controller.ts`。心理のタグの controller と同じ規則）。失敗したら最後に保存できた値へ戻す。書きかけの文字は消さない

## 選択肢

- **心理のタグの文書の鍵（`emotionTags`）に混ぜる**: 心理（気持ち）と行動は数え方も見せ方も違い、#163 の選択肢の設定・#162 の集計が混ざる。採らない
- **`record.exit.review`（総評）に書き足す**: 自由記述 1 つの欄に戻り、話題を数えられない。直す画面の PUT と同時に開くと上書きし合う。採らない
- **Good / More を別の入口（側ごと）にする**: 1 回の操作で 2 本の要求になり、一部だけ失敗すると食い違う。採らない
- **行に ID を付けて差分で送る**: 1 人で使う前提では、集合ごとの置き換えで足りる（後に届いた値が勝つ）。採らない

## 結果

- 何も付けていない取引の文書・応答の形は変わらない。判定・R・期間の集計は Good / More で変わらない
- 前の版へ戻しても Good / More は文書に残る（画面に出ないだけ）
- 同じ取引を 2 つのタブで同時に変えると、後に届いた値が勝つ
- 保存の後のシートの段（#220）は同じ入口を、同じ明細から保存した取引の集合で呼ぶ
