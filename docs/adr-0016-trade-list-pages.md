# ADR-0016: 取引の一覧は並びの鍵のカーソルでページに分け、画面は末尾に近づいたら続きを読む

- 状態: 採用
- 日付: 2026-11-19
- 関連: Issue #87、ADR-0004（記録の API。「一覧は全件を読んで並べる」をこの ADR で置き換える）、ADR-0007（消すと [元に戻す]）、ADR-0002（戻るで元の位置）、設計書 9.2・10 章・12 章

## 背景

#9 の時点では、取引の一覧の入口 `GET /api/trades` は利用者の取引を全件返し、一覧・ホーム・記録する画面がそれぞれ全件を読んでいた（ページ分けは #29 の取り込みの後に件数を見て決める、としていた）。取り込みで取引が 160 件を超え、毎日増える。ホームは 5 件、記録する画面は前回の 1 件しか使わないのに全件を読むので、記録を続けるほど記録を始めるまでの待ちが延び、事後 1 回 30 秒の予算（設計書 1.1 の 0）を食う。Firestore の読み取りの費用も件数に比例する。

## 決定

1. **API**: `GET /api/trades` に `limit`（1〜100 の整数）を付けたときだけページで返す。応答は `{"items": [...], "next": <カーソル> | null}`。`cursor` を付けると、そのカーソルの位置の後から返す。`order` は `exit`（既定。決済の時刻の新しい順 → 作った時刻の新しい順 → ID の昇順 = 今の一覧と同じ並び）と `created`（作った時刻の新しい順 → ID の降順。前回の 1 件・保存が届いたかの確かめ）。保存先は 1 ページで最大 `limit + 1` 件だけを読む（続きがあるかを見分ける 1 件）
2. **後方互換**: パラメータが無ければ今と同じ（全件・同じ並び・`next` の鍵なし）。デプロイの間の古い画面と、ブラウザに残った古い画面が壊れない。新しい画面は必ず件数を付ける（件数を付けない読みはソースの検査で 0 件にする）。全件の読みを止めるのは、古い画面が無くなった後に別に決める
3. **カーソル**: 並び・並びの鍵の値（決済の時刻・作った時刻・ID）を詰めた base64url の JSON 配列。署名はしない。読む場所は常に検証した uid の `users/{uid}/trades` なので、細工したカーソルでも自分の取引の別の位置にしか届かない。長さ・文字・型・範囲・ID の形（`schema.ID_PATTERN`）を検査し、外れたら 400 `invalid`（欄と種類だけ。送った値を返さない）。`limit` の無い `cursor`・`order`、知らない並び、別の並びのカーソル、同じパラメータの重なりも 400
4. **索引**: 決済の順は複合索引（`record.exit.time` 降・`createdAt` 降・`__name__` 昇。コレクション `trades`）が要るので、`infra/bootstrap/firestore.tf` に宣言する（所有者の apply。デプロイの前）。作った時刻の順は単一フィールドの索引で足りる（不要な複合索引は API が受け付けない）。**索引がまだ無い・作成中で読みが断られた（FailedPrecondition）ときは、全件を読んで切る形に一時的に戻し、ログ `trades_page_fallback` を出す**（apply とデプロイの順が前後しても一覧が開ける。結果は同じ）
5. **画面**:
   - 一覧は 50 件ずつ。末尾の印（見えない 1px の帯）が画面の下 600px の手前に入ったら IntersectionObserver で次のページを読む。[続きを読み込む] のボタンでも読める（キー・読み上げ・IntersectionObserver の無い環境）。読み込み中は同じボタンを「続きを読み込み中…」（aria-disabled・aria-busy）にして高さとフォーカスを保ち、失敗は決まった文言と同じボタンの [もう一度読み込む]（role=alert。読み込み済みの行は残す。失敗の後は自動で読み直さない）。最後まで読んだら件数の文を「全 N 件」にし、2 ページ以上読んだときは末尾に「全 N 件を表示しました」を出す（ボタンにフォーカスがあったら読み足した最初の行へ移す）。途中の件数の文は「N 件を表示中（決済の新しい順・続きあり）」（総数は数えない。数えるには全件の索引を読むため）。読み込みの始まり・終わりと件数は、常に置いた読み上げの欄（role=status）の中身を入れ替えて伝える。「—」の理由の脚注は末尾の段の後に 1 回だけ置き、続きがある間は件数の括弧を出さない
   - 戻るで一覧に戻ったときは、殻（App.tsx）に置いた記憶の中だけの入れ物から、読み込み済みの分を最初の描画で出し、覚えていた位置へ戻す。裏で同じ件数を読み直して差し替える（詳細・直すで変えた取引を反映する。失敗しても出している分と続きはそのまま）。入れ物はログアウト・ログインしていない状態で空にする。端末の保存先には書かない
   - ホームは決済の順の先頭 10 件を読んで直近 5 件を出す（[元に戻す] を待つ取引で隠れても足りるように少し多く）。記録する画面は開いたときに作った順の 1 件、保存が届いたかの確かめに作った順の 10 件を読む
   - 消した印（[元に戻す] を待つ取引）は今と同じく画面の側で隠す。続きを読んでも隠れたまま。見える行が 0 でも続きがあれば空の状態にしない

## 選択肢

- **オフセット（何件目から）でページを分ける**: Firestore のオフセットは飛ばした文書も読み取りに数え、件数に比例する費用が残る。間に取引が増減すると重なり・抜けが出る。採らない
- **カーソルに署名する**: 読む場所が利用者ごとに閉じているので、署名で守るものが無い。鍵の管理が増える。採らない
- **パラメータが無いときも上限つきで返す**: デプロイの間の古い画面が、上限を越えた取引を黙って失う。採らない
- **最初から総数を出す（count の集計）**: 件数に比例する索引の読みが毎回かかる。最後まで読んだときだけ出す
- **戻るで一覧を最初の 1 ページから読み直す**: 読み込み済みの位置へ戻れない（ADR-0002 の「戻るで元の位置」が崩れる）。採らない

## 結果

- 一覧・ホーム・記録する画面の取引の読みが、件数によらず一定（50 / 10 / 1 件）になる
- 本番の apply（索引）とデプロイが 2 段になる。索引が作られる前にデプロイしても、全件の読みに戻るだけで壊れない（ログ `trades_page_fallback` で気づける）
- 作った時刻の順の索引は単一フィールドの既定に頼る（エミュレーターは索引を見ないので、デプロイ後に本番で確かめる。断られても同じく全件の読みに戻る）
- 全件が要る集計（振り返りの画面。縦切り 3）は、一覧の入口とは別に集計の入口を作る
- ページを読む間に直された・記録された取引: カーソルは並びの位置なので、決済の時刻が後ろへ動いた取引は続きのページで 2 度来る（画面は ID で重ねずに後の方で置き換える）。カーソルより前へ動いた・新しく記録された取引は、開き直す・戻るの読み直しまで出ない（一覧を開き直せば揃う）
- 戻った直後は覚えていた分（直す前の判定など）を出し、裏の読み直しで差し替える。読み直しの前・間は続きを読まない（同じ分を読むため）
