# ADR-0027: 両建て（決済の代わり）は取引の外のまとまりで結び、固定した時点の価格で 1 件として判定する

- 状態: 採用
- 日付: 2026-11-28
- 関連: 設計書 C75〜C81・4.8・5.8・6.5・7.7・9.2・13.2、C18（R は価格だけから）・C30・C43（金額は口座の通貨）・C44（判定は画面の core）・C53・C54・C55・C71、ADR-0004（記録の API と保存）、ADR-0007（消す + 元に戻す）、ADR-0012（口座）、ADR-0020（足と保存の形の版）、ADR-0022（心理のタグ）、ADR-0024（Good / More）、ADR-0025（データの書き出し）、EPIC #269・Issue #264〜#268

## 背景

先物の市場が閉まっている間に、24 時間動く CFD で反対の玉を建てて損益を固定する（実質の決済）ことがある（オーナー「先物口座は止まっているがcfdは動いているから利確とか損失確定させるみたいな。複数ポジで構成するかも」「あんまりやらないと思うけど、同一口座でも有るかも。3つ以上の足も有るかも」）。今は先物と CFD が別々の取引で、次の 2 つが起きる。

1. 先物は固定した時点ではなく、後で外した時点で決済したことになり、LC を守れたかが正しく見えない
2. CFD 側は計画の無い取引として C（LC なし）に数えられ、片側の勝ちがもう片側の負けを隠す

条件は 5 つある。

- 記録の手間の予算（設計書 1.1 の 0。事後に 1 回・30 秒）を変えない
- 口座をまたぐ（先物の口座と CFD の口座）。同じ口座・3 件以上・本玉が複数のこともある
- 判定・R の計算は画面の `core/` が正（C44）。API は判定を持たない
- 前の版へ戻したとき（`rollback.yml`）・古いタブの画面が保存したときに、記録を壊さない（ADR-0020 の決定 7）
- オプションの足（4.7）は同じ口座・同じ明細・1 つの 1R が前提で、口座をまたぐ両建てには使えない

## 決定

1. **取引の外の文書 `users/{uid}/positionGroups/{id}`** に、メンバー（取引の ID・役割 `main` 本玉 / `hedge` 決済の代わり・範囲の読みのための時刻の写し）と、決済の任意の上書き `exit`（固定の価格・決済の代わりを建てた注文の種類・決済の理由）と版 `schemaVersion: 1` を持つ。取引の `record` は変えない
2. **取引の文書の最上位に逆参照 `positionGroupId`**（心理のタグと同じ作り。ADR-0022）。書くのはまとまりの入口だけで、取引の PUT・チャートの入口は `{**doc}` で保つ。取引の版は上げない。逆参照で、(a) 1 つの取引は 1 つのまとまりにだけ属すことを結ぶトランザクションの中で見る、(b) 取引を消すときに同じトランザクションでまとまりを直す（本玉か決済の代わりが 0 件になればまとまりを消す）、(c) メンバーの向きを変える取引の PUT を 409 にする、(d) 一覧の行が追加の読みなしにメンバーと分かる
3. **API の検査は形だけ**（2〜10 件・役割の組・向きが逆・足を持たない・本人の取引）。量・時刻・価格の意味（固定の時点・一部・固定を外した）は画面の `core/` が決める（C44 と同じ考え）
4. **固定の時点と価格**: 決済の代わりのエントリーを時刻の順に足して、量（数量 × 乗数）が本玉の量に揃った時刻と、そこまでの建値の量の加重平均（本人が直せる）。一部だけなら部分ごと（残りは本玉の決済）。決済の代わりを最初の本玉の決済より 30 分を超えて先に外したら、その分を固定に数えない
5. **判定は今の 5.3・5.4 を当てる**。本玉が複数なら、1 つの取引の複数のエントリーとみなす（5.1 の買い増しの式・ナンピン・C30）。メンバー単独の判定は出さない
6. **R は固定の価格から（C18）、損益は合計**。R は手数料・為替・通貨・固定の後の値差を含まず、固定した時点で決まる。損益はメンバーの損益の合計で、口座の通貨が違えば通貨ごとに並べて換算しない（換算の為替の欄を足さない）
7. **振り返りはまとまりを 1 件**（期間はまとまりの決済の時刻）。範囲の入口は、時刻の写しの幅が範囲と重なるまとまりと範囲の外のメンバーも返す。心理のタグ・Good / More はメンバーの和で、まとまりの画面で付けるとすべてのメンバーに同じ集合を書く（今の入口のまま）
8. **結ぶのは記録の後に取引の詳細から**。記録する画面は変えない
9. **書き出し**は JSON に `positionGroups` を足す（鍵を足すだけなので `version` は 1 のまま。ADR-0025 の結果）。CSV は列「両建て」「まとまり」を足し、判定・R は最初の本玉の行にだけ入れる

## 選択肢

- **オプションの足（4.7）と同じく 1 つの取引の文書に入れる**: 足は 1 つの口座・1 つの明細・1 つの snapshot（資金・銘柄の値）が前提で、口座・銘柄・通貨の違う玉を入れると snapshot と明細の損益の読み方が崩れる。記録の画面も 2 つの明細を 1 件にまとめる流れが要り、30 秒の予算を超える。採らない
- **まとまりの文書だけ（取引に逆参照を持たない）**: 取引を消すときにまとまりを探すクエリ（`array-contains`）をトランザクションの中で回すことになり、「1 つのまとまりにだけ」も同じ探し方で守ることになる。一覧のページごとにまとまりをすべて読む必要もある。逆参照は鍵 1 つで済み、心理のタグで前の版に戻しても落ちないことを確かめた作りなので、こちらを採る
- **取引の側だけに相手の ID を持つ（`hedgeOf: <取引の ID>`）**: 2 件なら足りるが、3 件以上・本玉が複数・固定の価格の上書きの置き場が無い。互いに指し合う 2 か所を同時に直すことになる。採らない
- **R = 損益の合計 ÷ 本玉の 1R（EPIC の案）**: 外したときの先物と CFD の値差・スワップ・手数料が R に入り、「固定した時点で決まった」という実感と合わない（例: 利確の固定で +1.5R のはずが +1.43R）。口座の通貨が違うと、換算の為替の欄を足さないと R が出ない。単独の取引の R も価格だけから出しているので（C18）、そろえて価格からにした。損益（実額）は合計で見せる
- **期間をメンバーの最後の決済で決める**: 範囲の読みは簡単になるが、金曜に固定して月曜に外した取引が月曜の週に入り、判定の時点（固定の時点）と並びが食い違う。採らない
- **明細から両建てを見つけて自動で結ぶ**: 誤って結ぶと判定が変わる。頻度が低い（オーナー「あんまりやらない」）ので、使ってから決める（スコープ外）

## 結果

- 取引の `record`・版・既存の fixture は変わらない。まとまりの無い取引の判定・集計も変わらない
- 前の版へ戻しても `positionGroupId` は文書に残る（前の版の API は知らずに保つ）。前の版で取引を消すと、まとまりに無い取引の ID が残る。新しい版はそれを「崩れたまとまり」としてメンバーを単独で判定し、［解く］ を出す（`infra/README.md` の切り戻しの注意は #266 で足す）
- 範囲の入口は本人のまとまりをすべて読んで絞る。まとまりが数百件を超えたら、時刻の写しの幅に索引を作る（保存の形は変えない。設計書 13.2）
- まとまりの画面で付けた心理のタグ・Good / More はすべてのメンバーに書かれ、解いた後も残る
- 決済の代わりが本玉より多い分（ドテン）・LC の先送りとしての両建て・オプションのポジションを含む両建ては判定しない（設計書 2.3・13.2）
- 実装は #265（core の判定・損益と 5.8 の例の表のテスト）・#266（保存と API）・#267（画面）・#268（振り返り）
